Resource Leveling: Definition, Steps and a Worked Example

Resource leveling is a scheduling technique that adjusts start and finish dates so that demand for a resource never exceeds its available supply. It removes over-allocation, but it can push the project end date later.

Written byNeural Project InstituteProject management editorial team
  • Published 30 September 2026
  • 5 min read

Key takeaways

  • Resource leveling removes over-allocation by moving tasks.
  • It can extend the end date; resource smoothing cannot.
  • Use a resource histogram to find and fix peaks.
  • Delay high-float tasks first, then agree any new dates.

Why leveling is needed

A schedule built only from task logic assumes unlimited resources. When the plan is then loaded with real people, some weeks need more of a resource than exists. Leveling reshapes the schedule so it can actually be staffed. It is usually done after initial resource allocation and before the schedule is baselined.

Resource leveling vs resource smoothing

Resource levelingResource smoothing
Main goalRemove over-allocationEven out peaks and troughs
Can the end date move?YesNo
Can the critical path change?Yes, oftenNo
UsesAny available time, including beyond floatOnly free and total float
When to useResources are fixed and limitedThe date is fixed and some float exists

See float and slack for how float is calculated.

How to level resources step by step

  1. Build the schedule with dependencies and durations; find the critical path.
  2. Assign resources to each task and set each resource's maximum units (for example 2 developers).
  3. Draw a resource histogram showing demand per period against capacity.
  4. Find the periods where demand exceeds capacity.
  5. Delay or split tasks with the most float first, keeping critical tasks where they are if possible.
  6. If delaying non-critical work is not enough, delay critical tasks and accept a later finish, or add capacity.
  7. Re-check the histogram and the new critical path, then agree the revised dates with stakeholders.

Worked example: a resource histogram before and after

A team has 2 developers. Three tasks need developer time over five weeks. Task A needs 2 developers in weeks 1-4 (critical). Task B needs 1 developer in weeks 2-3 and has 3 weeks of float. Task C needs 1 developer in week 3 and Task D needs 1 developer in week 5; C and D only need to finish by week 6.

Weeks 2 and 3 need 3 and 4 developers, but only 2 exist. Total demand is 2 + 3 + 4 + 2 + 1 = 12 developer-weeks. Twelve developer-weeks at 2 per week needs at least 6 weeks, so the work cannot finish in 5 weeks without extra people.

Demand after leveling222222
Capacity222222
Over-allocation000000

After leveling, Task B moves into weeks 5-6 using its float, Task C moves to week 5 and Task D to week 6, alongside B. Demand never exceeds 2, total effort is still 12 developer-weeks, and the project finishes one week later than the unlevelled plan. The alternative is to hire a third developer for weeks 2-3.

Leveling options compared

OptionEffect on dateEffect on cost
Delay tasks within floatNoneNone
Delay critical tasksEnd date moves laterMay add overhead costs
Split a taskUsually smallSome restart inefficiency
Add people or overtimeNoneHigher cost; see fast-tracking vs crashing
Reduce scopeNoneLower cost, less delivered

Tips and common mistakes

  • Level before you baseline, not after work has started.
  • Be careful with automatic leveling in software: check the result rather than accepting it blindly.
  • Explain to stakeholders that leveling trades time for realism; a levelled plan is one that can actually be staffed.
  • Do not split tasks that lose efficiency when interrupted, such as complex analysis.
  • Re-level when resources change, for example after a resignation or a new project starts.
Tip

Many gantt chart software tools include a level-resources function. Run it on a copy of the schedule first so you can compare the before and after dates.

Frequently asked questions

What is resource leveling in project management?

A technique that shifts task dates so that no resource is asked to do more work in a period than it has time for, even if the end date moves.

What is the difference between resource leveling and resource smoothing?

Leveling can move the end date and change the critical path; smoothing only uses float, so the end date stays fixed.

Does resource leveling change the critical path?

It often does. Delaying tasks to resolve clashes can create new resource-driven critical paths.

Does resource leveling increase project duration?

It can. If over-allocation cannot be resolved within float, the project finishes later than the unlevelled schedule.

What is a resource histogram in resource leveling?

A bar chart showing how much of a resource is needed in each period, usually with a line for available capacity, so over-allocation stands out.

When should you use resource leveling?

When resources are fixed or scarce and the schedule shows demand above capacity, ideally before the schedule baseline is approved.

Can project management software level resources automatically?

Yes, many tools offer automatic leveling, but the results should always be reviewed because the software does not know your priorities.

Which tasks should be delayed first in resource leveling?

Tasks with the most float and the lowest priority, so critical work keeps its dates where possible.

Is resource leveling the same as resource allocation?

No. Resource allocation assigns resources to tasks; leveling adjusts the schedule to resolve the over-allocation that allocation reveals.

What are the alternatives to resource leveling?

Adding people, paid overtime, outsourcing, reducing scope or crashing the schedule; each trades time against cost or scope.

Is resource leveling on the PMP exam?

Yes. Resource optimisation, including leveling and smoothing, is a standard schedule management concept that PMP candidates are expected to know.
