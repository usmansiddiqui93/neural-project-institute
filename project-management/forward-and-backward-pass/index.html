Forward and Backward Pass: Step-by-Step Worked Example

The forward and backward pass are the two calculations at the heart of the critical path method: the forward pass works from start to finish to find each activity's earliest start and finish dates, and the backward pass works from finish to start to find the latest dates. The gap between the two is the float, and activities with zero float form the critical path. This guide gives the formulas, three fully worked examples and a checklist for checking your answer.

Key takeaways

  • Forward pass: EF = ES + duration, and at a merge point take the largest EF of the predecessors.
  • Backward pass: LS = LF - duration, and at a burst point take the smallest LS of the successors.
  • Total float = LS - ES = LF - EF; activities with zero total float form the critical path.
  • Day 0 and day 1 conventions give different dates but the same float and critical path; never mix them.
  • Start the backward pass from a required date, not the calculated finish, to reveal project float or negative float.
  • Lags and SS, FF or SF links change the formulas: always apply the lag to the date the link refers to.

What is the forward and backward pass?

The forward pass is a calculation that moves through a project network from the first activity to the last, finding each activity's early start (ES) and early finish (EF). The backward pass moves from the last activity to the first, finding each activity's late finish (LF) and late start (LS). Together they give the project duration, the float of every activity and the critical path.

Both passes need the same inputs: a list of activities, a duration for each and the task dependencies between them. The terms you will meet:

TermAbbreviationMeaning
Early startESThe earliest an activity can start, once its predecessors allow it
Early finishEFThe earliest it can finish: ES + duration
Late finishLFThe latest it can finish without delaying the project finish (or a required date)
Late startLSThe latest it can start without delaying the project: LF - duration
Total floatTFHow long it can slip without delaying the project: LS - ES
Free floatFFHow long it can slip without delaying any successor
Merge pointAn activity with two or more predecessors; matters in the forward pass
Burst pointAn activity with two or more successors; matters in the backward pass

On an activity-on-node diagram, each box usually shows ES, duration and EF along the top and LS, total float and LF along the bottom. Our guide to the project network diagram shows the layout.

Forward and backward pass formulas

This guide uses the day-0 convention: the first activity starts at time 0, and a successor starts at the same number as its predecessor's finish. Read the numbers as the end of a day: EF 3 means the end of day 3, so a successor with ES 3 starts on day 4.

PassFormulaRule when there are several links
ForwardEF = ES + durationES = the largest EF of all predecessors (plus any lag)
BackwardLS = LF - durationLF = the smallest LS of all successors (minus any lag)
FloatTotal float = LS - ES = LF - EFFree float = smallest ES of successors - EF
Start and endES of the first activity = 0LF of the last activity = project EF, or a required finish date

An activity cannot start until all its predecessors have finished, so the latest one controls it. And it must finish in time for every successor, so the one needed earliest controls it.

Day 0 vs day 1 convention

Many textbooks, exam courses and the US GAO Schedule Assessment Guide use a day-1 convention instead, where the first activity starts on day 1 and both start and finish dates refer to whole working days. The formulas change slightly:

Day-0 conventionDay-1 convention
First activity ES01
Early finishEF = ES + durationEF = ES + duration - 1
Successor's ES (FS link)ES = predecessor EFES = predecessor EF + 1
Late startLS = LF - durationLS = LF - duration + 1
Predecessor's LF (FS link)LF = successor LSLF = successor LS - 1
Total floatLS - ESLS - ES (same result)

Under day 1, every ES and LS is one higher than under day 0, while EF and LF stay the same. Float and the critical path do not change. Day 0 is quicker for hand calculation; day 1 maps more naturally onto a calendar, because "starts on day 4" means the fourth working day. Pick one and use it consistently: mixing them is the most common source of off-by-one errors.

How to do a forward pass step by step

  1. Prepare the inputs. List every activity with its duration and predecessors. A work breakdown structure is the usual source of the activity list, and your estimates give the durations.
  2. Order the activities so that every activity comes after all its predecessors. Drawing the network first makes this easy.
  3. Set the first activity's ES to 0 (or 1 under the day-1 convention). If there are several start activities, each starts at 0 unless a constraint says otherwise.
  4. Calculate EF = ES + duration for that activity.
  5. Move to the next activity. If it has one predecessor, its ES is that predecessor's EF. If it has several (a merge point), its ES is the largest of their EFs. Add any lag on the link.
  6. Repeat until every activity has an ES and EF.
  7. Read the project duration. It is the largest EF in the network, normally the EF of the last activity.

How to do a backward pass step by step

  1. Choose the finish point. Set the LF of the last activity (or activities) to the project EF from the forward pass, or to a required finish date if one has been imposed.
  2. Calculate LS = LF - duration for that activity.
  3. Move backwards to its predecessors. If an activity has one successor, its LF is that successor's LS. If it has several (a burst point), its LF is the smallest of their LSs. Subtract any lag on the link.
  4. Repeat until you reach the first activity.
  5. Check the start. If you started from the calculated finish, the first activity's LS should be 0. If it is positive or negative, you either used a required date or made an error.
  6. Calculate float for every activity: total float = LS - ES, free float = smallest ES of successors - EF.
  7. Identify the critical path: the chain of activities with zero total float (or the lowest float, if a required date has been used).

Step 5: check your answer

  • The first activity's LS is 0 (day 0) or 1 (day 1) when the backward pass starts from the calculated finish.
  • The last activity's EF equals its LF.
  • Every critical activity has ES = LS and EF = LF.
  • No activity has free float greater than its total float.
  • The critical path length equals the sum of its durations (3 + 4 + 5 + 2 = 14).

Backward pass from a required finish date

So far the backward pass started from the calculated finish (day 14). In practice a sponsor, customer or contract often sets a required date. Start the backward pass from that date instead, and every late date moves by the difference.

Required finish on day 16

Set LF of F = 16 and repeat the backward pass. Every LS and LF rises by 2:

The C-E path still has 2 days of float, so shortening C or E would not help.

Forward and backward pass with leads and lags

A lag is a delay added to a link; a lead is an overlap, written as a negative lag. Both enter the calculation on the link itself, not on the activity duration. For a finish-to-start link:

  • Forward pass: ES of successor = EF of predecessor + lag (a lead is a negative lag).
  • Backward pass: LF of predecessor = LS of successor - lag.
  • Free float: ES of successor - lag - EF of predecessor.

Example: a 3-day lag between E and F

Suppose E is pouring a concrete base and F cannot start until it has cured for 3 days (E to F, FS+3). In the forward pass, E's link now gives F an ES of 8 + 3 = 11. D still gives 12, so F starts on 12 and the project still takes 14 days. In the backward pass, E's LF = LS of F (12) - 3 = 9.

ActivityESEFLSLFTotal float without lagTotal float with lag
C354641
E586941

The critical path is unchanged, but the lag has used 3 of the 4 days of float on C-E.

Example: a 2-day lead between D and F

Now suppose F can start 2 days before D finishes (D to F, FS-2). F's ES = max(12 - 2, 8) = 10, so F finishes on day 12 and the project shortens from 14 to 12 days. A-B-D-F is still critical, and C-E's float falls from 4 to 2. Using leads in this way is the basis of fast tracking, and it carries rework risk.

SS, FF and SF relationships

Finish-to-start is the most common link, but networks built with the precedence diagramming method can use all four types. The rule is always the same: apply the lag to the date the link refers to.

LinkForward pass (successor)Backward pass (predecessor)
Finish-to-start (FS)ES ≥ EF of predecessor + lagLF ≤ LS of successor - lag
Start-to-start (SS)ES ≥ ES of predecessor + lagLS ≤ LS of successor - lag, then LF = LS + duration
Finish-to-finish (FF)EF ≥ EF of predecessor + lag, then ES = EF - durationLF ≤ LF of successor - lag
Start-to-finish (SF)EF ≥ ES of predecessor + lag, then ES = EF - durationLS ≤ LF of successor - lag, then LF = LS + duration

When an activity has several incoming links, work out the date each link implies and take the latest (forward pass). When it has several outgoing links, work out each implied late date and take the earliest (backward pass). The link that sets the date is called the driving relationship.

Real-world complications

Textbook networks have one start, one finish and only finish-to-start links. Real schedules add a few complications that change how the passes behave:

  • Date constraints. A "start no earlier than" constraint can push an ES later in the forward pass; a "finish no later than" constraint can pull an LF earlier in the backward pass and create negative float. Use logic wherever you can and keep constraints to genuine external dates.
  • Calendars. Software counts working time on each activity's calendar, so a 5-day activity that spans a weekend or holiday takes longer in calendar days. Activities on different calendars, such as a 7-day calendar for curing, can make float look uneven along a path.
  • Open ends. An activity with no successor gets its LF from the project finish, which gives it inflated float. Every activity except the last should have a successor.
  • Progress. Once work has started, the forward pass for remaining work begins from the status (data) date rather than day 0, using actual dates for completed work and remaining durations for work in progress.
  • Uncertain durations. The passes treat every duration as fixed. For a range of outcomes, use three-point estimates with a PERT chart or a Monte Carlo simulation.
  • Resources. The passes assume unlimited resources; resource levelling can move work and change the critical path.

Forward and backward pass in scheduling software

Scheduling software recalculates both passes every time a date, duration or link changes. Knowing the method lets you check and explain the output.

  • Microsoft Project runs both passes automatically and shows the results as Early Start, Early Finish, Late Start, Late Finish, Free Slack and Total Slack fields. You can schedule from the project start date (the usual forward approach) or from a finish date.
  • Wrike, our top-rated tool, highlights the critical path in its interactive Gantt charts from the Team plan upwards, with all four dependency types and lead and lag time.
  • ClickUp Gantt charts support all four dependency types and show the critical path and slack time, rescheduling downstream tasks automatically.
  • Smartsheet combines a grid with Gantt dependencies and can identify the critical path, which suits date-driven projects.
  • Spreadsheets work for small networks. Our project schedule template and Gantt chart template are good starting points.

Whatever the tool, save a project baseline once the schedule is approved, so you can compare later passes against it.

Common mistakes

  • Taking the smallest EF at a merge point in the forward pass. Always take the largest.
  • Taking the largest LS at a burst point in the backward pass. Always take the smallest.
  • Mixing day-0 and day-1 formulas in the same calculation.
  • Forgetting lags, or applying an SS or FF lag to the wrong date.
  • Starting the backward pass from the wrong date. Use the calculated finish or the required date, and say which.
  • Reading the critical path off durations alone. In networks with lags, constraints or SS and FF links, the longest-looking chain of durations may not be critical; trust the float.
  • Not recalculating after a change. A new duration, link or deadline can switch the critical path.

Frequently asked questions

What is a forward pass in project management?

A calculation from the start of the network to the end that finds each activity's early start and early finish, and so the shortest possible project duration.

What is a backward pass?

A calculation from the end of the network to the start that finds each activity's late finish and late start, which shows how much each activity can slip.

Why take the largest EF in a forward pass?

Because an activity cannot start until all its predecessors have finished, so the latest-finishing one controls its start.

Why take the smallest LS in a backward pass?

Because an activity must finish in time for every successor, so the successor needed earliest controls its late finish.

Should the forward pass start at day 0 or day 1?

Either, if you are consistent. Day 0 is simpler for hand calculation; day 1 matches calendar days more naturally. Float and the critical path are the same either way.

How do you calculate float from the forward and backward pass?

Total float = LS - ES, or LF - EF. Free float = the smallest ES of the activity's successors minus its own EF, allowing for any lag.

Which comes first, the forward or backward pass?

The forward pass, because the backward pass normally starts from the project finish it calculates. The exception is when you start the backward pass from an imposed date.

What if the required finish date is earlier than the forward pass finish?

Start the backward pass from the required date. Critical activities will show negative float equal to the time that must be recovered.

Do I need to do the forward and backward pass by hand?

Scheduling software does it automatically, but working a small network by hand helps you understand and check the results, and it is a common exam topic.

Is the forward and backward pass on the PMP exam?

Network calculations such as float and the critical path are commonly covered in PMP preparation. See our PMP certification guide for the current exam content.

Is this the same as the forward and backward pass in neural networks?

No. In machine learning the terms describe computing a network's output and its gradients. In project management they are schedule calculations.
