Issue Log: Template, Examples and How to Manage Project Issues

An issue log is the record a project keeps of problems that are happening now and need action, together with their priority, owner, actions and status. It makes sure that nothing raised is forgotten and that every issue is resolved, escalated or closed deliberately.

Written byNeural Project InstituteProject management editorial team
  • Published 1 October 2026
  • 4 min read

Key takeaways

  • An issue log tracks problems that are happening now.
  • Every issue needs an impact, priority, owner, action and date.
  • Escalate issues that exceed the project manager's authority.
  • Link occurred risks to new issues and close the loop with lessons learned.

What counts as an issue

An issue is any current problem, query, concern or request for change that the project needs to deal with. Unlike a project risk, it is not uncertain: it has already happened or is certain to happen.

  • Problems: a test environment is down, a supplier has missed a delivery, a key person is off sick.
  • Concerns: a stakeholder is unhappy with the proposed design.
  • Off-specification items: a deliverable does not meet its acceptance criteria.
  • Requests for change: in some methods, including PRINCE2, change requests are also recorded as a type of issue before they go through change control.

How to manage issues step by step

  1. Capture: log every issue as soon as it is raised, even if it seems small.
  2. Assess: describe the impact and agree a priority using defined criteria.
  3. Assign: give the issue a single owner and a target date.
  4. Act: agree and carry out actions; check whether a contingency plan already exists for it.
  5. Escalate: if resolving it would breach agreed tolerances or needs decisions above the project manager's authority, escalate to the sponsor or governance body.
  6. Monitor: review open issues at each team meeting and report high-priority ones in the project status report.
  7. Close: record the resolution, confirm with the person who raised it, and capture any lessons learned.

Issue log vs risk register

Issue logRisk register
TimingNowFuture
CertaintyHas happened or certainly willMight happen
Main fieldPriority and resolutionProbability, impact and response
GoalFix or decidePrevent, reduce or prepare

When a risk occurs, close it in the risk register (marked 'occurred') and open a linked entry in the issue log. Many teams keep both inside a single RAID log.

Tips

  • Define priorities in practical terms, for example 'critical' means work on the critical path has stopped.
  • Keep descriptions factual and avoid blame.
  • Do not let issues sit without an owner or date; these are the ones that grow.
  • Look for patterns. Several issues with the same cause may point to a deeper problem worth analysing with a fishbone diagram.

Frequently asked questions

What is an issue log?

A record of current project problems, concerns and requests, with their priority, owner, actions and status.

What is the difference between an issue and a risk in an issue log?

An issue is happening now; a risk is uncertain and in the future. A risk that occurs becomes an issue.

What should an issue log include?

At least an ID, description, impact, priority, owner, actions, target date and status. Many teams also record who raised it and the final resolution.

Who maintains the issue log?

The project manager or project coordinator, with each owner updating progress on their own issues.

How do you prioritise issues in an issue log?

Use agreed criteria based on the effect on objectives, such as whether critical-path work has stopped, the cost involved and how many people are affected.

When should an issue on the issue log be escalated?

When resolving it needs authority, money or decisions beyond the project manager's agreed tolerances.

Is an issue log the same as a defect log?

Not quite. A defect log tracks faults in a product; an issue log covers any problem affecting the project, which may include serious defects.

Can I keep an issue log in Excel?

Yes. A spreadsheet works for most projects. Many project management tools also have issue or ticket features.

How often should the issue log be reviewed?

High-priority issues may need daily attention; the whole log is usually reviewed at each weekly project meeting.

What is an issue log in PRINCE2?

PRINCE2 uses an issue register for formally managed issues, with informal issues kept in the daily log.

Do Agile teams use issue logs?

Agile teams usually track blockers on their board and raise them at the daily scrum, but a separate log is still common for issues that need escalation.
