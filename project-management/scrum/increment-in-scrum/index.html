What Is an Increment in Scrum? Definition and Examples

An Increment is a concrete stepping stone toward the Product Goal. Each Increment adds to all prior Increments, is thoroughly verified, and must be usable.

By Neural Project InstitutePublished 5 October 2026 · 3 min read

Key takeaways

  • An Increment is a usable step towards the Product Goal.
  • Only work meeting the Definition of Done counts.
  • Increments can be released at any time.
Table of contents
  1. Key takeaways
  2. Key rules
  3. Examples
  4. Why usable matters
  5. Frequently asked questions

Key rules

  • Work becomes part of an Increment only when it meets the Definition of Done.
  • Each Increment is additive and works with all previous ones.
  • Multiple Increments can be created within a Sprint.
  • Increments can be delivered to stakeholders before the end of the Sprint.
  • The Sprint Review should never be the only gate to releasing value.

Examples

TeamExample Increment
SoftwareA working checkout flow released to 10% of users
MarketingA tested landing page with analytics live
HardwareA working prototype that passes defined tests
EducationA complete course module, reviewed and published

Why usable matters

A usable Increment allows real feedback. Partially done work hides risk and delays learning, which undermines empiricism. If work doesn't meet the Definition of Done, it returns to the Product Backlog.

Frequently asked questions

Does an Increment have to be released?

It must be usable, but whether to release it is a business decision.

Can there be more than one Increment per Sprint?

Yes. Teams practising continuous delivery may release many Increments in a Sprint.
