Scrum Boards: How to Set Up and Use One

A Scrum board makes the Sprint Backlog visible. It shows every item and task in the current Sprint and where each one is, so the team can coordinate at a glance.

By Neural Project InstitutePublished 5 October 2026 · 3 min read

Key takeaways

  • A Scrum board visualises the Sprint Backlog.
  • Update it daily and show the Sprint Goal.
  • It resets each Sprint, unlike a Kanban board.

Typical columns

ColumnMeaning
Sprint Backlog / To doSelected for the Sprint, not started
In progressBeing worked on
Review / TestBeing checked
DoneMeets the Definition of Done

What goes on a Scrum card

  • Item title, ideally as a user story.
  • Story point estimate.
  • Acceptance criteria or a link to them.
  • Owner of current tasks.
  • Blocker marker when stuck.

Using the board

  • Set it up at Sprint Planning.
  • Update it during the Daily Scrum.
  • Display the Sprint Goal at the top.
  • Add a burndown chart next to it.
  • Clear it at the end of the Sprint; unfinished items return to the Product Backlog.

Scrum board vs Kanban board

Scrum boardKanban board
LifespanOne SprintPersistent
LimitsSprint scopeWIP limits per column
ChangesAvoid changes that endanger the Sprint GoalNew items can be pulled any time

Frequently asked questions

Do Scrum teams need a board?

The Scrum Guide doesn't require one, but a board is the simplest way to make the Sprint Backlog transparent.

Can a Scrum board have WIP limits?

Yes. Many teams add WIP limits to improve flow within the Sprint.
