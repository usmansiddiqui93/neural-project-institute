Predecessors and Successors in Project Scheduling Explained

A predecessor is an activity that logically comes before another activity and controls when it can start or finish. A successor is the activity that comes after and depends on it. Every link in a schedule has one predecessor and one successor.

Written byNeural Project InstituteProject management editorial team
  • Published 23 September 2026
  • 3 min read

Key takeaways

  • A predecessor comes before; a successor depends on it and comes after.
  • Record only immediate predecessors with the link type and any lag.
  • With several predecessors, the latest-finishing one drives the start date.
  • Avoid open ends so delays show their real impact.

How they work

If "Install software" cannot start until "Install hardware" finishes, then Install hardware is the predecessor and Install software is the successor. The type of link is usually finish-to-start, but it can be any of the four dependency types.

  • An activity can have several predecessors; it then waits for the latest-finishing one (under finish-to-start).
  • An activity can have several successors; a delay to it affects all of them.
  • The first activity has no predecessor and the last has no successor. Most schedules use start and finish milestones for these.
  • Immediate predecessors are the ones directly linked; earlier activities in the chain are indirect predecessors.

How to identify predecessors

  1. For each activity, ask what must be complete or started before it can begin.
  2. Record only immediate predecessors, not every earlier activity, to keep the logic clean.
  3. Choose the link type and any lead or lag.
  4. Check that every activity has at least one predecessor and one successor, apart from the start and finish.
  5. Draw a network diagram to spot loops or dangling activities.

Tips

  • Avoid open ends: an activity with no successor can finish late without the schedule showing any impact.
  • Prefer logic links over date constraints.
  • When an activity has many predecessors, treat it as a risk point and monitor it closely.
  • Use the trace or path view in your tool to follow predecessors back from a late milestone.
Tip

When a milestone slips, trace its driving predecessors backwards. That chain is usually the real cause.

Frequently asked questions

What is a predecessor in project management?

An activity that must start or finish before another activity can start or finish.

What is a successor activity?

An activity that depends on a predecessor and follows it in the schedule.

Can a task have multiple predecessors?

Yes. Under finish-to-start links, it cannot start until all its predecessors have finished.

What is an immediate predecessor?

A predecessor that is directly linked to the activity, rather than further back in the chain.

What is a driving predecessor?

The predecessor that actually determines a successor's earliest start date.

How do you enter predecessors in a scheduling tool?

Usually by typing the predecessor's ID in a predecessor column, optionally with the link type and lag, for example "3FS+2".

What happens if a task has no successor?

It becomes an open end, so delays to it will not show any effect on the finish date. Link it to a later activity or the finish milestone.

Are predecessors the same as dependencies?

A dependency is the link; the predecessor and successor are the two activities at each end of it. See task dependencies.

What is a predecessor in a network diagram?

A node with an arrow leading out of it to another node; see project network diagram.

Do predecessors affect float?

Yes. Float depends on how the activity's dates compare with those of its successors; see float and slack.
