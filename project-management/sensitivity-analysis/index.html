Sensitivity Analysis in Project Management: Steps & Examples

Sensitivity analysis in project management tests how much an outcome such as cost, profit, net present value or finish date changes when you change one input and hold the others steady. It tells you which assumptions matter most and how far they can move before the project stops making sense. This guide gives you a step-by-step method, three fully worked examples and the mistakes to avoid.

Key takeaways

  • Sensitivity analysis changes one input at a time and measures the effect on a single outcome, such as profit, NPV, total cost or finish date.
  • Rank inputs by their swing (the gap between the low and high result) and show them on a tornado chart, widest bar at the top.
  • Pair it with break-even or switching values so sponsors see both what matters most and how wrong an estimate can be before the case fails.
  • Use realistic ranges for each variable rather than the same percentage for everything.
  • One-at-a-time results ignore interactions; add scenario analysis or Monte Carlo simulation when variables move together.
  • Feed the results into the risk register, contingency and estimating effort, and repeat the analysis when key assumptions change.

What is sensitivity analysis?

Sensitivity analysis is a quantitative technique that changes one uncertain input in a model, while holding all other inputs at their base values, to measure how much a chosen output changes. In project management the output is usually cost, profit, net present value or the finish date, and the result is a ranking of which assumptions matter most.

Every analysis has the same parts. You build a model that turns inputs into an output, calculate a base case using your best estimates, then move each input to a low and a high value and record the result. The difference between those two results is the input's swing. Inputs with large swings are the ones your decision really depends on.

PMI's PMBOK Guide has long listed sensitivity analysis, usually presented as a tornado diagram, among the data analysis techniques for quantitative risk analysis. You will also meet it in financial appraisal, where it tests a cost-benefit analysis or net present value calculation, and in schedule risk analysis, where it shows which activities drive the end date.

Why project managers use sensitivity analysis

Most project estimates contain dozens of assumptions, but only a handful decide whether the project succeeds. Sensitivity analysis finds that handful. Use it to:

  • Find the drivers. Identify the few variables that cause most of the uncertainty in cost, benefit or schedule, so you stop refining estimates that hardly matter.
  • Stress-test the business case. Show whether the investment still pays back if the key assumptions are wrong, which is a core question in any feasibility study.
  • Find switching values. Work out the point at which the decision changes, such as the lowest price at which a product still makes money.
  • Prioritise risks. Direct project risk management effort at the inputs with the widest swings.
  • Size contingency. Give reserves a rational basis instead of a flat percentage.
  • Communicate uncertainty. A tornado chart lets sponsors see in seconds where the exposure lies.

It is also cheap once the model exists, which makes it a sensible first step before heavier techniques such as Monte Carlo simulation.

Types of sensitivity analysis

"Sensitivity analysis" covers a family of methods. Most project work uses the first three; the last two are for larger or riskier decisions.

MethodWhat changesWhat you getUse it when
One-at-a-time (OAT)One input moves to low and high values; others stay at baseSwings, a ranking and a tornado chartYou need a quick view of what matters most
Two-way data tableTwo inputs change together across a gridA table of outcomes for every combinationTwo variables are clearly linked, such as price and volume
Break-even (switching value)One input moves until the output reaches a thresholdThe tipping point for the decisionYou need to know how much headroom a case has
Scenario analysisSeveral inputs change together to describe a coherent futureBest, base and worst case resultsVariables tend to move together
Probabilistic sensitivityAll inputs vary randomly in a simulationCorrelation or contribution of each input to the spread of resultsYou already run Monte Carlo and want to know what drives the spread

One-at-a-time analysis is sometimes called local or deterministic sensitivity analysis because it tests fixed points around the base case. Probabilistic methods are global: they look at the whole range of each input at once and can reveal interactions that OAT misses.

How to do a sensitivity analysis step by step

The method below works for cost, benefit and schedule models alike.

  1. Define the decision and the output. Write down the question, for example "Should we approve this project?", and the single output that answers it, such as NPV or profit. Testing several outputs at once muddles the ranking.
  2. Build or check the model. List the formula that links inputs to the output. Have someone else check it: a wrong formula produces a confident but wrong ranking.
  3. Calculate the base case. Use your most likely estimate for every input and record the result.
  4. List the uncertain inputs. Include anything that is estimated rather than known. Use your cost estimation assumptions, benefit forecasts and duration estimates. Eight to twelve inputs is usually plenty.
  5. Set a realistic low and high value for each input. Base the range on data, quotes, past projects or expert judgment. If you have nothing better, start with plus or minus 10% or 20%, and say so.
  6. Run the one-at-a-time tests. Set one input to its low value with all others at base, record the output, then repeat at the high value. Reset the input before moving to the next one.
  7. Calculate the swing for each input. Subtract the lower output from the higher one.
  8. Rank and chart. Sort inputs by swing, largest first, and draw a tornado chart.
  9. Find switching values for the top inputs. For the two or three widest bars, calculate how far the input can move before the output crosses your threshold, such as zero NPV or the contractual deadline.
  10. Act and record. Focus estimating, risk responses and contract terms on the top inputs. Record ranges, sources and results so others can review and repeat them.

Choosing realistic ranges

The ranking is only as fair as the ranges. If you give every input the same plus or minus 10%, you are really measuring how big each input is, not how uncertain it is. A $1 million construction cost that is fixed by contract should get a narrow range; a $50,000 marketing benefit that nobody has tested should get a wide one.

  • Use three-point estimates where you have them: the optimistic and pessimistic values become the low and high.
  • Use quotes, historical actuals and benchmark data for costs and durations.
  • Ask the person who owns each estimate what a plausible bad and good outcome would look like, not the most extreme imaginable.
Tip

Label each range with its source, for example "supplier quote", "last three projects" or "team judgment". Reviewers trust a ranking far more when they can see where the numbers came from.

Worked example 1: product profit and a tornado chart

This example is illustrative. A project will launch a new product. The model is profit = units x (price - variable cost) - fixed cost. Base values are 10,000 units, a price of $50, a variable cost of $30 per unit and a fixed cost of $120,000, so base profit = 10,000 x ($50 - $30) - $120,000 = $80,000.

Each input is moved 10% down and 10% up while the others stay at base.

Variable (-10% / +10%)Profit at low valueProfit at high valueSwingSensitivity ratio
Price ($45 / $55)$30,000$130,000$100,0006.25
Variable cost ($27 / $33)$110,000$50,000$60,000-3.75
Units sold (9,000 / 11,000)$60,000$100,000$40,0002.5
Fixed cost ($108,000 / $132,000)$92,000$68,000$24,000-1.5

Drawn as a tornado chart, price is the widest bar at the top, followed by variable cost, units sold and fixed cost. The sensitivity ratio tells the same story in another way: a 10% rise in price lifts profit by 62.5%, so the ratio is 6.25. A negative ratio means the output falls as the input rises.

Now find the switching value for price. Profit is zero when price = fixed cost / units + variable cost = $120,000 / 10,000 + $30 = $42. Price can fall 16% from the $50 base before the product loses money. Doing the same for variable cost gives $38, a rise of about 27%.

The decision follows directly: spend effort validating the price assumption through customer research and protecting unit cost through supplier terms. Refining the fixed-cost estimate further would barely change the answer.

Why one-at-a-time is not the whole story

Every result in the table is profitable, which can give false comfort. If price, volume and costs all go the wrong way together, the picture changes:

CaseUnitsPriceVariable costFixed costProfit
Combined worst case9,000$45$33$132,000-$24,000
Base case10,000$50$30$120,000$80,000
Combined best case11,000$55$27$108,000$200,000

Each input alone kept profit positive, but together they produce a $24,000 loss. That is the main limitation of one-at-a-time analysis, and it is why you should follow it with scenario analysis when inputs are likely to move together. A lower price, for example, might well come with weaker sales if a competitor enters the market.

Two-way data table

When two inputs are clearly linked, a grid shows every combination. Here is profit for three prices and three volumes, with costs at base.

Units soldPrice $45Price $50Price $55
9,000$15,000$60,000$105,000
10,000$30,000$80,000$130,000
11,000$45,000$100,000$155,000

The grid shows that a $5 price cut needs well over 11,000 units to recover base profit, which is a useful message for anyone tempted to discount for volume.

Worked example 2: NPV of an IT investment

This example is illustrative. A company is considering a $500,000 system that should save $150,000 a year for five years. Using an 8% discount rate, the present value of the savings is $150,000 x 3.9927 (the five-year annuity factor at 8%) = $598,907, so the base-case NPV is $98,907. If NPV basics are new to you, start with our NPV guide.

This time each input gets its own realistic range rather than a flat percentage.

VariableLow / high testedNPV at lowNPV at highSwing
Annual saving$120,000 / $180,000 (plus or minus 20%)-$20,875$218,688$239,563
Initial investment$400,000 / $600,000 (plus or minus 20%)$198,907-$1,093$200,000
Benefit life4 years / 6 years-$3,181$193,432$196,613
Discount rate6% / 10%$131,855$68,618$63,237

Three of the four inputs can turn NPV negative on their own, so this case is more fragile than its positive base NPV suggests. The switching values make the point precisely:

  • Annual saving: NPV reaches zero at about $125,200 a year, only 16.5% below the estimate.
  • Initial investment: NPV reaches zero at about $598,900, an overrun of just under 20%.
  • Discount rate: NPV reaches zero at about 15.2%, which is the project's internal rate of return. The case is not very sensitive to the rate the finance team chooses.

The project manager should validate the savings with the business owners who will deliver them, tie the investment to a fixed-price or capped contract, and confirm how long the system will be used before replacement.

Worked example 3: sensitivity in a project schedule

Sensitivity analysis works for time as well as money. This illustrative network has four activities:

ActivityDurationDepends on
A Design10 daysNone
B Build20 daysA
C Procure equipment18 daysA
D Install and test5 daysB and C

The critical path is A-B-D at 35 days. Path A-C-D takes 33 days, so C has 2 days of float. Now test each activity 5 days shorter and 5 days longer, one at a time.

ActivityFinish if 5 days shorterFinish if 5 days longerSwing
A Design30 days40 days10 days
D Install and test30 days40 days10 days
B Build33 days40 days7 days
C Procure equipment35 days38 days3 days

Two lessons stand out. First, cutting 5 days from Build saves only 2, because path A-C-D becomes critical at 33 days. Second, Procurement is not on the critical path yet still delays the finish by 3 days if it overruns by 5, because its float is only 2. Schedule sensitivity is not symmetrical, and a near-critical activity can matter as much as a critical one.

On real schedules with hundreds of activities, you would not test each one by hand. Schedule risk tools run a Monte Carlo simulation and produce a criticality index (how often an activity falls on the critical path) and a sensitivity or correlation ranking (how strongly its duration moves the finish date). Use those rankings to target schedule compression and risk responses where they will actually move the date.

How to read a tornado chart and a spider chart

A tornado chart is a horizontal bar chart. Each bar is one input, the vertical line is the base-case output, and each bar stretches from the result at the input's low value to the result at its high value. Bars are sorted with the widest at the top, which produces the funnel shape.

  • Read top to bottom. The top two or three bars usually explain most of the uncertainty. Focus there.
  • Look for lopsided bars. If a bar extends much further on one side of the base line, the downside and upside are not equal. That often reflects an asymmetric range, such as a duration that can overrun far more than it can underrun.
  • Check which side is bad. Colour the low-input and high-input ends differently, because for cost inputs the high value hurts and for benefit inputs the low value hurts.
  • Mark the threshold. Draw a line at zero NPV or the deadline. Any bar that crosses it is an input that can break the case on its own.

A spider chart plots the output against the percentage change in each input, giving one line per input. Steeper lines are more sensitive. Spider charts are useful when you want to show how sensitivity changes across the range, for example a schedule activity whose line stays flat until its float is used up and then rises steeply.

Sensitivity analysis vs other techniques

Sensitivity analysis is often confused with related methods. They answer different questions and work best together.

TechniqueWhat changesOutputQuestion it answers
Sensitivity analysisOne variable at a timeSwings, ranking, tornado chartWhich assumptions matter most?
Break-even analysisOne variable until the output hits a thresholdA switching valueHow wrong can this estimate be?
Scenario analysisSeveral variables together in defined casesBest, base and worst case resultsWhat happens in plausible futures?
Monte Carlo simulationAll variables at once, randomly, thousands of timesProbability distribution, such as P50 and P80How confident can we be in this date or budget?
Expected monetary value (EMV)Probability x impact for each risk or branchA probability-weighted valueWhich option is worth more on average?
Cost-benefit analysisNothing: it values the base caseNPV, benefit-cost ratio, paybackIs this worth doing at all?

A practical sequence for a significant investment is: build the cost-benefit model, run one-at-a-time sensitivity to find the drivers, test two or three coherent scenarios, then run Monte Carlo if the decision is large enough to justify it. For individual risks, use probability and impact scoring as described in our guide to project risk.

Doing a sensitivity analysis in Excel or Google Sheets

You do not need specialist software. A spreadsheet handles one-at-a-time and two-way analysis well.

  1. Separate inputs from formulas. Put every input in its own labelled cell in an inputs block, with the base value, low value, high value and source in adjacent columns.
  2. Point the model at the input cells. The output formula should reference the inputs block, never a typed number.
  3. Run one-at-a-time tests. Change each input cell to its low and high value in turn and copy the output into a results table.
  4. Use a one-variable data table. In Excel, list test values in a column, put a reference to the output at the top of the next column, select the block and choose Data, What-If Analysis, Data Table, with the input cell as the column input.
  5. Use a two-variable data table for grids like the price and volume example, with one input across the top row and the other down the first column.
  6. Find switching values with Goal Seek. In Excel, Data, What-If Analysis, Goal Seek sets the output cell to zero by changing one input cell. Google Sheets does not have a built-in data table, so build the grid with ordinary formulas and use an add-on or simple algebra for break-even values.
  7. Draw the tornado chart. Calculate each input's low and high result minus the base, sort by swing, and plot them as a horizontal bar chart with the two series overlapping on a shared axis.

Keep the sensitivity sheet next to your estimate so it updates when the estimate does. Our project cost estimate template gives you a structured base case to work from.

Using the results in your project

Analysis is only useful if it changes what the team does. Turn the top of the tornado chart into actions:

FindingAction
An input has the widest swingSpend more effort estimating it: get quotes, run a pilot, gather data
An input can turn the case negative aloneLog it in the risk register with an owner, a response and a trigger value
A cost input is highly sensitiveConsider fixed-price contracts, early purchase or price caps
A benefit input is highly sensitiveMake the benefit owner accountable and track it early after go-live
A schedule activity is near-critical and sensitiveMonitor it as closely as critical activities; protect its float
The combined downside is largeSize contingency reserve accordingly and prepare a contingency plan

The switching values make excellent monitoring triggers. If the break-even saving is $125,200 a year, report actual savings against that figure, not just against the forecast. Our free risk register template has columns for owner, response and trigger that fit these findings.

Many teams keep the risk register and schedule in their project management tool so that owners see actions alongside their tasks; Wrike, for example, supports custom fields and dashboards that can track risk triggers, while the sensitivity model itself usually stays in a spreadsheet.

Sensitivity analysis also improves project forecasting: once you know which inputs drive the forecast, you know which actuals to watch.

Common sensitivity analysis mistakes

  • Using the same percentage for every input. It ranks inputs by size, not uncertainty. Use realistic ranges.
  • Ignoring interactions. Inputs such as price and volume often move together. Follow up with scenarios.
  • Testing an unchecked model. A misplaced bracket can put the wrong variable at the top of the chart.
  • Testing too many inputs. Thirty bars hide the message. Group minor costs or leave them at base.
  • Treating swings as probabilities. Sensitivity analysis says how much the outcome could move, not how likely that is. Use Monte Carlo for probabilities.
  • Not recording sources. Without them, nobody can review or update the ranges.
  • Doing it once. Repeat the analysis at each stage gate and whenever a major assumption changes.

Sensitivity analysis checklist

Before you present the results, check that you can answer yes to each of these:

  • The decision and the single output are stated clearly.
  • The model has been checked by someone other than its author.
  • Each input has a low and high value with a recorded source.
  • Inputs are ranked by swing and shown on a tornado chart.
  • Switching values are calculated for the top two or three inputs.
  • At least one combined downside scenario has been tested.
  • Each top input has an owner, an action and a review date.

Frequently asked questions

What is sensitivity analysis in project management?

It is a quantitative technique that changes one input at a time, such as price, cost or an activity duration, to see how much an outcome like profit, NPV, total cost or finish date changes. It shows which assumptions matter most.

What is a tornado diagram in sensitivity analysis?

A horizontal bar chart that shows each input's swing, sorted with the widest bar at the top. The shape looks like a tornado. It shows at a glance which inputs drive the most uncertainty.

How do you do a simple sensitivity analysis?

Calculate a base case, move each uncertain input to a realistic low and high value one at a time while keeping the others at base, record the outcome, then rank the inputs by the size of the change.

What is the difference between sensitivity analysis and scenario analysis?

Sensitivity analysis changes one variable at a time to find which matters most. Scenario analysis changes several variables together to describe a coherent best, base or worst case.

How does sensitivity analysis relate to Monte Carlo simulation?

Monte Carlo varies all inputs together thousands of times to produce probabilities, such as P80 cost. Its sensitivity output, often a tornado chart of correlations, shows which inputs drive the spread of results.

What is a switching value?

The value of an input at which the decision changes, usually where NPV or profit reaches zero. It is the same idea as a break-even point and shows how much headroom an estimate has.

What are the types of sensitivity analysis?

The main types are one-at-a-time analysis, two-way data tables, break-even or switching-value analysis, scenario analysis and probabilistic sensitivity analysis within a Monte Carlo simulation.

When should sensitivity analysis be done in a project?

When building the business case, during risk analysis in planning, at major stage gates and whenever a key assumption changes significantly.

Can sensitivity analysis be done in Excel?

Yes. Use an inputs block, one- and two-variable data tables, Goal Seek for break-even values and a sorted horizontal bar chart for the tornado diagram.

What are the limitations of sensitivity analysis?

It ignores interactions between variables, says nothing about probability, and depends entirely on the model structure and the ranges chosen.

Is sensitivity analysis on the PMP exam?

Quantitative risk analysis is part of the exam content, and questions may ask you to interpret a tornado diagram or distinguish sensitivity analysis from EMV and Monte Carlo simulation.

What is the difference between sensitivity analysis and EMV?

Sensitivity analysis measures how much an outcome moves when an input changes. Expected monetary value multiplies each outcome by its probability to give an average value for a risk or decision.
