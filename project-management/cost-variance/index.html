Cost Variance (CV): Formula, Examples and Analysis

Cost variance (CV) tells you whether the work completed on a project has cost more or less than was budgeted for it. In earned value management it is calculated as CV = EV - AC: a negative result means you are over budget for the work done, and a positive result means you are under. This guide covers the formula, a worked example across five work packages, how to set thresholds and what to do when the number turns red.

Key takeaways

  • CV = EV - AC. Negative means over budget for the work done; positive means under budget.
  • CV% = CV / EV x 100 lets you compare work packages and projects of different sizes.
  • Compare actual cost with earned value, not with planned spend; otherwise schedule and cost effects get mixed up.
  • Break CV down by work package to find what is driving it, and track the cumulative trend month by month.
  • Set thresholds with both a percentage and a money amount, and agree in advance what happens when they are breached.
  • Always read CV alongside schedule variance, CPI and the estimate at completion.

What is cost variance (CV)?

Cost variance (CV) is the difference between the budgeted cost of the work actually completed (earned value, EV) and the actual cost of that work (AC) at a given status date. It shows, in money, whether completed work has cost more or less than planned. A negative CV means the project is over budget for the work done.

Cost variance is one of the core measures in earned value management (EVM), alongside schedule variance, the cost performance index and the estimate at completion. It is calculated for the project as a whole and, more usefully, for each work package or control account.

In older EVM material and in some government contracts, you will see different names for the same inputs:

Current termOlder termMeaning
Earned value (EV)BCWP: budgeted cost of work performedThe budget for the work actually done
Actual cost (AC)ACWP: actual cost of work performedWhat that work really cost
Planned value (PV)BCWS: budgeted cost of work scheduledThe budget for the work that should have been done by now

So CV = BCWP - ACWP is exactly the same formula as CV = EV - AC.

Tip

In general finance, "cost variance" or "budget variance" often just means actual spend compared with budget. In project management with EVM, cost variance always compares actual cost with the value of work completed. That distinction is the whole point of the measure, and it is covered in detail below.

The cost variance formula

FormulaWhat it shows
CV = EV - ACCost variance in money, for the work done to date
CV% = (CV / EV) x 100Cost variance as a percentage of the work done
EV = % complete x BACEarned value for a work package or project
VAC = BAC - EACVariance at completion: the cost variance expected at the end

Where BAC is the budget at completion, the total approved budget, and EAC is the estimate at completion, the current forecast of the final cost.

How to read the result

ResultMeaningTypical response
CV > 0 (positive)Completed work cost less than budgeted: under budgetCheck the data is complete, then look for lessons or release contingency
CV = 0Completed work cost exactly its budgetKeep monitoring
CV < 0 (negative)Completed work cost more than budgeted: over budgetFind the cause, forecast the impact and agree action

The sign convention in EVM is simple to remember: negative is bad for both cost variance and schedule variance. Some finance teams use the opposite convention for budget variances (actual minus budget), so check which one a report uses before you read it.

How to calculate cost variance step by step

  1. Fix the status date. All figures must relate to the same cut-off, such as the last working day of the month.
  2. Confirm the BAC for each work package. Use the current approved cost baseline, including approved changes, and exclude management reserve.
  3. Measure progress. Apply your agreed percent-complete rules, such as 0/100 for short tasks, 50/50, or weighted milestones for longer ones, to each work package.
  4. Calculate EV for each work package: % complete x BAC. Add them up for the project total.
  5. Collect AC for the same work, including accruals for work done but not yet invoiced, and timesheet hours at the right rates.
  6. Calculate CV and CV% for each work package and for the total.
  7. Calculate CPI (EV / AC) and compare with the previous period to see the trend.
  8. Compare with your thresholds and write a variance explanation for anything outside them.
  9. Update the forecast: recalculate EAC and VAC, and report the result in your status report.

Steps 3 and 5 are where most errors come from. If progress is overstated, EV is too high and CV looks better than it is. If costs are missing because invoices lag the work, AC is too low with the same effect. Both problems make the project look healthier than it is, so the bad news arrives late.

Worked example: CRM implementation by work package

A company is implementing a new customer relationship management (CRM) system. The budget at completion is $400,000, split across five work packages. Here is the position at the end of month five.

Work packageBAC% completeEVACCVCV%CPI
1. Requirements and design$60,000100%$60,000$58,000+$2,000+3.3%1.03
2. Configuration and build$140,00060%$84,000$103,000-$19,000-22.6%0.82
3. Data migration$70,00040%$28,000$26,500+$1,500+5.4%1.06
4. Testing$80,00010%$8,000$9,500-$1,500-18.8%0.84
5. Training and go-live$50,0000%$0$0$0--
Project total$400,00045%$180,000$197,000-$17,000-9.4%0.91

Calculating the totals

  • EV = 60,000 + 84,000 + 28,000 + 8,000 + 0 = $180,000 (45% of the BAC).
  • CV = 180,000 - 197,000 = -$17,000.
  • CV% = -17,000 / 180,000 x 100 = -9.4%.
  • CPI = 180,000 / 197,000 = 0.914: the project is getting about 91 cents of planned work for every dollar spent.

What the breakdown tells you

  • The whole overrun is explained by configuration and build: -$19,000, or 22.6% over for the work done. The other packages net to +$2,000.
  • Testing has a large percentage variance (-18.8%) but only -$1,500 in money, because it has barely started. Watch it, but it is not yet the priority.
  • Requirements came in slightly under budget, and data migration is running efficiently so far.

Without the breakdown, the project total (-9.4%) suggests a general problem. With it, you know where to look: in this case, the build team's productivity, the supplier's rates or unplanned customisation.

Turning CV into a forecast

CV tells you where you are; the forecast tells you where you are heading.

  • If the current efficiency continues: EAC = BAC / CPI = 400,000 / 0.914 = about $437,800.
  • VAC = BAC - EAC = 400,000 - 437,800 = about -$37,800. The project is heading for a 9.4% overrun.
  • If the overrun was a one-off and the remaining work goes to plan: EAC = AC + (BAC - EV) = 197,000 + 220,000 = $417,000, a VAC of -$17,000.
  • To finish on the original budget, the remaining work would need a TCPI of (BAC - EV) / (BAC - AC) = 220,000 / 203,000 = 1.08, which is better efficiency than any work package has achieved so far.

The honest message to the sponsor is that the project is likely to need between $17,000 and $38,000 more than budgeted unless the build issue is fixed. Our estimate at completion guide explains how to choose between the formulas.

Cumulative and period cost variance

Most reports show cumulative CV: everything from the start of the project to the status date. Period CV looks at one month (or week) on its own and shows when a problem started. Here are both for the CRM project.

MonthEV this monthAC this monthPeriod CVCumulative CVCumulative CV%Cumulative CPI
1$20,000$19,000+$1,000+$1,000+5.0%1.05
2$25,000$25,000$0+$1,000+2.2%1.02
3$40,000$44,000-$4,000-$3,000-3.5%0.97
4$45,000$51,000-$6,000-$9,000-6.9%0.94
5$50,000$58,000-$8,000-$17,000-9.4%0.91

The period figures show the variance getting worse every month since month three, when the build started. This is a trend, not a blip, which supports the more pessimistic EAC. If month five had shown a positive period CV, you would have evidence that corrective action was working, even though the cumulative figure was still negative.

Tip

Plot cumulative EV, AC and PV on one chart. The gap between the AC and EV lines is your cost variance; the gap between the PV and EV lines is your schedule variance. See our guide to the S-curve.

Why cost variance uses EV, not planned spend

The most common misreading of project costs is to compare actual cost with the planned spend to date (PV). In the CRM example at month five:

ComparisonCalculationResultWhat it seems to say
Actual vs planned spendPV - AC = 205,000 - 197,000+$8,000"We are $8,000 under budget"
Cost variance (EVM)EV - AC = 180,000 - 197,000-$17,000"The work we have done cost $17,000 more than budgeted"
Schedule variance (EVM)EV - PV = 180,000 - 205,000-$25,000"We are $25,000 of work behind plan"

The project has spent less than planned only because it has done less work than planned. Comparing AC with PV mixes up two different questions, "are we spending efficiently?" and "are we on time?", and here it hides a real overrun. EVM separates them: CV for cost, SV for schedule, both measured against the value of work actually earned.

This is why a simple budget-versus-actual spreadsheet is not enough for anything but the smallest projects. You need a measure of progress, not just spend.

Reading cost variance with schedule variance

CV on its own only tells half the story. Read it alongside SV to understand the project's real position.

CVSVWhat it usually meansQuestions to ask
PositivePositiveAhead of schedule and under budgetIs progress reported accurately? Can contingency be released?
PositiveNegativeUnder budget but behind scheduleIs work being delayed rather than done cheaply? Are resources missing?
NegativePositiveAhead of schedule but over budgetAre we paying for speed (overtime, extra staff)? Was that agreed?
NegativeNegativeBehind schedule and over budgetWhat is the root cause? Is a re-plan or change request needed?

The CRM project is in the bottom row: negative CV and negative SV (SPI = 180,000 / 205,000 = 0.88). That is the most serious combination, because catching up on schedule will usually cost more money, making the cost variance worse.

Cost variance vs CPI, VAC and budget variance

MeasureFormulaTypeBest for
Cost variance (CV)EV - ACMoney amount, to dateShowing the size of the overrun or saving so far
CV%CV / EV x 100Percentage, to dateComparing work packages and projects; thresholds
Cost performance index (CPI)EV / ACRatio, to dateEfficiency trend; forecasting EAC
Variance at completion (VAC)BAC - EACMoney amount, forecastShowing the expected overrun at the end
Schedule variance (SV)EV - PVMoney amount, to dateShowing how far ahead or behind plan the work is
Budget variance (finance)Budget - actual, or actual - budgetMoney amount, by cost lineAccounting control by period and cost code

CV and CPI use the same inputs and always point the same way: a negative CV means CPI is below 1. CV shows the money at stake; CPI shows efficiency and travels well between projects of different sizes. Report both.

Accounting cost variances

You may also see material, labour and overhead variances. These come from standard costing in management accounting rather than from EVM. They split a variance into its price and quantity (or rate and efficiency) components. For example, a labour variance can be divided into a rate variance (paying more per hour than planned) and an efficiency variance (using more hours than planned).

They are useful for explaining a project cost variance. If configuration and build is $19,000 over, finding that $4,000 is due to higher contractor rates and $15,000 to extra hours tells you where to act. But they are a diagnostic tool, not a replacement for EVM's comparison with earned value.

Variance thresholds and when to act

Not every variance needs a meeting. Most organisations set variance thresholds in the cost management plan: limits beyond which the project manager must explain the variance, forecast its impact and propose action. Thresholds are usually set for both CV and SV, and often tighten as the project matures, because there is less time to recover.

There is no universal standard for the right threshold. It depends on the industry, the contract type, the accuracy of the estimates and the organisation's tolerance for risk. The table below is an example to adapt, not a rule:

StatusExample threshold (cumulative)Action
GreenCV% within plus or minus 5%, and under $10,000Report as normal
AmberCV% between 5% and 10%, or $10,000 to $25,000Written variance explanation and recovery plan in the next report
RedCV% beyond 10%, or over $25,000Escalate to the sponsor or board; revised EAC; consider a change request

Using both a percentage and a money amount avoids two problems. A percentage alone flags small packages, like testing in the CRM example (-18.8% but only -$1,500), and creates noise. A money amount alone misses meaningful drift on large packages. Many teams also set a favourable threshold, because a large positive variance often signals a data or estimating problem.

Under the example thresholds, the CRM project as a whole (-9.4%, -$17,000) is amber, and the configuration and build package (-22.6%, -$19,000) is red at the package level.

Common causes of cost variance

Causes of a negative cost variance

  • Optimistic or incomplete estimates. Missing tasks, low productivity assumptions or no allowance for risk. See cost estimation.
  • Higher rates or prices than planned. Labour rates, contractor day rates, materials, currency movements or inflation.
  • Rework. Defects, unclear requirements or late design changes that mean work is done twice.
  • Unapproved scope changes. Scope creep absorbed without going through change control, so cost rises but the budget does not.
  • Lower productivity. Inexperienced staff, interruptions, context switching or tools that do not work.
  • Schedule pressure. Overtime, expediting fees or extra resources added to recover lost time.
  • Realised risks. Ground conditions, supplier failure, regulatory changes, outages.

When a positive cost variance is a warning

An underspend is not automatically good news. Check for these before celebrating:

  • Missing actual costs: invoices not yet received, timesheets not submitted or accruals not posted.
  • Overstated progress: tasks claimed as further along than they are, which inflates EV.
  • Padded estimates: a large, persistent positive CV suggests the budget was too generous and could have been used elsewhere in the portfolio.
  • Deferred work: cheaper work done first while the expensive, risky work is still ahead.
  • Quality shortcuts: lower cost now, higher cost later in testing or support.

To find the real cause of a significant variance, a structured technique such as a fishbone diagram or five whys works well with the team that did the work.

How to respond to a negative cost variance

  1. Validate the data. Confirm progress measurement and actual costs, including accruals, before anyone draws conclusions.
  2. Locate the variance. Drill down from the project to the control account, work package and cost line until you find what is driving it.
  3. Find the root cause. Separate price from quantity: are you paying more per unit, or using more units?
  4. Decide whether it is typical or atypical. Will the cause continue (a structural productivity issue) or was it a one-off (a single supplier failure)? This decides which EAC formula to use.
  5. Forecast the impact. Recalculate EAC and VAC, and check the effect on contingency.
  6. Agree corrective or preventive actions. Assign owners and dates.
  7. Raise a change request if the baseline is no longer realistic, and route it through change control.
  8. Record the decision and monitor the next period's CV to check the actions are working.

Corrective action options

OptionWhen it helpsWatch out for
Fix the root cause (training, tooling, clearer requirements)Productivity or rework problemsTakes time to show in the numbers
Renegotiate rates or change suppliersPrice-driven variancesContract terms and switching costs
Re-sequence or simplify the remaining workWhen there is flexibility in the design or approachQuality and stakeholder expectations
Reduce scope, with sponsor approvalWhen the budget is fixedBenefits may fall; check the business case
Draw on contingency reserveWhen the cause was an identified riskContingency is finite; track the burn rate
Request extra budget through change controlWhen the original baseline is no longer achievableNeeds a strong explanation and revised forecast

For the identified risks behind a variance, your contingency plan should already say which reserve to use and who can release it.

What to write in a variance explanation

  • The variance: CV, CV% and CPI, cumulative and for the period.
  • The cause, in one or two sentences, with evidence.
  • Whether the cause is expected to continue.
  • The impact on EAC, VAC, contingency and any milestones.
  • The actions, owners and dates.
  • Any decision needed from the sponsor or board.

Example: "Configuration and build is $19,000 over for the work done (CV% -22.6%, CPI 0.82). The cause is 210 extra hours of custom development for the sales pipeline, requested by users without a change request. This is expected to continue unless scope is controlled. Forecast EAC is $437,800 (VAC -$37,800). Actions: freeze customisation requests through change control from 1 November (PM); re-estimate the remaining build (lead developer, by 8 November). Decision needed: approve or reject the outstanding pipeline changes."

Cost variance in Agile projects

EVM was designed for plan-driven projects with a detailed baseline, but the idea behind cost variance still works in Agile delivery if you measure progress in a way that fits.

  • Measure EV at release level. Treat the release budget as BAC and the proportion of planned story points completed as percent complete. If 120 of 300 points are done on a $300,000 release, EV is $120,000.
  • Use team cost per sprint for AC. Agile team costs are fairly stable, so AC is often the number of sprints multiplied by the cost of the team per sprint, plus any other spend.
  • Re-baseline when the backlog changes. If the product owner adds or removes scope, adjust the planned points so CV reflects efficiency rather than scope change.
  • Read it with velocity. A falling velocity will show up as a worsening CV, because the same cost buys fewer points.

Approaches of this kind are often called AgileEVM. They work best as a conversation starter with the sponsor rather than as a precise control tool. Our guide to Agile metrics and KPIs covers the measures most Agile teams rely on day to day.

Common cost variance mistakes

  • Comparing actual cost with planned value instead of earned value.
  • Reporting only the project total, which hides which work package is driving the problem.
  • Subjective percent complete, such as tasks stuck at 90% for weeks, which inflates EV.
  • Ignoring accruals and committed costs, which makes AC too low.
  • Including management reserve in BAC, which blurs the performance baseline.
  • Treating every variance as a problem, without thresholds, so real issues get lost in noise.
  • Explaining the variance without forecasting it: always update EAC and VAC.
  • Assuming a positive CV is good news without checking the data.
  • Letting scope changes in without change control, so the baseline no longer matches the work.

Frequently asked questions

What is cost variance in project management?

Cost variance is the difference between the earned value of the work completed and its actual cost, CV = EV - AC. It shows whether completed work has cost more or less than its budget.

What is the cost variance formula?

CV = EV - AC, where EV is earned value (the budget for the work completed) and AC is the actual cost of that work. As a percentage, CV% = CV / EV x 100.

What does a negative cost variance mean?

The work completed so far has cost more than its budget, so the project is over budget for the work done. In the CRM example, EV of $180,000 and AC of $197,000 give a CV of -$17,000.

What does a positive cost variance mean?

The work completed has cost less than budgeted, so the project is under budget for the work done. Check the data before treating it as good news.

Can a positive cost variance be bad?

Yes. It can be caused by missing invoices or accruals, overstated progress, padded estimates or expensive work still to come. A large, persistent positive variance also suggests budget that could have been used elsewhere.

How do you calculate cost variance percentage?

Divide the cost variance by earned value and multiply by 100. A CV of -$17,000 on EV of $180,000 is -9.4%.

What is an acceptable cost variance?

There is no universal figure. Acceptable limits are set in the project's cost management plan and depend on the industry, contract and estimate accuracy. Many teams use a percentage band plus a money amount, and tighten them as the project progresses.

How often should you calculate cost variance?

At every reporting period, usually monthly for most projects and weekly or fortnightly for short, fast-moving ones. Use the same status date for progress and costs.

What is the difference between cost variance and schedule variance?

Cost variance (EV - AC) measures cost performance: are we spending efficiently? Schedule variance (EV - PV) measures schedule performance in money terms: have we done as much work as planned? Both use earned value.

What is the difference between cost variance and CPI?

Both use EV and AC. CV is the difference (EV - AC) in money; CPI is the ratio (EV / AC). A negative CV always means a CPI below 1.

What is variance at completion?

Variance at completion (VAC) is the cost variance expected when the project finishes: VAC = BAC - EAC. A negative VAC means a forecast overrun.

Is cost variance the same as budget variance?

Not quite. Budget variance usually compares actual spend with the budget for a period. EVM cost variance compares actual cost with the earned value of the work completed, which separates cost efficiency from schedule progress.

What are BCWP and ACWP?

They are the older names for earned value (budgeted cost of work performed) and actual cost (actual cost of work performed). Cost variance is BCWP - ACWP.

Can cost variance be used in Agile projects?

Yes, at release level. Use the release budget as BAC, the share of planned story points completed as percent complete, and team cost per sprint for actual cost. Adjust the baseline when the backlog changes.
