Work Breakdown Structure (WBS): How to Create One

A work breakdown structure (WBS) is a hierarchical decomposition of the total scope of work into smaller, manageable pieces. It is the foundation for estimating, scheduling and assigning work.

Written byNeural Project InstituteProject management editorial team
  • Published 16 September 2026
  • 3 min read

Key takeaways

  • A WBS breaks scope into deliverables and work packages.
  • Follow the 100% rule and use nouns.
  • It is the basis for estimates, schedules and assignments.

Key principles

  • Deliverable-oriented: elements are nouns (outputs), not verbs (activities).
  • 100% rule: the WBS includes all the project scope and nothing more; each level adds up exactly to its parent.
  • Mutually exclusive: no overlap between elements.
  • Right level of detail: stop at work packages that can be estimated and owned.

How to create a WBS

  1. Start from the scope statement.
  2. Identify major deliverables or phases (level 2).
  3. Break each into smaller deliverables.
  4. Continue until you reach work packages.
  5. Number each element.
  6. Check the 100% rule.
  7. Write a WBS dictionary describing each element.
  8. Review with the team.

The WBS dictionary

A companion document describing each element: description, owner, acceptance criteria, estimates, dependencies and resources.

Frequently asked questions

What is a WBS?

A hierarchical breakdown of project scope into deliverables and work packages.

What is the 100% rule in a WBS?

The WBS must include all the work in scope, and each level must add up exactly to its parent.

Is a WBS the same as a schedule?

No. The WBS shows what; the schedule shows when.

Should a WBS use nouns or verbs?

Nouns: deliverables rather than activities.

How many levels should a WBS have?

Typically three to five, depending on project size.

What is a work package in a WBS?

The lowest level of the WBS; see work package.

What is a WBS dictionary?

A document describing each WBS element in detail.

Who creates the WBS?

The project manager with the team, who know the work best.

Can a WBS be organised by phase?

Yes. Level 2 can be phases or major deliverables.

Do Agile projects use a WBS?

Not usually in the classic form; a backlog of epics and user stories serves a similar purpose.
