Definition of Done in Agile: Meaning, Examples and Checklist

The Definition of Done (DoD) is the shared checklist that every piece of work must meet before a team can call it finished. It stops "done" from meaning different things to different people, and it protects quality sprint after sprint.

Written byNeural Project InstituteProject management editorial team
  • Published 14 September 2026
  • 3 min read

Key takeaways

  • The Definition of Done is a shared quality checklist for all work.
  • Acceptance criteria are specific to one item; the DoD applies to every item.
  • Keep it short, visible and improving.

What the Definition of Done is

In Scrum, the Definition of Done is a formal description of the state of the Increment when it meets the quality standards required for the product. Work that does not meet it is not done, cannot be released and does not count towards velocity. The Definition of Done is the commitment attached to the Increment.

Definition of Done vs acceptance criteria

Definition of DoneAcceptance criteria
Applies toEvery backlog itemOne specific item
DescribesQuality standards for all workWhat this item must do
Written byThe team (and organisation standards)Product Owner with the team
ExampleCode reviewed, tested, documentedA user can reset their password by email

An item is complete only when it meets both its acceptance criteria and the Definition of Done.

Example: software team

  • Code written and peer reviewed.
  • Automated tests written and passing.
  • Integrated into the main branch without breaking the build.
  • Meets agreed security and accessibility checks.
  • User-facing text reviewed.
  • Product Owner has seen it working.

Example: marketing or content team

  • Results dashboard set up.

How to create and evolve your Definition of Done

  1. Start with your organisation's quality standards, if any.
  2. Hold a short workshop with the team: "What must be true before we'd be happy to release this?"
  3. Keep it short enough to check every time; a handful of items is usually enough.
  4. Make it visible on your board.
  5. Review it in retrospectives and tighten it as the team matures.

Frequently asked questions

Who owns the Definition of Done?

If the organisation has a standard, all teams follow it as a minimum. Otherwise the Scrum Team creates its own.

Can the Definition of Done change?

Yes. Teams usually strengthen it over time. Any change applies to future work, and teams should be honest about work that was done to an older standard.

What is the Definition of Done in Agile?

A shared checklist of quality standards that every piece of work must meet before it counts as complete. In Scrum it is the commitment attached to the Increment.

What is the difference between Definition of Done and acceptance criteria?

The Definition of Done applies to every backlog item and describes general quality standards; acceptance criteria apply to one item and describe what it must do. An item needs both.

What is the Definition of Ready compared with the Definition of Done?

An optional checklist some teams use to decide when a backlog item is clear enough to bring into a sprint. Unlike the Definition of Done, it is not part of the Scrum Guide.

What should be in a Definition of Done?

Typical items include peer review, testing, integration, documentation where needed, security or accessibility checks and Product Owner review. Keep it short enough to check every time.

What happens if an item does not meet the Definition of Done?

It is not done. It cannot be released or counted in velocity and returns to the Product Backlog for re-ordering.

Is the Definition of Done the same for all teams?

If several teams work on the same product, they share one Definition of Done. Each can add stricter standards of its own.

Where should the Definition of Done be displayed?

Somewhere the team sees it daily, such as on the board or in the team's tool, so it is used during work rather than forgotten.

Does the Definition of Done apply to non-software teams?

Yes. A marketing team might require editor approval, brand and legal checks and tested links before a piece counts as done.

How does the Definition of Done relate to velocity?

Only items that meet the Definition of Done count towards velocity. Partially finished work counts as zero.
