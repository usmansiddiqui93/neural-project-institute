Agile Workflow: How to Design One for Your Team

An Agile workflow is the path a piece of work follows from idea to done. Making that path visible, usually on a board, is the first step to improving it.

A typical Agile workflow

  1. Backlog: ideas and requests, ordered by priority.
  2. Ready: refined items with clear acceptance criteria.
  3. In progress: being worked on.
  4. Review or test: being checked against acceptance criteria and the Definition of Done.
  5. Done: complete and, ideally, released.

Designing your board

  • Map the steps work really goes through today, not an ideal process.
  • Split busy columns into "doing" and "done" sub-columns, so waiting time is visible.
  • Write a short policy for each column: what must be true for a card to enter it.
  • Use swimlanes for different types of work, such as an expedite lane for urgent items.
  • Add WIP limits to active columns.

WIP limits

A work-in-progress limit caps how many items can be in a column at once. When a column is full, the team helps finish work downstream instead of starting new work. Start with roughly one or two items per person in each active column and adjust based on experience.

Example workflows

TeamWorkflow
SoftwareBacklog → Ready → In development → Code review → Testing → Done
MarketingIdeas → Brief ready → Creating → Review → Scheduled → Live
SupportNew → Triage → In progress → Waiting on customer → Resolved
RecruitmentOpen roles → Sourcing → Interviewing → Offer → Hired

Improving the workflow

Review the board in retrospectives. Look for columns where cards pile up, items that sit for days, and frequent backward moves. Track cycle time and throughput to see whether changes help.

Key takeaways

  • An Agile workflow makes the path from idea to done visible.
  • Column policies and WIP limits turn a board into a management tool.
  • Review the workflow regularly using flow metrics.

Frequently asked questions

Is an Agile workflow the same as a Kanban board?

A Kanban board is the most common way to visualise an Agile workflow. Scrum teams use similar boards for their Sprint Backlog.

How many columns should a board have?

As few as possible to show the real stages. Most teams use four to seven.
