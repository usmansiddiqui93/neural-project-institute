Was ist ein Inkrement in Scrum? Definition und Beispiele

Ein Inkrement ist ein konkreter Trittstein in Richtung Produktziel. Jedes Inkrement ergänzt alle vorherigen, wird gründlich überprüft und muss nutzbar sein.

  • Veröffentlicht 15. September 2026
  • 3 Min. Lesezeit

Das Wichtigste in Kürze

  • Ein Inkrement ist ein nutzbarer Schritt in Richtung Produktziel.
  • Nur Arbeit, die die Definition of Done erfüllt, zählt.
  • Inkremente können jederzeit freigegeben werden.

Wichtige Regeln

  • Arbeit wird erst dann Teil eines Inkrements, wenn sie die Definition of Done.
  • Jedes Inkrement baut auf den vorherigen auf und funktioniert mit allen zusammen.
  • Innerhalb eines Sprints können mehrere Inkremente entstehen.
  • Inkremente können den Stakeholdern schon vor Sprintende geliefert werden.
  • Das Sprint Review sollte nie die einzige Hürde für die Freigabe von Wert sein.

Beispiele

TeamBeispiel-Inkrement
SoftwareEin funktionierender Checkout-Ablauf, freigegeben für 10 % der Nutzer
MarketingEine getestete Landingpage mit aktiver Analyse
HardwareEin funktionierender Prototyp, der definierte Tests besteht
BildungEin vollständiges Kursmodul, geprüft und veröffentlicht

Warum Nutzbarkeit wichtig ist

Ein nutzbares Inkrement ermöglicht echtes Feedback. Halbfertige Arbeit verbirgt Risiken und verzögert das Lernen, was den Empirismus untergräbt. Erfüllt Arbeit die Definition of Done nicht, geht sie zurück ins Product Backlog.

Häufig gestellte Fragen

Muss ein Inkrement freigegeben werden?

Es muss nutzbar sein, doch ob es freigegeben wird, ist eine geschäftliche Entscheidung.

Kann es mehr als ein Inkrement pro Sprint geben?

Ja. Teams, die Continuous Delivery praktizieren, geben in einem Sprint möglicherweise viele Inkremente frei.

Was ist ein Produktinkrement?

In Scrum ist ein Inkrement ein konkreter, nutzbarer Schritt in Richtung Produktziel. Es ergänzt alle vorherigen Inkremente und wird gründlich überprüft, damit alle zusammen funktionieren.

Wann entsteht ein Inkrement?

Laut Scrum Guide 2020 entsteht ein Inkrement in dem Moment, in dem ein Product-Backlog-Eintrag die Definition of Done erfüllt.

Was ist das Commitment für das Inkrement?

Die Definition of Done, die die Qualität beschreibt, die das Inkrement erfüllen muss.

Was passiert mit Arbeit, die die Definition of Done für das Inkrement nicht erfüllt?

Sie kann nicht freigegeben oder im Sprint Review als fertig präsentiert werden. Sie geht zur späteren Berücksichtigung zurück ins Product Backlog.

Ist ein Inkrement dasselbe wie ein Release?

Nein. Ein Inkrement ist nutzbar und könnte freigegeben werden; die Freigabe ist eine eigene geschäftliche Entscheidung. Mehrere Inkremente können zu einem Release gebündelt oder jeweils sofort freigegeben werden.

Was bedeutet „potenziell auslieferbares Inkrement“?

Eine Formulierung aus früheren Versionen des Scrum Guide, die bedeutet, dass sich das Inkrement in einem auslieferbaren Zustand befindet. Der Guide von 2020 verwendet stattdessen das Wort „nutzbar“.

Muss das Inkrement Software sein?

Nein. Außerhalb der Softwareentwicklung kann ein Inkrement eine getestete Landingpage, ein veröffentlichtes Kursmodul oder ein funktionierender Prototyp sein, der vereinbarte Qualitätsstandards erfüllt.

Wer erstellt das Inkrement?

Die Developers erstellen es. Das gesamte Scrum Team ist dafür verantwortlich, in jedem Sprint ein wertvolles, nützliches Inkrement zu schaffen.

Wie hängt das Inkrement mit dem Sprint Review zusammen?

Im Sprint Review wird das Inkrement mit den Stakeholdern überprüft und das Product Backlog angepasst. Siehe Sprint Review.
