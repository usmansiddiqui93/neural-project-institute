Projektmeilensteine: Definition, Beispiele und Festlegung

Ein Projektmeilenstein ist ein bedeutender Punkt oder ein bedeutendes Ereignis in einem Projekt, etwa eine Genehmigung, eine Übergabe oder ein Go-live. Meilensteine haben eine Dauer von null: Sie markieren einen Zeitpunkt, keine Arbeit.

Das Wichtigste in Kürze

  • Meilensteine sind Punkte mit einer Dauer von null, die bedeutende Ereignisse markieren.
  • Formulieren Sie sie als erreichte Zustände mit klaren Abschlusskriterien.
  • Verknüpfen Sie sie mit Vorgängen, damit sich ihre Termine aus dem Terminplan berechnen.
  • Berichten Sie die Meilensteinprognosen gegenüber der Baseline.

Häufige Beispiele für Meilensteine

  • Projektauftrag genehmigt; siehe Projektauftrag.
  • Anforderungen freigegeben.
  • Design genehmigt.
  • Auftrag an einen Lieferanten vergeben.
  • Entwicklung abgeschlossen oder Code Freeze.
  • Benutzerakzeptanztest bestanden.
  • Go-live oder Launch.
  • Projekt abgeschlossen und an den Betrieb übergeben; siehe den Projektabschluss hinaus.

So legen Sie Meilensteine fest

  1. Suchen Sie nach Punkten, an denen eine Entscheidung getroffen wird, eine Phase endet oder etwas an eine andere Partei übergeben wird.
  2. Formulieren Sie jeden Meilenstein als erreichten Zustand, zum Beispiel „Lieferantenvertrag unterzeichnet“ statt „Vertrag unterzeichnen“.
  3. Verknüpfen Sie jeden Meilenstein mit den Vorgängen, die zuvor abgeschlossen sein müssen, damit sich sein Termin berechnet.
  4. Vereinbaren Sie klare Abschlusskriterien, damit es keine Diskussion darüber gibt, ob er erreicht ist.
  5. Halten Sie die Anzahl überschaubar: Ein paar pro Phase genügen für das Berichtswesen meist.
  6. Markieren Sie die Meilensteine, die dem Sponsor oder Kunden am wichtigsten sind, und berichten Sie darüber.

Rechenbeispiel

Ein über 12 Wochen geplantes Website-Redesign könnte diese Meilensteine verwenden:

MeilensteinZielAbschlusskriterien
Discovery abgeschlossenEnde Woche 2Anforderungsdokument vom Product Owner unterzeichnet
Design genehmigtEnde Woche 5Sponsor genehmigt die Seitendesigns
Entwicklung abgeschlossenEnde Woche 9Alle Seiten bestehen die internen Tests
LaunchEnde Woche 12Website live und Monitoring eingerichtet

Wird das Design am Ende von Woche 6 statt Woche 5 genehmigt, zeigt der Meilensteinbericht sofort eine Woche Verzug, noch bevor die Entwicklung betroffen ist.

Tipps zur Verfolgung von Meilensteinen

  • Berichten Sie für jeden Meilenstein die Prognose gegenüber den Baseline-Terminen in Ihrem Statusbericht.
  • Nutzen Sie eine Meilensteintrendanalyse, um zu zeigen, wie sich die prognostizierten Termine im Zeitverlauf verschieben.
  • Behandeln Sie einen verpassten Meilenstein als Anlass für ein Gespräch über Gegenmaßnahmen, nicht bloß als Notiz.
  • Verknüpfen Sie Zahlungsmeilensteine in Verträgen mit klaren Abnahmekriterien.
Tipp

Ein Meilenstein ohne klaren Verantwortlichen oder Abschlusskriterien wird leicht zu früh für erreicht erklärt. Halten Sie fest, wer bestätigt, dass er erreicht ist.

Häufig gestellte Fragen

Was ist ein Projektmeilenstein?

Ein bedeutender Punkt im Terminplan eines Projekts mit einer Dauer von null, der Fortschritt markiert, etwa eine Genehmigung oder den Abschluss einer Phase.

Haben Projektmeilensteine eine Dauer?

Nein. Ein Meilenstein markiert einen Zeitpunkt. Die Arbeit bis dorthin wird als Aufgaben dargestellt.

Wie viele Projektmeilensteine sollten Sie haben?

Es gibt keine feste Anzahl. Genug, um den Fortschritt an sinnvollen Punkten zu zeigen, typischerweise einige pro Phase.

Was ist der Unterschied zwischen einem Projektmeilenstein und einem Liefergegenstand?

Ein Liefergegenstand ist ein Ergebnis; ein Meilenstein ist der Moment, in dem etwas geschieht, etwa die Abnahme des Liefergegenstands. Siehe Projektliefergegenstände.

Was ist ein Meilensteindiagramm?

Ein einfaches Diagramm, das nur die Meilensteine auf einer Zeitachse zeigt, nützlich für hochrangige Stakeholder; siehe Projektzeitstrahl.

Was ist ein Zahlungsmeilenstein in einem Meilensteinplan?

Ein vertraglicher Meilenstein, der eine Zahlung auslöst, wenn die vereinbarte Arbeit abgenommen ist.

Wie stellen Sie Projektmeilensteine in einem Gantt-Diagramm dar?

Als Rauten. In den meisten Tools erstellen Sie sie, indem Sie die Dauer einer Aufgabe auf null setzen; siehe Gantt-Diagramm.

Kann ein Projektmeilenstein auf dem kritischen Pfad liegen?

Ja. Meilensteine, die mit kritischen Vorgängen verknüpft sind, liegen auf dem kritischen Pfad, und jede Verzögerung bei ihnen verzögert das Projekt.

Was ist der Unterschied zwischen einem Projektmeilenstein und einem Phase Gate?

Ein Phase Gate ist eine Art Meilenstein, an dem vor Beginn der nächsten Phase eine formelle Go-/No-Go-Entscheidung getroffen wird.

Werden Projektmeilensteine in Agile verwendet?

Ja. Agile Teams nutzen häufig Release-Termine, Sprint Reviews oder Produkteinführungen als Meilensteine auf einer agilen Roadmap.
