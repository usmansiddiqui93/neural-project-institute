Kanban-Karten: was darauf gehört und warum

Jede Karte auf einem Kanban-Board steht für einen Arbeitseintrag. Gut gestaltete Karten lassen jeden auf einen Blick Zweck, Status und Dringlichkeit eines Eintrags erkennen.

Verfasst vonNeural Project InstituteRedaktionsteam Projektmanagement
  • Veröffentlicht 6. September 2026
  • 3 Min. Lesezeit

Das Wichtigste in Kürze

  • Eine Karte steht für einen wertvollen Arbeitseintrag.
  • Zeigen Sie Titel, Verantwortliche, Typ, Daten und Blocker.
  • Halten Sie Einträge klein, damit sie fließen.

Was eine Karte zeigen sollte

  • Ein kurzer, klarer Titel , der das Ergebnis beschreibt.
  • Verantwortlich oder Verantwortliche, die gerade daran arbeiten.
  • Typ oder Serviceklasse, oft durch Farbe dargestellt.
  • Fälligkeitsdatum, nur für Einträge mit wirklich festem Termin.
  • Startdatum, um zu sehen, wie lange er bereits in Bearbeitung ist.
  • Blocker-Markierung wenn der Eintrag nicht vorankommt.
  • Link zu Details in einem Ticket oder Dokument.

Arbeitseinträge dimensionieren

Karten sollten klein genug sein, um das Board in Tagen statt Wochen zu durchlaufen. Große Einträge verdecken Probleme und machen die Durchlaufzeit unvorhersehbar. Teilen Sie große Arbeit in kleinere wertvolle Teile auf oder verwenden Sie eine übergeordnete Karte mit untergeordneten Karten.

Farben und Markierungen nutzen

VisuellTypische Bedeutung
KartenfarbeArbeitstyp: Feature, Fehler, Anfrage, Verbesserung
Rote MarkierungBlockiert; siehe Blocker-Clustering
Avatar oder InitialenWer daran arbeitet
Punkte pro TagWie viele Tage die Karte schon in ihrer Spalte ist

Halten Sie die Legende einfach und zeigen Sie sie auf dem Board an.

Häufig gestellte Fragen

Sollte jede Aufgabe eine Kanban-Karte haben?

Verfolgen Sie Arbeitseinträge, die einem Kunden Wert liefern. Sehr kleine Teilaufgaben können als Checklisten auf der übergeordneten Karte stehen.

Was ist eine blockierte Kanban-Karte?

Eine Karte, die wegen einer externen Abhängigkeit oder eines Problems nicht vorankommt. Markieren Sie sie deutlich, damit das Team bei der Lösung helfen kann.

Was ist eine Kanban-Karte?

Eine Kanban-Karte steht für einen Arbeitseintrag auf einem Kanban-Board. Sie zeigt, um welche Arbeit es sich handelt, und wandert mit dem Fortschritt des Eintrags durch die Spalten.

Welche Informationen sollten auf einer Kanban-Karte stehen?

Ein klarer Titel, der Verantwortliche, der Arbeitstyp, das Startdatum und ggf. ein Fälligkeitsdatum sowie eine sichtbare Blocker-Markierung, wenn der Eintrag feststeckt. Digitale Karten können auf ausführlichere Details verlinken.

Wie groß sollte eine Kanban-Karte sein?

Klein genug, um in Tagen statt Wochen abgeschlossen zu werden, damit die Arbeit fließt und Probleme schnell sichtbar werden. Teilen Sie große Einträge in kleinere Teile auf, die weiterhin Wert liefern.

Warum gehört ein Startdatum auf eine Kanban-Karte?

Ein Startdatum lässt das Team das Alter jedes Eintrags erkennen und die Durchlaufzeit berechnen. Alternde Einträge sind ein Frühwarnzeichen dafür, dass Arbeit feststeckt.

Können Kanban-Karten farblich gekennzeichnet werden?

Ja. Farben zeigen häufig den Arbeitstyp, etwa Feature, Fehler oder Wartung, oder die Serviceklasse. Halten Sie eine sichtbare Legende bereit, damit alle sie gleich lesen.

Sollten Kanban-Karten Schätzungen zeigen?

Das ist möglich, doch viele Kanban-Teams verzichten auf detaillierte Schätzungen und halten Einträge stattdessen ähnlich groß. Prognosen stützen sich dann auf Durchsatz und Cycle-Time-Daten.

Wie viele Personen sollten einer Kanban-Karte zugewiesen sein?

Meist wird eine Person als Verantwortliche angezeigt, die den Eintrag bis zum Abschluss vorantreibt, auch wenn andere helfen. Manche Teams zeigen mit kleinen Avataren, wer an welcher Karte arbeitet.

Was passiert mit einer Kanban-Karte, wenn sie erledigt ist?

Sie wandert in die Done-Spalte und wird nach einem Review oder Release archiviert. Wenn Start- und Enddatum erhalten bleiben, können Sie Kennzahlen im Zeitverlauf verfolgen.

Was ist der Unterschied zwischen einer Kanban-Karte und einer User Story?

Eine User Story beschreibt einen Bedarf aus Sicht des Nutzers; eine Kanban-Karte ist das visuelle Zeichen, mit dem jeder Arbeitseintrag verfolgt wird, sei es eine User Story, ein Fehler oder eine Aufgabe. Siehe User Stories.
