成本偏差（CV）：公式、示例与分析

成本偏差（CV）告诉您项目已完成的工作花费是高于还是低于其预算。在挣值管理中，其计算公式为 CV = EV - AC：结果为负表示已完成工作超出预算，结果为正表示低于预算。本指南介绍该公式、一个涵盖五个工作包的实例、如何设定阈值，以及数值变红时该怎么办。

要点总结

  • CV = EV - AC。负值表示已完成工作超支；正值表示低于预算。
  • CV% = CV / EV x 100，可用于比较不同规模的工作包和项目。
  • 将实际成本与挣值而非计划支出进行比较；否则进度和成本的影响会混在一起。
  • 按工作包分解 CV，找出驱动因素，并逐月跟踪累计趋势。
  • 同时用百分比和金额设定阈值，并事先商定超出阈值时如何处理。
  • 务必将 CV 与进度偏差、CPI 和完工估算结合起来解读。

什么是成本偏差（CV）？

成本偏差（CV） 是在给定状态日期，实际已完成工作的预算成本（挣值，EV）与该工作的实际成本（AC）之差。它以金额显示已完成工作的花费是高于还是低于计划。CV 为负意味着项目在已完成工作上超支。

成本偏差是以下体系的核心指标之一： 挣值管理（EVM），以及 进度偏差、 成本绩效指数 和 完工估算。它既针对整个项目计算，更有用的是针对每个 工作包 或控制账户。

在较早的 EVM 资料和一些政府合同中，您会看到同一输入的不同名称：

现行术语旧术语含义
挣值（EV）BCWP：已完成工作的预算成本实际已完成工作的预算
实际成本（AC）ACWP：已完成工作的实际成本这些工作的实际花费
计划价值（PV）BCWS：计划工作的预算成本截至目前应完成的工作的预算

因此 CV = BCWP - ACWP 与 CV = EV - AC 的公式完全相同。

提示

在一般财务中，“成本差异”或“预算差异”通常只是指实际支出与预算的比较。在采用 EVM 的项目管理中，成本偏差始终是将实际成本与以下数值进行比较： 已完成工作的价值。这一区别正是该指标的意义所在，下文将详细介绍。

成本偏差公式

公式展示内容
CV = EV - AC以金额表示的、截至目前已完成工作的成本偏差
CV% = (CV / EV) x 100成本偏差占已完成工作的百分比
EV = 完成百分比 x BAC工作包或项目的挣值
VAC = BAC - EAC完工偏差：预计在项目结束时的成本偏差

其中 BAC 是 完工预算，即已批准的总预算，以及 EAC 是完工估算，即当前对最终成本的预测。

如何解读结果

结果含义典型应对
CV > 0（正值）已完成工作的花费低于预算：低于预算检查数据是否完整，然后总结经验或释放应急储备
CV = 0已完成工作的花费恰好等于其预算继续监控
CV < 0（负值）已完成工作的花费超过预算：超支找出原因、预测影响并商定行动

EVM 中的符号惯例很容易记住： 负值不利 ，成本偏差和进度偏差都是如此。有些财务团队对预算偏差采用相反的惯例（实际减预算），因此阅读报告前请先确认其采用哪种惯例。

如何逐步计算成本偏差

  1. 固定状态日期。 所有数据必须对应同一截止时间，例如每月最后一个工作日。
  2. 确认每个工作包的 BAC。 使用当前已批准的 成本基准，包括已批准的变更，并排除管理储备。
  3. 衡量进度。 对每个工作包应用商定的完成百分比规则，例如短期任务采用 0/100、50/50，较长任务采用加权里程碑。
  4. 计算 EV ，针对每个工作包：完成百分比 x BAC。将它们相加得到项目总数。
  5. 收集 AC （针对同一工作），包括已完成但尚未开票工作的应计费用，以及按正确费率计算的工时。
  6. 计算 CV 和 CV% ，针对每个工作包及合计。
  7. 计算 CPI （EV / AC），并与上一期比较以观察趋势。
  8. 与阈值进行比较 ，并为超出阈值的任何情况撰写偏差说明。
  9. 更新预测：重新计算 EAC 和 VAC，并在您的以下文件中报告结果： 状态报告.

大多数错误出在第 3 步和第 5 步。如果进度被夸大，EV 就会过高，CV 看起来比实际更好。如果由于发票滞后于工作而遗漏了成本，AC 就会过低，产生同样的效果。这两种问题都会让项目看起来比实际更健康，导致坏消息姗姗来迟。

实例：按工作包划分的 CRM 实施

某公司正在实施一套新的客户关系管理（CRM）系统。完工预算为 $400,000，分为五个工作包。以下是第五个月末的状况。

工作包BAC完成百分比EVACCVCV%CPI
1. 需求与设计$60,000100%$60,000$58,000+$2,000+3.3%1.03
2. 配置和构建$140,00060%$84,000$103,000-$19,000-22.6%0.82
3. 数据迁移$70,00040%$28,000$26,500+$1,500+5.4%1.06
4. 测试$80,00010%$8,000$9,500-$1,500-18.8%0.84
5. 培训和上线$50,0000%$0$0$0--
项目合计$400,00045%$180,000$197,000-$17,000-9.4%0.91

计算合计

  • EV = 60,000 + 84,000 + 28,000 + 8,000 + 0 = $180,000 （BAC 的 45%）。
  • CV = 180,000 - 197,000 = -$17,000.
  • CV% = -17,000 / 180,000 x 100 = -9.4%.
  • CPI = 180,000 / 197,000 = 0.914：项目每花费一美元，大约只获得 91 美分的计划工作。

细分数据告诉您什么

  • 全部超支都可以归因于 配置和构建：-$19,000，即已完成工作超支 22.6%。其他工作包合计为 +$2,000。
  • 测试 的百分比偏差很大（-18.8%），但金额只有 -$1,500，因为它才刚刚开始。需要关注，但还不是优先事项。
  • 需求工作略低于预算，数据迁移目前运行高效。

如果没有细分，项目总数（-9.4%）只表明存在普遍问题。有了细分，您就知道该从何处入手：在本例中，是构建团队的生产率、供应商的费率或计划外的定制开发。

将 CV 转化为预测

CV 告诉您现在所处的位置；预测告诉您将走向何方。

  • 如果当前效率持续下去： EAC = BAC / CPI = 400,000 / 0.914 = 约 $437,800.
  • VAC = BAC - EAC = 400,000 - 437,800 = 约 -$37,800。项目正面临 9.4% 的超支。
  • 如果超支是一次性的，且剩余工作按计划进行：EAC = AC + (BAC - EV) = 197,000 + 220,000 = $417,000，VAC 为 -$17,000。
  • 要按原预算完成，剩余工作需要达到 TCPI ，即 (BAC - EV) / (BAC - AC) = 220,000 / 203,000 = 1.08，这比迄今任何工作包所达到的效率都要高。

向发起人传达的如实信息是：除非解决构建问题，否则项目可能需要比预算多 $17,000 至 $38,000。我们的 完工估算指南 解释了如何在各公式之间做出选择。

累计成本偏差与当期成本偏差

大多数报告显示 累计 CV：从项目开始到状态日期的全部数据。 时期 当期 CV 单独看某一个月（或某一周），能显示问题从何时开始。以下是 CRM 项目的两项数据。

月份本月 EV本月 AC当期 CV累计 CV累计 CV%累计 CPI
1$20,000$19,000+$1,000+$1,000+5.0%1.05
2$25,000$25,000$0+$1,000+2.2%1.02
3$40,000$44,000-$4,000-$3,000-3.5%0.97
4$45,000$51,000-$6,000-$9,000-6.9%0.94
5$50,000$58,000-$8,000-$17,000-9.4%0.91

当期数据显示，自第三个月构建开始以来，偏差每个月都在恶化。这是一个 趋势，而不是偶然波动，这支持了更悲观的 EAC。如果第五个月的当期 CV 为正，您就有证据表明纠正措施正在奏效，即使累计数值仍为负。

提示

将累计 EV、AC 和 PV 绘制在同一张图上。AC 线与 EV 线之间的差距就是成本偏差；PV 线与 EV 线之间的差距就是进度偏差。请参阅我们的指南： S 曲线.

为什么成本偏差使用 EV 而不是计划支出

对项目成本最常见的误读，是将实际成本与截至目前的计划支出（PV）进行比较。在 CRM 示例的第五个月：

比较计算结果表面上的含义
实际支出与计划支出PV - AC = 205,000 - 197,000+$8,000“我们低于预算 $8,000”
成本偏差（EVM）EV - AC = 180,000 - 197,000-$17,000“我们已完成的工作比预算多花了 $17,000”
进度偏差（EVM）EV - PV = 180,000 - 205,000-$25,000“我们的工作比计划落后 $25,000”

项目的支出低于计划，只是因为完成的工作少于计划。将 AC 与 PV 比较混淆了两个不同的问题，即“我们的支出是否高效？”和“我们是否按时？”，在这里还掩盖了真实的超支。EVM 将两者分开： CV 衡量成本，SV 衡量进度，两者都以实际挣得的工作价值为衡量基准。

这就是为什么除了最小的项目以外，简单的预算与实际对比电子表格是不够的。您需要的是进度的衡量指标，而不仅仅是支出。

结合进度偏差解读成本偏差

单看 CV 只能说明一半情况。请将其与 SV 结合解读，以了解项目的真实状况。

CVSV通常意味着什么需要提出的问题
正数正数进度提前且低于预算进度报告是否准确？是否可以释放应急储备？
正数负数低于预算但进度落后工作是被推迟了，而不是以更低成本完成了？是否缺少资源？
负数正数进度提前但超出预算我们是否在为速度付费（加班、额外人员）？这是否经过同意？
负数负数进度落后且超出预算根本原因是什么？是否需要重新规划或提出变更请求？

CRM 项目位于最下面一行：CV 为负，SV 也为负（SPI = 180,000 / 205,000 = 0.88）。这是最严重的组合，因为追赶进度通常需要花费更多资金，从而使成本偏差进一步恶化。

成本偏差与 CPI、VAC 和预算差异的比较

度量公式类型最适合
成本偏差（CV）EV - AC金额，截至目前显示截至目前的超支或节约规模
CV%CV / EV x 100百分比，截至目前比较工作包和项目；阈值
成本绩效指数（CPI）EV / AC比率，截至目前效率趋势；预测 EAC
完工偏差（VAC）BAC - EAC金额，预测值显示预计的最终超支
进度偏差（SV）EV - PV金额，截至目前显示工作比计划提前或落后多少
预算差异（财务）预算 - 实际，或实际 - 预算金额，按成本项按期间和成本代码进行会计控制

CV 和 CPI 使用相同的输入，方向始终一致：CV 为负意味着 CPI 小于 1。CV 显示涉及的金额；CPI 显示效率，便于在不同规模的项目之间比较。两者都要报告。

会计中的成本差异

您还可能看到 材料、人工和间接费用差异。它们来自管理会计中的标准成本法，而不是 EVM。它们将差异分解为价格和数量（或费率和效率）两部分。例如，人工差异可以分为费率差异（每小时支付高于计划）和效率差异（使用的工时多于计划）。

它们有助于解释项目的成本偏差。如果配置和构建超支 $19,000，发现其中 $4,000 是由于承包商费率较高、$15,000 是由于额外工时，就能告诉您应从何处着手。但它们是一种诊断工具，不能取代 EVM 与挣值的比较。

偏差阈值及何时采取行动

并非每个偏差都需要开会。大多数组织会设定 偏差阈值 在 成本管理计划：超出这些限值时，项目经理必须解释偏差、预测其影响并提出行动建议。阈值通常同时针对 CV 和 SV 设定，并往往随着项目推进而收紧，因为可用于恢复的时间越来越少。

合适的阈值没有通用标准。它取决于行业、合同类型、估算的准确性以及组织的风险承受能力。下表是一个 示例 ，供您调整使用，而非硬性规定：

状态示例阈值（累计）行动
绿色CV% 在正负 5% 以内，且低于 $10,000照常报告
琥珀色CV% 在 5% 至 10% 之间，或 $10,000 至 $25,000在下一份报告中提供书面偏差说明和恢复计划
红色CV% 超过 10%，或超过 $25,000上报发起人或委员会；修订 EAC；考虑提出变更请求

同时使用百分比和金额可以避免两个问题。只用百分比会标记出小型工作包（例如 CRM 示例中的测试，-18.8% 但只有 -$1,500），从而产生噪声。只用金额则会忽略大型工作包中有意义的偏移。许多团队还会设定有利偏差阈值，因为较大的正偏差往往意味着数据或估算存在问题。

按照示例阈值，CRM 项目整体（-9.4%，-$17,000）处于 黄色，而配置和构建工作包（-22.6%，-$19,000）则是 红色 （在工作包层面）。

成本偏差的常见原因

负成本偏差的原因

  • 估算过于乐观或不完整。 遗漏任务、生产率假设过低或未考虑风险。参见 成本估算.
  • 费率或价格高于计划。 人工费率、承包商日费率、材料、汇率变动或通胀。
  • 返工。 缺陷、需求不明确或后期设计变更导致工作返工。
  • 未经批准的范围变更。 范围蔓延 未经变更控制就被吸收，因此成本上升而预算不变。
  • 生产率较低。 员工缺乏经验、工作被打断、频繁切换任务或工具无法正常使用。
  • 进度压力。 为弥补损失的时间而增加的加班、加急费用或额外资源。
  • 已发生的风险。 地质条件、供应商失误、法规变化、停电或停机。

什么情况下正成本偏差是一个警告

支出不足并不一定是好消息。在庆祝之前，请检查以下情况：

  • 实际成本缺失：发票尚未收到、工时表未提交或应计费用未入账。
  • 夸大进度：声称任务的进展比实际更快，从而虚增 EV。
  • 估算有水分：持续存在的较大正 CV 表明预算过于宽裕，本可以用于投资组合中的其他地方。
  • 推迟的工作：先完成了较便宜的工作，而昂贵、高风险的工作仍在后面。
  • 在质量上走捷径：现在成本较低，但之后在测试或支持阶段成本更高。

要找出重大偏差的真正原因，可采用结构化技术，例如 鱼骨图 或五问法与实际完成工作的团队一起使用效果很好。

如何应对负成本偏差

  1. 验证数据。 在任何人得出结论之前，先确认进度衡量和实际成本，包括应计费用。
  2. 定位偏差。 从项目向下细分到控制账户、工作包和成本项，直到找出驱动偏差的因素。
  3. 找出根本原因。 区分价格与数量：是单价更高了，还是用量更多了？
  4. 判断它是典型的还是非典型的。 原因会持续存在（结构性生产率问题）还是一次性的（单个供应商失误）？这决定了使用哪个 EAC 公式。
  5. 预测影响。 重新计算 EAC 和 VAC，并检查对应急储备的影响。
  6. 商定纠正或预防措施。 分配负责人和日期。
  7. 如果基准已不再现实，则提出变更请求， 并通过以下流程处理： 变更控制.
  8. 记录决定 ，并监控下一期的 CV，以检查各项行动是否奏效。

纠正措施选项

选项适用场景需要注意

对于偏差背后已识别的风险，您的 应急计划 应已说明使用哪项储备以及由谁动用。

偏差说明中应写些什么

  • 偏差：CV、CV% 和 CPI，包括累计值和当期值。
  • 用一两句话说明原因，并附证据。
  • 原因是否预计会持续。
  • 对 EAC、VAC、应急储备和任何里程碑的影响。
  • 行动、负责人和日期。
  • 需要发起人或委员会做出的任何决定。

示例：“配置和构建在已完成工作上超支 $19,000（CV% -22.6%，CPI 0.82）。原因是用户在未提交变更请求的情况下要求为销售管道增加了 210 小时的定制开发。除非控制范围，否则预计这种情况将持续。预测 EAC 为 $437,800（VAC -$37,800）。行动：自 11 月 1 日起，所有定制请求须通过变更控制（项目经理负责）；重新估算剩余的构建工作（首席开发人员负责，11 月 8 日前完成）。需要决策：批准或否决尚未处理的管道变更。”

敏捷项目中的成本偏差

EVM 是为具有详细基准的计划驱动型项目设计的，但只要以合适的方式衡量进度，成本偏差背后的理念在敏捷交付中同样适用。

  • 在发布层级衡量 EV。 将发布预算视为 BAC，将已完成的计划故事点比例视为完成百分比。如果一次预算为 $300,000 的发布已完成 300 个点中的 120 个，则 EV 为 $120,000。
  • 使用每个冲刺的团队成本作为 AC。 敏捷团队的成本相当稳定，因此 AC 通常为冲刺数量乘以每个冲刺的团队成本，再加上其他支出。
  • 待办事项列表变化时重新设定基准。 如果产品负责人增加或删除了范围，请调整计划点数，使 CV 反映的是效率而不是范围变更。
  • 结合速度来解读。 下降的 速度 会表现为 CV 恶化，因为同样的成本换来的点数更少。

这类方法通常称为 AgileEVM。它们最适合作为与发起人沟通的切入点，而不是精确的控制工具。我们的指南 敏捷指标与 KPI 介绍了大多数敏捷团队日常依赖的指标。

成本偏差的常见错误

  • 将实际成本与计划价值进行比较 ，而不是挣值。
  • 只报告项目总数，这掩盖了是哪个工作包导致了问题。
  • 主观的完成百分比，例如任务连续数周停留在 90%，从而虚增 EV。
  • 忽略应计费用和已承诺成本，这会使 AC 过低。
  • 将管理储备计入 BAC，这会使绩效基准变得模糊。
  • 把每个偏差都当作问题，且没有阈值，导致真正的问题淹没在噪声中。
  • 解释偏差却不进行预测：务必更新 EAC 和 VAC。
  • 以为 CV 为正就是好消息 ，而没有核查数据。
  • 不经变更控制就允许范围变更，因此基准不再与工作相符。

常见问题

项目管理中的成本偏差是什么？

成本偏差是已完成工作的挣值与其实际成本之差，CV = EV - AC。它显示已完成工作的花费是高于还是低于其预算。

成本偏差的公式是什么？

CV = EV - AC，其中 EV 为挣值（已完成工作的预算），AC 为该工作的实际成本。以百分比表示，CV% = CV / EV x 100。

负的成本偏差意味着什么？

迄今已完成工作的花费超过其预算，因此项目在已完成工作上超支。在 CRM 示例中，EV 为 $180,000，AC 为 $197,000，得出 CV 为 -$17,000。

正的成本偏差意味着什么？

已完成工作的花费低于预算，因此项目在已完成工作上低于预算。在将其视为好消息之前，请先核查数据。

正成本偏差可能是坏事吗？

是的。原因可能是发票或应计费用缺失、进度被夸大、估算有水分，或者昂贵的工作尚未开展。持续存在的较大正偏差也表明有预算本可用于其他地方。

如何计算成本偏差百分比？

将成本偏差除以挣值再乘以 100。EV 为 $180,000 时，-$17,000 的 CV 为 -9.4%。

多大的成本偏差可以接受？

没有通用的数值。可接受的限值在项目的成本管理计划中设定，取决于行业、合同和估算精度。许多团队使用百分比区间加金额，并随项目推进逐步收紧。

应多久计算一次成本偏差？

在每个报告期进行，大多数项目通常按月，短期快速推进的项目则按周或每两周一次。进度和成本使用相同的状态日期。

成本偏差和进度偏差有什么区别？

成本偏差（EV - AC）衡量成本绩效：我们的支出是否高效？进度偏差（EV - PV）以金额衡量进度绩效：我们完成的工作是否与计划一样多？两者都使用挣值。

成本偏差与 CPI 有什么区别？

两者都使用 EV 和 AC。CV 是以金额表示的差值（EV - AC）；CPI 是比值（EV / AC）。CV 为负总是意味着 CPI 小于 1。

什么是完工偏差？

完工偏差（VAC）是项目结束时预计的成本偏差：VAC = BAC - EAC。VAC 为负意味着预测超支。

成本偏差与预算偏差相同吗？

不完全是。预算差异通常比较某一期间的实际支出与预算。EVM 成本偏差则比较实际成本与已完成工作的挣值，从而将成本效率与进度进展区分开来。

什么是 BCWP 和 ACWP？

它们是挣值（已完成工作的预算成本）和实际成本（已完成工作的实际成本）的旧称。成本偏差为 BCWP - ACWP。

成本偏差可以用于敏捷项目吗？

可以，在发布层级使用。将发布预算作为 BAC，将已完成的计划故事点比例作为完成百分比，将每个冲刺的团队成本作为实际成本。待办事项列表发生变化时调整基准。
