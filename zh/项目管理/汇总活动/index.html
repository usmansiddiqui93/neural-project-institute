吊床活动：定义、示例与使用方法

吊床活动是一种进度活动，其开始和完成与其他活动绑定，因此其持续时间由这些活动计算得出，而不是估算的。它会随所跨越的工作的移动而伸缩，因此非常适合基于时间的支持性工作，例如监理、设备租赁或项目管理。本指南介绍持续时间的计算方法、一个含成本的示例、吊床活动与摘要任务和投入水平活动的区别，以及如何在常用工具中创建吊床活动。

要点总结

  • 吊床活动跨越一组活动并从中获取日期：开始取自第一项活动，完成取自最后一项活动。
  • 其持续时间是计算得出的，从不估算：最晚的链接完成时间减去最早的链接开始时间。
  • 将吊床活动用于依赖时间的支持工作、成本和报告跨度，例如监理、租赁和管理费用。
  • 吊床活动应跟随网络，而不是驱动网络，并且不应出现在关键路径上。
  • Primavera P6 为此提供了投入水平活动类型；Microsoft Project 则需要变通方法。
  • 在吊床活动上平均分配资源，避免成本前置。

什么是汇总活动？

A 汇总活动（hammock activity） （或吊床任务）是一种跨越一组其他活动的摘要型进度活动。它没有自己的持续时间，而是在其链接的第一项活动开始时开始，在最后一项活动完成时完成，因此其持续时间会自动计算，并随这些活动的移动而变化。

这个名称来自挂在两棵树之间的吊床的形象。移动任何一棵树，吊床都会拉长或缩短，但它从不把树固定在原地。同样，吊床活动悬挂在进度计划中的两个点之间，并跟随它们移动。

您可能还会看到它被称为 摘要工期任务 或 框架活动（frame activity）。早期版本的 PMBOK 指南在术语表中将吊床活动与摘要活动归为一类，许多排程工具则将这一概念实现为 投入水平（LOE） 活动。这些术语存在重叠，下文的比较会解释其区别。

吊床活动属于以下内容的细节层面： 项目进度安排。在活动网络建立之后再构建它们，因为它们依赖于网络的日期。

汇总活动如何运作

吊床活动有四个决定性特征：

  • 它是链接得出的，而不是估算的。 其开始与某项活动的开始绑定（通常采用开始到开始链接），其完成与另一项活动的完成绑定（通常采用完成到完成）。参见 任务依赖关系 ，了解各种链接类型。
  • 它可以跨越任何活动。 与摘要任务不同，它不限于以下结构中某一分支下的子项： 工作分解结构。它可以在一个阶段开始，在另一个阶段结束。
  • 它遵循网络图。 当中间的活动延误或加快时，吊床活动会随之延长或缩短。它绝不应推动其他工作。
  • 它通常承载资源和成本。 任何按时间计费的项目，例如监理人员、起重机或现场工棚，都可以分配给吊床活动，使其成本随进度计划更新。

持续时间公式

采用以下文章中第 0 天的约定： 顺推法与逆推法:

  • 吊床活动开始 = 第一个链接活动的最早开始时间。
  • 吊床活动完成 = 最后一个链接活动的最早完成时间。
  • 汇总活动工期 = 吊床活动完成 − 吊床活动开始，以吊床活动日历上的工作日计。

如果吊床活动跨越的多项活动中可能有不同的活动最先开始或最后完成，则使用其中最早的开始和最晚的完成。有些工具允许您为吊床活动链接多个紧前和紧后活动，并自动完成这一计算。

进度计划变化时会发生什么

由于吊床活动从其他活动读取日期，它会对两者之间的每一个变化做出反应：

进度计划中的变化对吊床活动的影响
其跨越的某项活动延误，但仍在浮动时间范围内不变，因为第一个开始和最后一个完成都没有移动
其跨越的某项关键活动延误吊床活动延长相同的时间
对关键工作进行赶工或快速跟进吊床活动缩短
第一个链接活动开始较晚吊床活动开始较晚；其长度也可能变化
吊床活动结束活动之后的工作发生变化不变，因为它在跨度之外

这正是基于时间的成本所需要的，也是吊床活动在建筑、工程和政府项目进度计划中广受欢迎的原因。

吊床活动示例：办公室装修

一家承包商正在装修一层办公楼。六项施工活动（持续时间以工作日计）构成如下网络：

A拆除4-040

关键路径为 A-C-D-E-F，共 19 个工作日。B 有 1 天浮动时间。（如需核对这些数字，我们的 关键路径法 指南解释了计算方法。）

第 1 步：添加吊床活动

承包商有两项取决于时间而非任何单项活动的成本：

  • H1 现场监理，每天 $450，从拆除开始到移交期间都需要。它与 A 建立开始到开始链接，与 F 建立完成到完成链接。
  • H2 垃圾箱和临时生活设施租赁，每天 $60，从拆除开始到电气二次安装完成（即嘈杂、脏乱的工作结束）期间都需要。它与 A 建立开始到开始链接，与 D 建立完成到完成链接。

第 2 步：计算持续时间和成本

  • H1 从 A 的最早开始时间（0）开始，到 F 的最早完成时间（19）结束，因此其持续时间为 19 天 ，成本为 19 × $450 = $8,550.
  • H2 从 0 开始，到 D 的最早完成时间（13）结束，因此其持续时间为 13 天 ，成本为 13 × $60 = $780.

示例说明了什么

  • 浮动时间保护吊床活动。 B 延误的一天被其浮动时间吸收，因此两个吊床活动都不变。
  • 关键活动延误会让您付出双倍代价。 隔断工程延误三天会推迟完成日期，并增加 $1,530 的支持成本；如果将监理和租赁作为固定工期任务输入，这一点很容易被忽略。
  • 每个吊床活动只看到自己的跨度。 对装修工作赶工可使 H1 缩短一天，但 H2 不受影响，因为 H2 在 D 结束。
  • 时间成本可见。 当您评估 进度压缩，提前完成所节省的吊床活动成本是商业论证的一部分。在本例中，赶工 E 每天最多值 $450，超过这一金额则得不偿失。
提示

绝不要让吊床活动成为其他实际工作的紧前活动。如果 H1 驱动 F，而 F 又驱动 H1，工具要么报告循环逻辑，要么生成毫无意义的日期。吊床活动应悬挂在网络上，而不是支撑网络。

吊床活动、摘要任务与投入水平的比较

这些术语经常被混用，但它们并不完全相同。

日期如何确定通过与选定活动的依赖关系链接按大纲（WBS）层级由其支持的工作决定，通常通过吊床链接由其紧前活动或约束决定

在实践中： 投入水平 描述的是*工作的类型*（持续时间与其所支持的工作一样长的支持性工作），而 吊床活动 描述的是*排程技术*（从其他活动获取日期）。吊床活动是安排 LOE 工作的常用方式，这就是 Primavera P6 等工具将吊床活动实现为投入水平活动类型的原因。

A 摘要任务 遵循 WBS 大纲。Oracle 的 P6 文档描述了一种单独的 WBS 摘要 活动类型，其日期从共享同一 WBS 代码的活动的最早开始延续到最晚完成，这属于摘要任务的概念而不是吊床活动。如果您的支持成本跨越 WBS 的多个分支，吊床活动更为合适。我们的指南 项目任务和活动 介绍了其他活动类型， 项目里程碑 介绍了零持续时间的事件。

何时使用吊床活动

只要某项内容的持续时间恰好等于进度计划中的某一段，并且您希望它自动更新，就使用吊床活动。

采用示例行业
监理与管理从动员进场到移交期间的现场经理建筑
设备或设施租赁从安装到拆除期间的塔式起重机建筑、工程
质量和安全保障构建和测试阶段的 QA 检查员工程、制造
项目管理工作量从启动到收尾期间的项目经理和 PMO 支持任意
环境和许可证成本从构建开始到用户验收签核期间的测试环境IT 与软件
报告跨度跨越多个工作包中活动的“第 2 阶段交付”项目集和政府项目
活动保障从进场搭建到撤场期间的安保和场馆人员事件

吊床活动在大型项目集进度计划中也很有用，例如 综合主计划 及其进度计划中，管理者希望在不重组 WBS 的情况下使用横跨 WBS 的摘要条。

何时不宜使用

  • 当工作产生可交付成果时。 有产出的实际工作应作为普通活动，拥有自己的估算和链接。
  • 用来表示缓冲或浮动时间。 跨越空档的吊床活动不是应急储备。请明确规划缓冲。
  • 用来强制设定日期。 如果您希望某项活动在固定日期开始，请谨慎使用约束，而不是使用吊床活动。
  • 当摘要任务已经能胜任时。 如果支持工作只覆盖 WBS 的一个分支，使用摘要行可能更简单。
  • 在非常小的项目中。 如果没有按时间计费的成本，吊床活动只会增加复杂性而无益处。

如何逐步创建吊床活动

在任何工具中方法都相同，只是菜单不同。

  1. 先建立并检查网络图。 每项实际活动都需要其持续时间和 紧前活动与紧后活动 然后再添加吊床活动。
  2. 确定吊床活动所代表的内容 以及哪项活动标志其开始、哪项活动标志其完成。将其写在活动名称或备注中，例如“现场监理（吊床活动：A 开始至 F 完成）”。
  3. 创建活动 且没有固定的持续时间，或者如果您的工具支持，将其设为投入水平类型。
  4. 链接开始 链接到第一项活动，通常为无滞后的开始到开始关系。
  5. 链接完成 链接到最后一项活动，通常为无滞后的完成到完成关系。
  6. 分配资源或成本 （整个期间），在持续时间内平均分配（或按曲线分配）。
  7. 进行测试。 更改上游某个关键活动的持续时间，检查吊床活动及其成本是否随之变化。在浮动时间范围内更改某个非关键活动的持续时间，检查它们是否保持不变。

将吊床活动集中放置，例如放在“支持和管理费用”标题下，以便查找并将其排除在关键路径报告之外。

Primavera P6 中的吊床活动

Oracle 的 Primavera P6 提供五种活动类型：任务相关、资源相关、投入水平、开始或完成里程碑以及 WBS 摘要。根据 Oracle 的 P6 帮助文档， 投入水平 活动的持续时间由其相关活动决定，通常用于项目管理、文书工作或变革管理等持续性工作。这就是 P6 中的吊床活动。

  1. 添加活动并设置其 活动类型 在“常规”选项卡中设为投入水平（Level of Effort）。
  2. 为其应跨越的第一项和最后一项活动添加关系。Primavera 培训师介绍的一种常见惯例是：与第一项活动建立开始到开始关系，与最后一项活动建立完成到完成关系。
  3. 对项目进行排程，并检查 LOE 是否从第一项活动的开始延续到最后一项活动的完成。
  4. 分配资源或费用。如果添加资源，请应用资源曲线，使单位量在整个持续时间内分布，而不是集中在开始阶段。

遵循组织的链接惯例，并检查 LOE 没有驱动任何实际工作。如果您只需要为一个 WBS 要素做汇总， WBS 摘要 类型可能是更好的选择。

Microsoft Project 中的吊床任务

Microsoft Project 没有吊床任务类型，但 Microsoft TechNet wiki 中介绍了一种由来已久的变通方法，即使用链接单元格：

  1. 创建将作为吊床活动的任务。
  2. 选择 开始 单元格（即应驱动吊床活动开始时间的任务）并复制它。
  3. 选择吊床任务的 开始 单元格并选择 任务 > 粘贴 > 选择性粘贴 > 粘贴链接.
  4. 复制 完成 单元格（即应驱动吊床活动完成时间的任务）。
  5. 选择吊床任务的 完成 单元格，并以同样方式粘贴链接。

现在，当源任务移动时，吊床活动的日期会随之更新。请注意该 wiki 列出的注意事项：

  • 这些链接使用较旧的 DDE 技术，可能很脆弱。只有吊床活动会显示一个小标记；源任务则没有任何显示。
  • 要删除吊床活动，请先断开链接，而不是直接删除任务，以免留下孤立的链接碎片。
  • 为任务取一个清晰的名称，例如“提供管理支持（吊床活动）”，并在备注中记录源任务。

由于这些限制，许多 Microsoft Project 用户只为少数重要的支持成本设置吊床活动，或者在支持工作只覆盖大纲的一个分支时使用摘要任务。

电子表格和其他工具中的吊床活动

如果您的工具没有吊床活动或投入水平类型，仍然可以得到同样的结果：

  • 电子表格公式。 将吊床活动的开始设为第一个链接行的开始，将其完成设为最后一个链接行的完成，或者对其跨越范围内的开始日期使用 MIN()、对完成日期使用 MAX()。持续时间即为完成减去开始（或用 NETWORKDAYS() 计算工作日）。
  • 父行或摘要行。 许多项目管理工具会根据子行计算父行的日期。将活动归组到一个父行下并在那里分配成本，但要接受它只覆盖该组的事实。
  • 成本列。 将计算出的持续时间乘以日费率，这样日期变化时支持成本会随之更新。

我们的免费 项目进度表模板 包含持续时间和紧前活动列， 项目成本估算模板 是存放日费率的好地方。如果您在 甘特图，请为吊床活动使用不同的颜色，以免读者将其误认为实际工作。

吊床活动与关键路径

吊床活动跨越关键活动，因此其总浮动时间可能看起来为零，但它本身并不是关键活动。没有任何活动依赖于它，而且不缩短其所悬挂的活动就不可能缩短它。

美国政府问责局（GAO）的《进度评估指南》对此说得很明确：LOE 活动不应驱动进度计划，并警告说，如果 LOE 处于关键路径上，管理层将无从得知哪些活动可以延误、哪些活动会对追加资源做出响应。在实践中，这意味着：

  • 将吊床活动和 LOE 活动排除在关键路径报告和筛选器之外。
  • 如果吊床活动出现在关键路径上，请检查是否存在它作为实际工作紧前活动的链接，并将其删除。
  • 在查看以下内容时，不要计入吊床活动的浮动时间： 浮动时间与松弛时间 来评估风险；请改为查看实际活动。
  • 在重大重新规划后审查吊床活动，因为新的活动可能落在其原本应覆盖的跨度之外。

吊床活动、成本和挣值

吊床活动对成本控制最为重要，因为许多项目管理费用是按时间支付的。

  • 预算编制。 当您构建 项目预算，为吊床活动上的基于时间的成本定价，使基准成本与基准进度相匹配。
  • 预测。 当进度延误时，吊床活动会延长，预测成本也会自动上升，从而通过以下方式提供早期预警： 成本控制.
  • 挣值。 在 挣值管理中，投入水平工作通常采用 LOE 方法衡量：挣值随时间推移而获得，因此挣值等于计划价值，LOE 不会显示进度偏差。但如果每天的支出超过计划，它仍可能显示成本偏差。

由于 LOE 随时间获得挣值，如果进度计划中有很大比例的预算分配在吊床活动上，整体绩效看起来就会比实际更好。请保持 LOE 预算适度，并将其与离散工作分开报告。

常见的吊床活动错误

  • 输入固定的持续时间。 硬编码持续时间的吊床活动只是一项普通任务，不会自动更新。
  • 让吊床活动成为实际工作的紧前活动。 这可能造成循环逻辑，或让支持性活动决定完成日期。
  • 链接到错误的活动。 末端绑定到非关键活动的吊床活动可能会在工作仍在继续时提前结束。
  • 资源前置。 在某些工具中，除非应用曲线或平均分配，否则 LOE 上的资源会集中在开始阶段。
  • 用吊床活动掩盖空档或缓冲。 应急储备应当可见并受到管理，而不是隐藏在支持性横道中。
  • 吊床活动过多。 满是吊床活动的进度计划更难阅读和审计。仅将其用于真正基于时间的支持和报告。
  • Microsoft Project 中脆弱的链接。 如果删除带有粘贴链接的任务前未先断开链接，可能会留下孤立的链接碎片。

PMP 考试中的吊床活动

吊床活动偶尔会出现在 PMP 认证 学习资料中作为进度管理术语出现。值得记住的要点包括：

  • 吊床活动是一种摘要型活动，其持续时间由其跨越的活动决定。
  • 它从一项活动的开始链接到另一项活动的完成。
  • 它通常用于投入水平和支持性工作。
  • 它不驱动其他活动，也不属于关键路径。

考试题目更可能考查关键路径、浮动时间和依赖关系类型，而不是吊床活动本身，因此请确保这些基础知识扎实。

常见问题

项目管理中的吊床活动是什么？

吊床活动是一种摘要型进度活动，它跨越一组活动并从中获取日期。它在第一个链接活动开始时开始，在最后一个链接活动完成时完成，因此当这些活动移动时，其持续时间会自动变化。

为什么叫作汇总活动（hammock activity）？

因为它悬挂在进度计划中的两个点之间，就像挂在两棵树之间的吊床，并随着这两个点的移动而伸缩。

汇总活动的工期如何计算？

持续时间等于最后一个链接活动的完成时间减去第一个链接活动的开始时间，以吊床活动日历上的工作日计。如果它跨越多个可能的开始或结束活动，则使用最早的开始和最晚的完成。

吊床活动的例子有哪些？

建筑项目中的现场监理，从第一项现场活动开始链接到移交完成。如果任何关键工作延误，监理活动及其成本都会自动延长。

汇总活动位于关键路径上吗？

不是。它跨越关键活动，但不驱动任何工作，因此应排除在关键路径之外。GAO《进度评估指南》指出，LOE 活动不应驱动进度计划。

汇总活动和摘要任务有什么区别？

摘要任务在 WBS 大纲中对其子任务进行分组。吊床活动通过依赖关系链接，可以跨越 WBS 不同分支中的活动，并且通常承载资源和成本。

吊床活动与投入水平是一回事吗？

不完全是。投入水平是没有具体产出的支持性工作，例如项目管理。吊床活动是从其他活动获取日期的排程技术。吊床活动是安排 LOE 工作的常用方式，Primavera P6 将吊床活动实现为一种投入水平活动类型。

如何创建吊床活动？

创建一项没有固定持续时间的活动，将其开始链接到其应跨越的第一项活动的开始，将其完成链接到最后一项活动的完成，然后分配基于时间的资源或成本。通过更改上游某个关键活动的持续时间进行测试。

汇总活动可以分配资源吗？

可以。分配基于时间的资源和成本（如监理人员、设备租赁或管理时间）是使用吊床活动的主要原因之一。在其持续时间内平均分配或按曲线分配。

Microsoft Project 有吊床任务吗？

没有内置类型。您可以复制一项任务的开始日期和另一项任务的完成日期，然后使用“选择性粘贴 > 粘贴链接”将其粘贴到吊床活动的“开始”和“完成”字段中来创建吊床活动，不过这些链接可能很脆弱。

如何在 Primavera P6 中创建吊床活动？

将活动类型设为投入水平，并为其应跨越的第一项和最后一项活动添加关系，通常与第一项活动建立开始到开始关系，与最后一项活动建立完成到完成关系。如果承载资源，请应用资源曲线。

汇总活动应该驱动其他活动吗？

不应该。吊床活动应跟随网络，绝不能作为实际工作的紧前活动，否则可能产生循环逻辑和误导性的关键路径。

汇总活动如何帮助成本控制？

进度计划变动时，基于时间的成本会自动更新，因此延误会立即体现为更高的预测成本。参见 成本控制.

挣值如何处理吊床活动或 LOE 活动？

LOE 工作通常随时间推移获得挣值，因此挣值等于计划价值，不会显示进度偏差，但仍可能显示成本偏差。参见 挣值管理.
