项目管理中的残余风险：含义与示例

项目管理中的残余风险是指在规划并执行风险应对措施后仍然存在的风险。很少有应对措施能完全消除风险，因此大多数项目都带有残余风险，必须对其进行衡量、由适当的人员接受、用储备加以覆盖并持续监控。本指南通过计算示例讲解如何计算残余风险，以及如何判断它是否可以接受。

要点总结

  • 残余风险是应对之后剩余的风险；固有风险是采取任何应对措施之前的风险水平。
  • 次生风险是由应对措施产生的新风险，与残余风险不同。
  • 在采取应对措施后重新评定概率和影响或预期货币价值，以计算残余风险。
  • 将残余风险与商定的承受范围进行比较；如果过高，就增加应对措施或上报。
  • 重大的残余风险应由发起人或项目委员会明确接受，并记录在风险登记册中。

什么是残余风险？

残余风险 是指实施风险应对措施后仍然存在的风险水平。PMI 的《PMBOK 指南》将残余风险描述为采取计划的应对措施后预计仍会存在的风险，包括被有意接受的风险。ISO 的风险管理词汇（ISO Guide 73）对其的定义更为简洁：风险处置后剩余的风险。

通俗地说，您从一个 项目风险开始，决定如何应对，付诸实施，然后问：现在它发生的可能性有多大，后果会有多严重？答案就是残余风险。

  • 它是已识别的风险。 您已经知道它的存在，因此可以为其做计划，这与未知风险不同。
  • 它很少为零。 减轻可以降低概率或影响；转移可以转移财务影响；但两者通常都不能完全消除事件本身。
  • 它是一个决策点。 一旦知道残余风险的水平，就必须有人决定它是否可以接受。
  • 它的应用不限于项目。 信息安全、健康与安全、内部审计和企业风险管理都使用同样的概念。

固有风险、残余风险与次生风险

风险管理以及 PMP 和 CAPM 考试题目中会出现四个相关术语。下表以一项数据迁移风险为例，说明它们的区别。

术语含义示例
固有风险采取任何应对或控制措施之前的风险迁移期间数据丢失：概率 3 x 影响 5 = 15
残余风险采取应对措施之后仍然存在的风险完成全量备份和演练后：概率 1 x 影响 4 = 4
次生风险因执行应对措施而直接产生的新风险演练会占用测试环境，导致其他测试延误
新兴风险随着项目推进才显现出来的风险交付期间新的数据法规出台

残余风险与次生风险

两者很容易混淆，因为它们都出现在采取应对措施之后。区别在于它们的来源：

  • 残余风险 是 同一项风险，降低了但未消除。事件仍可能发生。
  • 次生风险 是由您的应对措施引入的 另一项风险 。它需要在以下文件中单独登记： 风险登记册，并有自己的得分和负责人。

示例：为了降低技能短缺的风险，您将测试外包给一家专业公司。测试仍有一定可能延期（残余风险）。外包还带来了新的可能性，即该公司误解您的需求（次生风险）。

提示

考试技巧：如果题目问的是“剩余”的风险，答案是残余风险；如果问的是“由应对措施引起”的风险，答案是次生风险。

为什么残余风险很重要

规划了应对措施可能会带来虚假的安全感。衡量残余风险能让风险状况保持真实。

  • 如实报告。 发起人需要知道团队采取行动后还剩下哪些风险，而不仅仅是最初识别出的风险。
  • 规模适当的储备。 应急储备通常根据残余风险和已接受风险的预期成本来确定规模。
  • 物有所值。 比较固有风险和残余风险可以表明某项应对措施是否值得其成本。
  • 明确的问责。 当残余风险被记录并正式接受后，每个人都知道是谁决定承担它。
  • 更好地聚焦。 残余得分高的风险继续留在议程上；已降至低水平的风险可以转入常规监控。

各种应对策略如何影响残余风险

您选择的应对措施决定了剩下的风险。以下是 PMI 描述的威胁应对策略及其对残余风险的通常影响。

策略职能典型的残余风险
规避更改计划，使威胁无法发生，例如去掉一项有风险的功能该风险接近于零，但要检查变更是否带来新的风险
减轻降低概率、影响或两者低于固有风险；是残余风险最常见的来源
转移将财务影响转嫁给第三方，例如保险或固定价格合同财务影响下降，但进度和声誉影响可能仍然存在，而且第三方也可能违约
接受目前不采取行动；可预留储备或制定应急计划等于固有风险
上报由于超出项目的权限，将责任移交给更高层级从项目登记册中移出，但组织仍然承担该风险

对于机会，逻辑正好相反：在开拓、提高或分享之后，重新评估收益现在实现的可能性有多大以及规模有多大。

如何计算残余风险

并没有唯一的官方公式。大多数项目使用以下三种方法之一。请选择一种，始终如一地使用，并在风险管理计划中定义您的量表。

方法 1：重新评定概率和影响

这是最简单、最常用的方法，与大多数登记册使用的概率 x 影响矩阵相一致。

  1. 为固有风险评分：概率（1-5）x 影响（1-5）。
  2. 列出应对措施，并确认它们切实可行、有资金保障且有人负责。
  3. 假设应对措施按计划奏效，重新评定概率和影响。
  4. 相乘得到残余得分。

例如，固有概率为 4、影响为 4，得分为 16。如果减轻措施将概率降至 2 而影响仍为 4，残余得分为 8。

方法 2：预期货币价值

在可以估算成本的情况下，用金额来表示残余风险。 残余预期货币价值 = 残余概率 x 残余成本影响。 有 10% 的可能超支 £20,000，则残余风险敞口为 £2,000。这有助于确定应急储备的规模，也便于将应对措施与其成本进行比较。对于整个项目， 蒙特卡洛模拟 可以将多项残余风险综合成一个结果区间。

方法 3：控制有效性

有些组织（尤其是在安全和审计领域）会估算控制措施的有效性，并据此降低固有得分： 残余风险 = 固有风险 x (1 - 控制有效性)。固有得分为 15、控制措施被评估为 60% 有效，则得分为 6。请将其视为粗略的参考：有效性百分比是主观判断，而且降低概率的应对措施并不总能降低影响。

提示

您经常会看到“残余风险 = 固有风险 - 控制措施的影响”这一简略说法。它描述了这一概念，但您仍需使用上述方法之一将其转化为具体数字。

计算示例：建筑项目中的残余风险

一个建筑项目依靠租用的塔式起重机来架设钢结构。一旦起重机发生故障，在找到替代设备之前，工作可能停滞长达六周。

步骤详细程度得分或价值
固有风险概率 3（可能）x 影响 5（非常高）15（高）
固有风险敞口30% 的可能性 x 延误六周的成本 £120,000£36,000
应对措施 1租赁公司每周进行检查，降低概率概率 2
应对措施 2与第二家租赁公司签订备用协议，将任何延误限制在三天以内影响 2
残余风险概率 2 x 影响 24（低）
残余风险敞口10% 的可能性 x 延误三天的成本 £15,000£1,500
应对措施成本检查费加备用费£5,000
次生风险备用公司可能无法在短时间内提供空闲的起重机单独登记，得分 3

应对措施花费 £5,000，使预期风险敞口减少 £34,500，因此显然是值得的。残余得分 4 在项目承受范围 6 之内，因此项目经理将该风险记录为按其残余水平接受，在应急储备中预留 £1,500，并继续监控检查报告。

此处的数字仅用于说明。在您自己的项目中，请使用组织的量表和成本估算。

如何分步评估残余风险

  1. 为固有风险评分 ，使用商定的概率和影响量表。
  2. 商定应对措施，为每项行动指定负责人、成本和日期。
  3. 估算计划的残余风险：假设应对措施奏效，重新评分。这就是您的目标。
  4. 检查应对措施 产生的次生风险，并单独登记。
  5. 与承受范围进行比较 ，承受范围在以下文件中设定： 项目管理计划.
  6. 做出决定：接受、增加应对措施或上报。
  7. 记录决定，包括由谁、在何时接受了残余风险。
  8. 应对措施完成后重新评分 ，得出实际的残余风险，并持续监控触发因素。
提示

将计划的残余得分与实际的残余得分分开记录。仅处于计划阶段的应对措施尚未降低任何风险。

残余风险可以接受吗？

判断残余风险是否可以接受是一种判断，但应遵循商定的规则，而不是凭直觉。

  • 将其与承受范围进行比较。 风险管理计划应根据组织的风险偏好，说明哪些得分项目可以接受，哪些需要上报。
  • 权衡进一步降低风险的成本。 如果再采取一项应对措施的成本超过它所消除的风险敞口，接受残余风险往往是明智的。 成本效益分析 在这方面会有所帮助。
  • 考虑非财务影响。 即使从经济角度看理由不充分，安全、法律和声誉风险也可能需要进一步降低。
  • 让决策公开透明。 重大残余风险应由发起人或项目委员会通过项目的 治理 安排明确接受，而不是由团队悄悄接受。

以下是使用 1-25 评分量表的商定规则示例：

残余得分等级典型行动
15-25高在项目层面不可接受；增加应对措施或上报发起人或项目委员会
8-14中只有在发起人同意、制定应急计划并密切监控的情况下才可接受
1-7低项目经理可以接受；按正常审查频率进行监控

这些等级是我们的建议，而非标准。请根据组织的风险偏好和项目的重要性自行设定。

管理残余风险：应急储备和弹回计划

已接受的残余风险仍然需要计划。常用的工具有两种。

工具是什么使用时机
应急计划风险发生时要采取的行动在风险事件发生或达到触发条件时启动
后备计划应急计划不奏效时的第二套行动用于单一计划不足以应对的高影响风险
应急储备为已识别风险（包括残余风险）预留的时间或资金根据预期价值确定规模，风险发生时动用
管理储备为未知风险预留的时间或资金，位于基准之外针对无人识别出的风险，通过治理程序释放

应急储备位于成本 基准 之内，是 项目预算的组成部分。将已接受风险的残余预期价值相加，可以为应急储备的规模提供一个站得住脚的起点。

如果残余风险确实发生，它就成为问题：将其移入 问题日志，执行应急计划；如果预算或进度发生变化，则需走 变更控制.

向发起人报告残余风险

发起人和项目委员会不需要了解每一项风险，但确实需要知道项目承担着哪些风险。

  • 将主要风险的固有得分和残余得分并列展示，让应对措施的效果清晰可见。
  • 突出显示所有超出承受范围的残余风险，以及您需要发起人做出的决定。
  • 报告剩余的应急储备，并与其所要覆盖的残余风险敞口进行对比。
  • 将残余风险纳入定期的 项目状态报告 以及阶段关口评审中。

在较小的项目中， RAID 日志 可以将风险、假设、问题和依赖关系集中记录在一处；参见我们的 RAID 日志模板.

处理残余风险时的常见错误

  • 以为应对措施能消除风险。 除非已经规避了风险，否则通常都会有残留。
  • 过早重新评分。 在应对措施仅处于计划阶段而尚未完成时就降低得分，会夸大进展。
  • 忽视次生风险。 每项应对措施都可能产生新的风险；每次都要检查。
  • 将转移视为消除。 保险或合同转移的是金钱，而不是时间、声誉或安全。
  • 对发起人隐瞒。 团队私下接受的残余风险并不算真正被接受。
  • 没有储备。 接受残余风险却没有预留应急时间或资金，意味着一旦风险发生，就会变成预算或进度问题。
  • 从不重新审视。 情况会发生变化；请在每次风险审查和每个阶段关口复核残余得分。

残余风险是识别、分析、应对和监控风险这一更广泛过程的组成部分。

常见问题

项目管理中的残余风险是什么？

在规划并执行风险应对措施后仍然存在的风险。它与之前是同一项风险，只是概率或影响降低了（如果是被接受的风险，则保持不变）。

残余风险的示例是什么？

一个团队在数据迁移前进行了全面演练并做了备份。数据损坏的可能性现在大大降低，但仍有很小的可能。这种剩余的可能性及其影响就是残余风险。

如何计算残余风险？

假设应对措施已经到位，重新评定概率和影响并相乘，或者使用降低后的概率和成本影响计算预期货币价值。有些组织则根据估算的控制有效性来降低固有得分。

残余风险的公式是什么？

常见的简略说法是：残余风险 = 固有风险 - 应对或控制措施的效果。在实践中，您可以按残余概率 x 残余影响计算，或按固有风险 x (1 - 控制有效性) 计算。

固有风险和残余风险有什么区别？

固有风险是采取任何应对或控制措施之前的风险水平；残余风险是采取应对措施之后仍然存在的风险水平。

残余风险与次生风险有什么区别？

残余风险是原有风险在应对之后剩余的部分。次生风险是因执行应对措施而直接产生的另一项新风险。

残余风险可以为零吗？

很少能。只有完全规避风险（例如取消引发该风险的活动）才能使该风险接近于零，即便如此，这种变更也可能带来新的风险。

项目中由谁接受残余风险？

项目经理通常可以接受较低的残余风险。重大残余风险应由发起人或项目委员会按照项目的治理规定和承受范围予以接受。

什么样的残余风险水平是可以接受的？

在风险管理计划中商定的承受范围之内、并符合组织风险偏好的水平。可接受的程度因组织和影响类型而异，尤其是安全和法律风险。

残余风险记录在哪里？

记录在风险登记册中，通常是在固有得分旁边的残余得分列中，并注明接受人的姓名和日期。

如果残余风险过高该怎么办？

增加应对措施、更改计划以规避风险、转移更多的影响、上报至更高层级，或在极端情况下决定不再继续。

如何在财务上覆盖残余风险？

通常通过应急储备，其规模根据已识别风险（包括残余风险和已接受风险）的预期成本确定。管理储备则用于覆盖未知风险。

什么是弹回计划？

当某项风险的应急计划不奏效时使用的第二套行动。通常会为高影响的残余风险准备弹回计划。

残余风险在项目管理之外也会使用吗？

会。它是信息安全、内部审计、健康与安全以及企业风险管理中的标准概念，通常被定义为风险处置后剩余的风险。
