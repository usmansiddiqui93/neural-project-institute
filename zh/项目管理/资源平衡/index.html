资源平衡：定义、步骤与计算示例

资源平衡是一种进度计划技术，通过调整活动的开始和完成日期，确保任何人员或资源在某一时段内承担的工作量都不超过其可用时间。它能把一份只在纸面上可行的计划变成真正能配齐人手的计划，但可能会推迟项目完成日期。

  • 最后更新 2026 年 10 月 9 日

要点总结

  • 资源平衡通过推迟、拆分或重新分派工作来消除过度分配。
  • 它可能推迟完成日期并改变关键路径；资源平滑则不会。
  • 资源直方图显示需求在哪些时段超出产能，以及应在何处采取行动。
  • 优先推迟优先级低、浮动时间多的工作，并尽可能保护关键路径。
  • 在确定基准之前进行资源平衡，并在人员或优先级发生变化时重新平衡。
  • 软件可以自动进行资源平衡，但在接受结果之前务必审查。

什么是资源平衡？

资源平衡 是一种资源优化技术，通过调整进度计划中的日期，使每项资源的需求永远不超过可用量。它适用于资源固定或稀缺的情况。由于工作可能需要等待人员空闲下来，资源平衡可能会延长项目工期并改变其关键路径。

PMI 的《PMBOK 指南》（第六版）将资源平衡和资源平滑一起描述为制定进度计划时使用的资源优化技术。英式英语将该术语拼写为“levelling”，但技术本身相同。

在实践中，资源平衡回答一个简单的问题： 以我们真正拥有的人员，这项工作实际上什么时候能完成？ 它通常在以下工作之后进行： 资源分配，即将人员分派给任务；它也是进度计划获批并确定基准之前的最后几个步骤之一。

为什么进度计划需要资源平衡

仅根据任务逻辑、使用 关键路径法编制的进度计划，假设资源是无限的。只要 依赖关系 允许，它就会毫无顾忌地在同一周为同一名工程师安排四项任务。一旦填上真实姓名，某些时段所需的工作量就会超出实际可用量。这就是 过度分配.

以下情况需要进行资源平衡：

  • 同一个人或同一项技能被分派到相互重叠的任务上。
  • 某位专家或某台设备需要与其他项目共享。
  • 有人离职、休假或被调去做优先级更高的工作。
  • 范围扩大了，但团队没有扩充。
  • 一项延误使两项工作挤进了同一时段。

忽视过度分配并不能让工作塞得进去。它通常会演变成错过日期、仓促应付质量和疲惫不堪的人员，而进度计划仍然显示一切正常。资源平衡让这种权衡变得清晰可见，让您可以在问题发生之前而不是之后与发起人讨论。

了解平衡所依据的产能也很有帮助。请使用扣除休假、会议和支持工作后的实际可用时间，而不是完整的工作周； 产能规划 和 全职当量 介绍了如何计算。

资源平衡与资源平滑对比

这是大多数人搜索的比较，也是常见的考试题目。两种技术都会重塑资源需求；区别在于是否允许完成日期变动。

资源平衡资源平滑
主要目标消除过度分配平抑需求的高峰和低谷
驱动因素资源限制固定的结束日期
完成日期能否变动？有否
关键路径会改变吗？是，通常如此否
可使用的时间任意时间，包括超出浮动时间仅限自由浮动时间和总浮动时间
能否保证消除所有过度分配？能，只要日期可以充分后移不能，只能在浮动时间允许的范围内
适用情况人员固定，日期可以协商日期固定，且有一定的浮动时间

一个便于记忆的说法： 资源平衡保护人员，资源平滑保护日期。许多项目经理会先尝试资源平滑，只有在不够时才进行超出浮动时间的资源平衡。

资源平衡与相关技术的比较

其他几种技术也常与资源平衡混淆。有些在它之前进行，有些是它的替代方案，还有些是在它推迟日期之后采取的措施。

技巧职能与资源平衡的关系
资源分配将具体人员分派给任务最先进行，暴露出资源平衡所要解决的过度分配
资源负荷显示每个时段分配给每项资源的工作量资源平衡的输入，通常绘制为直方图
产能规划在数月的跨度内比较团队或项目组合的需求与供给长期版本；资源平衡在任务层面进行
快速跟进让通常按顺序进行的活动重叠进行可以追回因资源平衡而损失的时间，但需要有空闲人员来完成重叠的工作
赶工增加资源以缩短活动工期，需额外付出成本日期不能变动时的替代方案
关键链围绕资源制约因素安排进度，并用缓冲保护结束日期将资源平衡内置于方法本身

快速跟进和赶工属于 进度压缩 技术，而不是资源平衡技术，尽管有些文章将它们列在一起。相关比较详见 快速跟进与赶工.

如何分步进行资源平衡

  1. 编制逻辑驱动的进度计划。 输入活动、工期和 紧前活动与紧后活动，然后找出关键路径和浮动时间。
  2. 分配资源并设定可用性。 记录每项任务需要多少每种资源，以及每个时段有多少可用（例如 2 名开发人员，或一名投入 80% 时间的设计师）。
  3. 绘制资源直方图。 针对每项资源，按天或按周绘制需求图，并与产能线进行对比。
  4. 找出过度分配的时段。 记录每个时段中哪些任务相互重叠，以及每项任务有多少浮动时间。
  5. 先尝试资源平滑。 在浮动时间内移动非关键任务，看看能否在不改变完成日期的情况下消除高峰。
  6. 必要时进行超出浮动时间的资源平衡。 推迟、拆分或重新分派优先级最低的工作，仅在必要时接受较晚的完成日期。
  7. 重新计算并检查。 重新运行进度计划，再次检查直方图，并找出新的关键路径，此时它可能由资源而非逻辑驱动。
  8. 就结果达成一致并确定基准。 向发起人解释其中的权衡，商定日期，然后设定 项目基准.

应该先移动哪些任务？

当多项任务争用同一个人时，您需要一条规则来决定哪项任务等待。进度计划软件和计划人员通常使用如下启发式规则，大致按以下顺序：

  • 尽可能让关键路径上的任务保持不动；优先移动 浮动时间最多 的任务。
  • 尊重业务 优先级：不太重要或时间不太紧迫的工作等待。
  • 让 已经开始 的任务继续进行，以免时断时续造成效率低下。
  • 优先移动 较短的任务，它们对进度计划其余部分的干扰较小。
  • 不要中断拆分后会降低效率的工作，例如复杂的分析或设计。
提示

开始之前，与发起人商定优先级规则。如果大家已经就哪个项目或可交付成果优先达成一致，资源平衡的结果就容易站得住脚得多。

计算示例：对一个小型软件进度计划进行资源平衡

一个由 2 名开发人员 组成的团队正在开发一个小型内部工具。共有五项活动，开发人员是唯一受限的资源。

ID活动工期所需开发人员紧前活动
A设计数据库3 天1无
B构建 API4 天2A
C构建管理界面3 天1A
D编写测试脚本2 天1无
E集成测试2 天1B, C, D

按照逻辑允许的最早时间安排，A 和 D 分别在第 1–3 天和第 1–2 天进行，B 在第 4–7 天，C 在第 4–6 天，E 在第 8–9 天。项目在以下时间结束： 第 9 天结束时。关键路径为 A、B、E。C 有 1 天浮动时间，D 有 5 天。

资源平衡之前

天123456789
需求（开发人员）221333211
产能222222222
过度分配000111000

在第 4–6 天，由于 B（2 人）和 C（1 人）重叠，计划需要 3 名开发人员。总工作量为 18 个开发人日。

资源平滑能解决吗？

资源平滑只能利用浮动时间。C 只有 1 天浮动时间，因此最多只能移到第 5–7 天，但在第 5、6、7 天仍与 B 重叠。移动 D 也无济于事，因为 D 并不涉及这一冲突。 如果没有第三名开发人员，资源平滑无法消除过度分配，因此只有增加产能才能保住第 9 天这一完成日期。

资源平衡之后

资源平衡将 C 推迟到 B 完成之后。C 现在在第 8–10 天进行，而依赖 C 的 E 则移到第 11–12 天。

产能222222222222
过度分配000000000000

需求从未超过 2，总工作量仍为 18 个开发人日，但项目现在的完成时间是 第 12 天，晚了三天。关键路径也发生了变化：现在是 A、B、C、E，因为 C 是在等待开发人员，而不是在等待逻辑关系。这是一条由资源驱动的关键路径，在未经资源平衡的计划中是看不见的。从第 8 天起，有一名开发人员空闲，您可以将这部分产能提供给其他工作。

选项完成成本与风险

资源平衡技术

技巧运作方式对完成日期的影响需要注意
在浮动时间内推迟在浮动时间范围内将非关键任务后移无浮动时间被用掉，之后的延误影响更大
超出浮动时间推迟将任务后移到超出其浮动时间允许的范围推迟出现新的、由资源驱动的关键路径
拆分任务暂停一项任务，之后再继续通常较小重新启动所需的时间以及注意力分散
重新分派工作将任务交给另一位具备相应技能的人员通常没有技能缺口；请查看 技能矩阵
更改分配单位以兼职方式在更长的时间内完成任务可能推迟任务工期变长
增加产能或加班承包商、新员工或额外工时无成本和疲劳；这属于赶工
缩减范围删除或推迟价值较低的工作无影响或提前需要相关方同意

前两项是严格意义上的资源平衡。其他几项是在无法接受延误时需要权衡的替代或补充手段。它们对应经典的 项目制约因素：您可以在时间、成本或范围之间进行权衡，但几乎无法完全避免权衡。

跨多个项目进行资源平衡

教科书中的资源平衡针对的是单个进度计划。在大多数组织中，人员同时参与多个项目以及日常业务工作，因此过度分配往往只有在跨项目审视时才会显现。

  • 使用共享的工作负荷或资源视图，显示每个人的全部分配，而不只是某一个项目的分配。
  • 商定项目组合的优先级，以便在人员冲突时知道哪个项目的任务需要等待。
  • 长期规划时按角色或技能层面进行资源平衡，未来几周的计划则按具体人员进行平衡。
  • 定期重新进行资源平衡，因为一个项目的延误可能导致另一个项目超负荷。
  • 将反复出现的冲突反馈到 产能规划中，因为这通常意味着团队规模对于需求而言根本太小。

我们关于 管理多个项目 介绍了防止共享团队超负荷的更广泛的习惯做法。

项目管理软件中的资源平衡

Microsoft Project

Microsoft Project 包含自动资源平衡功能。根据 Microsoft 的文档，资源调配选项包括：

  • 手动或自动调配：手动（默认）模式仅在您选择“全部调配”时进行调配；自动模式则在任何变更造成过度分配时自动调配。
  • 识别过度分配的时间基准，从逐分钟到逐月不等。
  • 调配顺序：仅按标识号、按标准条件（紧前任务、可宽延时间、日期、优先级和限制）或优先级优先。
  • 任务优先级 范围为 0 到 1,000，其中 1,000 表示该任务永不调配。默认值为 500。
  • 仅在可用的可宽延时间内调配，这会阻止调配推迟完成日期，实际上相当于资源平滑设置。
  • 调配时是否可以拆分剩余工作 或调整单个分配。
  • 清除调配，用于删除 Project 添加的调配延迟和拆分。

云端工作管理工具

大多数云端工具采用更直观的方式：工作负荷视图突出显示谁的分配过多或过少，您可以将任务拖到另一个日期或另一个人名下来重新平衡。 Wrike是我们评分最高的工具，提供显示谁的分配过多或过少的工作负荷图表，高级别套餐还提供工作量分配、岗位角色和产能规划功能。Asana、ClickUp 和 monday.com 也提供工作负荷视图，通常需要付费套餐。

检查自动调配的结果

  • 先对进度计划的副本进行资源平衡，以便比较前后的日期。
  • 检查关键任务或合同规定固定日期的任务是否被意外推迟。
  • 留意被拆分成许多碎片的任务，这在现实中很少行得通。
  • 确保资源日历（休假、兼职工时）正确，否则资源平衡将基于错误的产能进行。
提示

除非您告诉软件，否则它并不了解您的优先级。在按下按钮之前，请设置任务优先级，或保护关键任务不参与资源平衡。

资源平衡的优点与缺点

优势缺点
一份真正能配齐人手的进度计划完成日期可能推迟
可持续的工作负荷，减少倦怠出现新的、由资源驱动的关键路径
更早预警资源短缺浮动时间被消耗，计划应对意外情况的余地变小
交付过程中意外延误减少需要投入精力，并且情况变化时需要重复进行
为招聘或外包决策提供更充分的依据拆分任务可能降低效率

常见错误与实用技巧

  • 在工作开始后才进行资源平衡。 在基准获批之前进行资源平衡，之后只在情况变化时重新平衡。
  • 按 100% 可用性计算。 没有人会把每个小时都花在项目任务上；请使用实际产能。
  • 盲目接受自动资源平衡的结果。 审查结果及其对里程碑的影响。
  • 隐瞒影响。 如果资源平衡推迟了完成日期，请告知发起人并展示可选方案，就像上面的示例那样。
  • 为避免冲突而虚构逻辑关系。 资源冲突不是依赖关系；一旦冲突消失，虚假的关系仍会继续拖延工作。
  • 孤立地对单个项目进行资源平衡 ，而同一批人员还在参与其他项目。
  • 忘记非人力资源 ，例如同样有限的测试环境、设备或会议室。

资源平衡属于我们以下指南所述的更广泛过程： 项目进度安排 ，并且取决于您是否了解自己的 项目资源。免费的 项目进度表模板 和 关键路径模板 是编制待平衡进度计划的好起点。

常见问题

什么是项目管理中的资源平衡？

一种调整任务日期的技术，确保任何资源在某一时段内承担的工作量都不超过其可用时间。即使完成日期必须推迟，它也会消除过度分配。

资源平衡的示例是什么？

两名开发人员被安排的任务在三天内需要三个人。资源平衡将单人任务推迟到较大的任务完成之后，使需求永远不超过两人，项目则晚三天完成。

资源平衡与资源平滑有什么区别？

资源平衡可以推迟完成日期并改变关键路径，以消除过度分配。资源平滑则保持完成日期不变，只在浮动时间范围内移动任务，因此可能无法消除每一个高峰。

资源平衡会改变关键路径吗？

通常会。为解决冲突而推迟任务，可能使原本非关键的任务变为关键任务，从而形成一条由资源驱动的关键路径。

资源平衡会延长项目工期吗？

可能会。如果过度分配无法在可用浮动时间内解决，经过资源平衡的项目就会比原进度计划更晚完成。

什么是资源直方图？

一种条形图，显示每个时间段需要多少某项资源，通常带有一条表示可用产能的线，使过度分配一目了然。

何时应该使用资源平衡？

当资源固定或稀缺、且进度计划显示需求超出产能时进行，最好在基准获批之前进行，并在资源或优先级发生变化时再次进行。

应该先推迟哪些任务？

通常是浮动时间最多、优先级最低的任务，以便关键工作尽可能保持原定日期。避免中断已经开始的任务。

谁负责资源平衡？

由项目经理或项目进度计划人员对项目进度计划进行资源平衡。当人员在多个项目之间共享时，通常由资源经理或 PMO 商定整个项目组合的优先级。

资源平衡与资源分配是一回事吗？

否。 资源分配 是将资源分配给任务；资源平衡则调整进度计划，以解决分配过程中暴露出的过度分配问题。

软件能自动进行资源平衡吗？

能。Microsoft Project 和其他进度计划工具都具备自动资源平衡功能，许多云端工具还提供工作负荷视图供手动重新平衡。请务必审查结果，因为软件并不了解您的优先级。

如何在不延误项目的前提下进行资源平衡？

只使用可用的浮动时间（资源平滑）、将工作重新分派给有余力的人员、临时增加产能或缩减范围。如果这些都不够，就只能推迟日期。

资源平衡有哪些替代方法？

增加人员、支付加班费、外包、缩减范围或对进度计划进行赶工。每一种方法都是在时间与成本或范围之间进行权衡。

PMP 考试会考资源平衡吗？

资源平衡和资源平滑是 PMI《PMBOK 指南》中的标准资源优化概念，也是 PMP 考试备考中的常见内容；参见我们的 PMP 认证指南.
