什么是 Kanban？Kanban 方法完全指南

Kanban 是一种管理工作的方法：让工作可视化、限制同时进行的工作量，并持续改进从需求到交付的工作流动。它起源于丰田的工厂车间，如今已被全球的软件、营销、运营和支持团队广泛使用。

Kanban 的起源

“Kanban”在日语中意为“看板”或“可视卡片”。在大野耐一自 20 世纪 40 年代末开始主导建立的丰田生产方式中，看板卡用于发出某道工序需要更多零件的信号，从而使生产由真实需求拉动，而不是由预测推动。请参阅 准时制 和 拉动系统与推动系统.

2000 年代，David J. Anderson 等人将这些理念应用于知识工作。由此形成的 Kanban 方法如今是应用最广泛的一种 敏捷方法.

Kanban 系统如何运作

  1. 可视化工作 ，使用 Kanban 看板，每个工作项一张 卡片 ，每个阶段一列。
  2. 限制在制品 ，通过 WIP 限制 约束每个活动列。
  3. 拉动而非推动： 只有在有产能时才开始新工作。
  4. 管理流动： 关注工作如何流动，并消除拖慢流动的因素。
  5. 明确规则： 商定并公示每个阶段的规则。
  6. 持续改进 ，借助 指标 和定期评审。

Kanban 的原则

Kanban 方法从您的现状出发，而不是强加一套新流程。其基本原则是：从您当前的做法开始；同意以渐进式变革追求改进；鼓励各个层级的领导行为。请参阅 Kanban 原则 ，了解完整内容。

Kanban 的优势

  • 可见性： 每个人都能看到正在处理什么工作，以及工作卡在了哪里。
  • 交付更快： 限制 WIP 可缩短 周期时间.
  • 灵活性： 优先级可以随时调整，而不会打乱在制品。
  • 减轻负荷： 团队以可持续的节奏拉取工作。
  • 可预测性： 流动指标支持可靠的预测。
  • 易于起步： 无需设立新角色或新仪式。

何时使用 Kanban

  • 工作持续且不可预测地到来：支持、运营、维护。
  • 工作项在规模和紧急程度上差异很大。
  • 团队希望在不进行大规模重组的情况下逐步改进。
  • 多个团队或个人共享一项服务，需要了解需求情况。

对于以固定周期开展的产品开发，请比较 Kanban 与 Scrum.

如何在一周内起步

  1. 梳理您的工作实际经历的各个阶段。
  2. 按这些阶段绘制看板，并将当前所有工作项放上去。
  3. 为每个活动列商定 WIP 限制，大致为每人一到两项。
  4. 每天召开简短的 Kanban 会议 （在看板前进行）。
  5. 两周后，查看 周期时间 以及卡片在何处等待，并做出一项改进。

常见问题

Kanban 属于敏捷吗？

是的。Kanban 被普遍视为一种敏捷方法，它关注流动和持续改进，而不是固定的迭代。

Kanban 有角色吗？

Kanban 方法不要求设立新角色。一些团队在成熟后会增设服务交付经理或服务请求经理。

使用 Kanban 需要软件吗？

不需要。一块白板和一些便利贴就足以起步。数字工具对远程团队和指标统计很有帮助。

Kanban 是什么意思？

Kanban 在日语中意为“看板”或“可视卡片”。在丰田，看板卡用于发出某道工序需要更多零件的信号，从而使生产由真实需求拉动。

简单来说，什么是 Kanban？

Kanban 是一种管理工作的方式：把每个工作项放在可视化看板上，限制同时进行的工作量，并稳步改进工作流向完成的方式。您可以从现有流程开始，逐步加以改变。

Kanban 方法是谁创建的？

面向知识工作的 Kanban 方法由 David J. Anderson 等人在 2000 年代开发，其基础是大野耐一主导的丰田生产方式中的看板系统。

Kanban 的核心实践有哪些？

可视化工作、限制在制品、管理流动、明确规则、建立反馈循环，以及通过协作和实验进行改进。请参阅 Kanban 原则.

Kanban 使用冲刺吗？

不使用。Kanban 管理的是持续的工作流，在产能空出时拉入工作项，而不是在固定时长的迭代中进行规划。希望有时间盒节奏的团队通常会考虑 Scrumban.

哪些类型的团队使用 Kanban？

软件、IT 运维和支持、营销、人力资源、法务、设计以及许多其他团队都在使用 Kanban。它适合持续到来或在规模和紧急程度上差异较大的工作。

Kanban 中的 WIP 限制是什么？

WIP 限制规定了某个阶段或整个看板上同时可容纳的工作项数量上限。它能防止团队同时开展过多工作，并缩短每个工作项所需的时间；请参阅 WIP 限制.

Kanban 适合项目管理吗？

适合，尤其是优先级多变或任务源源不断的项目。当有固定截止日期时，许多团队会将 Kanban 看板与里程碑或高层级计划结合使用。

如何开始使用 Kanban？

将当前工作流映射为看板列，把所有当前工作写在卡片上，商定 WIP 限制和几条明确的规则，然后每天围绕看板召开简短会议。随着认识的加深不断改进看板。
