Kanban 与 Scrumban：有什么区别？

Scrumban 是 Scrum 和 Kanban 的混合体。它保留了 Scrum 的部分结构，例如定期规划和回顾会，同时采用 Kanban 的持续流动和 WIP 限制。

  • 阅读时长 3 分钟

要点总结

  • Scrumban 融合了 Scrum 的节奏和 Kanban 的流动。
  • 它适合经常面对计划外工作的 Scrum 团队。
  • 未使用 Scrum 的团队可以直接从 Kanban 开始。

何时选择 Scrumban

  • Scrum 团队的冲刺不断被紧急工作打断。
  • 团队希望从 Scrum 逐步过渡到 Kanban。
  • 工作中既有计划内的功能，也有计划外的请求。
  • 团队重视 Scrum 的反思节奏，但不想要固定的冲刺承诺。

何时纯 Kanban 更好

如果您目前没有使用 Scrum，可以直接从 Kanban 开始。Scrumban 最适合作为已在实践 Scrum 的团队的过渡桥梁。

常见问题

Kanban 与 Scrumban：Scrumban 是谁创立的？

该术语由 Corey Ladas 在 2000 年代后期推广，最初是作为 Scrum 团队向 Kanban 过渡的一种方式。

Kanban 和 Scrumban 使用冲刺吗？

Kanban 不使用。Scrumban 可以使用：一些 Scrumban 团队保留冲刺长度的规划周期；另一些则在“就绪”列不足时随时规划。

Kanban 与 Scrumban：什么是 Scrumban？

Scrumban 是一种混合方法，结合了 Scrum 的定期节奏和评审，以及 Kanban 的持续流动、可视化看板和 WIP 限制。

Kanban 和 Scrumban 有什么区别？

Kanban 是一种逐步改进任何现有流程的方法，不要求设置角色或迭代。Scrumban 在 Kanban 流动的基础上增加了一些 Scrum 元素，例如定期规划会议或评审会议。

Kanban 和 Scrumban 有规定的角色吗？

两者都不强制要求角色。从 Scrum 转向 Scrumban 的团队通常会保留产品负责人或 Scrum Master，而另一些团队则会取消这些角色。

团队应在何时选择 Scrumban 而非 Kanban？

Scrumban 适合希望更灵活或需要处理大量计划外工作的 Scrum 团队，也适合希望拥有定期规划和评审节奏的 Kanban 团队。

Kanban 和 Scrumban 都使用 WIP 限制吗？

是的。看板上的 WIP 限制是 Scrumban 借鉴的主要 Kanban 元素之一。

Kanban 和 Scrumban 的规划方式有何不同？

在 Scrumban 中，规划按需进行，例如当“就绪”列低于设定阈值时，或者定期进行，没有固定的冲刺承诺。Kanban 则在产能释放时持续补充工作。

Kanban 和 Scrumban 是官方框架吗？

与 Scrum 不同。Kanban 自称为一种方法，并有已发布的指导材料，例如 Kanban University 的 Kanban 方法资料。Scrumban 没有单一的官方指南；它是一种由团队根据自身需要灵活塑造的方法。

Kanban 和 Scrumban 团队会举行回顾会吗？

大多数 Scrumban 团队保留了 Scrum 中的定期回顾会，因为无论交付节奏如何，反思都很有价值。Kanban 团队利用服务交付评审和运营评审进行改进，许多团队也会增加回顾会。

Kanban 与 Scrumban：哪个更适合维护团队？

两者都可以。Scrumban 深受那些同时处理计划内功能工作与缺陷和支持请求的团队欢迎，因为持续流动比固定冲刺更能吸收计划外工作。纯 Kanban 适合工作几乎全部为计划外的团队。
