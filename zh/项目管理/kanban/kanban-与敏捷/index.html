Kanban 与敏捷：Kanban 如何融入敏捷

Kanban 和敏捷并非竞争关系。敏捷是一套价值观和原则；Kanban 是应用它们的一种方法，其根源在于精益制造而非软件。

要点总结

  • 敏捷是一种思维方式；Kanban 是应用这种思维方式的一种方法。
  • Kanban 源自精益，注重流动。
  • Kanban 演进您现有的流程，而不是取而代之。

简短回答

敏捷 是一种思维方式，阐述于 敏捷宣言. Kanban 是一种管理流动的方法，被广泛用于践行敏捷。Kanban 契合敏捷对持续交付价值、响应变化和定期改进的重视。

Kanban 与敏捷的契合之处

  • 持续交付价值。
  • 欢迎优先级变化：新工作可以随时被拉取。
  • 通过 WIP 限制保持可持续的节奏。
  • 通过节奏和评审进行定期反思。
  • 通过可视化看板实现透明。

Kanban 的不同之处

典型的敏捷框架（如 Scrum）Kanban
起源软件开发精益制造
时间结构固定迭代持续流动
变革方式采用新框架演进您当前的流程
关注点交付增量优化流动

两者结合使用

Kanban 可以作为一种敏捷方法单独使用，也可以与其他框架结合，例如 Scrum 团队使用 Kanban 看板和 WIP 限制。参见 Kanban 与 Scrum.

常见问题

Kanban 与敏捷：Kanban 是一种敏捷方法论吗？

是的，Kanban 通常被归类为一种敏捷方法，尽管它源自精益制造，而非最初的敏捷软件运动。

团队可以不用 Scrum 而践行敏捷和 Kanban 吗？

可以。许多团队仅使用 Kanban 来践行敏捷原则。

Kanban 和敏捷有什么区别？

敏捷是一套以迭代方式交付工作并响应变化的价值观和原则。Kanban 是一种具体的方法，侧重于工作可视化和限制 WIP，许多团队借助它以敏捷的方式开展工作。

Kanban 与敏捷如何结合？

Kanban 被普遍视为与 Scrum 和 XP 并列的敏捷方法之一，尽管其根源在于精益制造。参见 敏捷方法论的类型.

Kanban 和敏捷都源于精益吗？

Kanban 源自丰田的精益思想，而敏捷则源于 2001 年《敏捷宣言》背后的软件运动。Kanban 与敏捷同样关注客户价值、反馈和持续改进，因此通常被视为既属于精益也属于敏捷。参见 精益 Kanban.

Kanban 和敏捷是否共享《敏捷宣言》的价值观？

Kanban 并非依据《敏捷宣言》制定，但与其价值观高度契合：重视协作、可用的成果和响应变化，而非僵化的计划。

敏捷与 Kanban：其他主要的敏捷框架有哪些？

常见的包括 Scrum、极限编程（XP）、Scrumban 以及 SAFe 等规模化框架。参见 Kanban 与 Scrum.

Kanban 和敏捷是迭代式的吗？

大多数敏捷方法都是迭代和增量式的。Kanban 是增量且持续的，而不是按固定周期迭代：事项在完成后逐一交付，定期的节奏提供反馈。

非软件团队能否使用 Kanban 和敏捷？

可以。营销、人力资源、财务和运营团队常常把 Kanban 作为进入敏捷的切入点，因为它不需要新的角色或冲刺。

Kanban 与敏捷：Kanban 是方法论还是框架？

它通常被称为一种方法：Kanban 方法。它提供的是应用于现有流程的原则和实践，而不是一套固定的角色和事件。

敏捷与 Kanban：哪个更好？

它们并非二选一。敏捷是理念，Kanban 是将其付诸实践的一种方式，因此真正的选择是在 Kanban、Scrum 或其他方法之间进行。
