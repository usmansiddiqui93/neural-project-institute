项目预测：方法、示例和步骤

项目预测是根据项目迄今为止的绩效和仍需完成的工作，预测项目的最终结果，主要是最终成本和完成日期。好的预测能在还有时间采取行动时，向发起人提供诚实的早期预警，通常最好以带有置信水平的区间而非单一数字来表述。

作者Neural Project Institute项目管理编辑团队
  • 发布于 2026 年 9 月 30 日
  • 最后更新 2026 年 10 月 25 日
  • 阅读时间 19 分钟

要点总结

  • 同时预测最终成本（EAC）和完成日期；只预测其中一项会产生误导。
  • EAC = BAC / CPI 等挣值公式是一个快速、客观的起点，而不是最终答案。
  • 挣得进度（预测工期 = 计划工期 / SPI(t)）提供的时间预测在项目后期仍然可靠。
  • 蒙特卡洛模拟和敏捷速度区间将预测转化为概率和日期区间。
  • 用团队对剩余工作的重新估算、未关闭的风险和待定的变更来验证公式结果。
  • 每个报告期更新预测，跟踪其准确性，并如实报告。

什么是项目预测？

项目预测 是利用迄今为止的实际绩效、剩余工作和已知风险，预测项目未来结果（主要是最终成本、完成日期和资源需求）的过程。与最初的估算不同，预测在整个交付过程中不断更新，因此决策者始终能看到与已批准基准相比最可能的终点。

预测是监控的一部分。在 PMI 的 PMBOK 指南第八版（2025 年 11 月）中，它属于监控财务和进度等过程。

预测、估算、预算和目标的对比

这四个词经常被随意使用，这在指导会议上会造成混淆。

术语是什么何时设定是否可以变更？
估算在工作完成之前对成本或工期做出的预计在规划期间，根据范围和假设在规划期间细化
预算已批准的资金数额（即 完工预算，即 BAC）成本基准获批时只能通过正式的变更控制
预测利用实际绩效对最终结果做出的当前最佳预测交付期间的每个报告期是的，每次更新时都要
目标期望的结果，通常是管理层设定的挑战性目标任何时候由管理层酌情决定

预算是一种承诺；预测是一种预计。当预测偏离预算时，这个差距就是需要做出决策的信号，例如变更范围、追加资金或采取恢复措施。一个被悄悄调整以符合预算的预测就不再是预测了。

预测哪些内容

大部分注意力都放在成本和日期上，但完整的预测涵盖发起人做出决策所需的一切内容。

预测项典型衡量指标回答的问题
最终成本完工估算 （EAC）项目总共将花费多少？
完工所需成本完工尚需估算（ETC = EAC - AC）我们还需要多少资金？
完工偏差VAC = BAC - EAC项目完成时将超出或低于预算多少？
完成日期预测的完成日期或工期最后一项可交付成果何时完成？
资源需求按月统计的人员、技能或全职当量（FTE）我们有足够的人员完成剩余工作吗？
风险和应急储备未关闭风险的期望值；剩余应急储备剩余的应急储备够用吗？
优势预期收益及其实现时间项目是否仍然值得做？

在大型项目中，预测通常在工作包或控制账户层级做出，然后再向上汇总。

项目预测方法

预测方法大致分为两大类。 定性方法 依靠判断，在数据很少时使用，例如在项目早期或针对全新的工作。 定量方法 使用绩效数据和模型，随着项目推进会变得更加可靠。

方法类型所需数据产出最佳用途
专家判断和团队重新估算定性对剩余工作的了解点估算或区间估算随时，尤其是在发生变更之后
德尔菲技术定性专家小组共识区间对于不确定的工作，尽早进行
类比估算和参考类别预测定性/基于数据类似过往项目的结果基于历史数据调整后的估算商业论证和早期规划
挣值公式定量BAC、PV、EV、ACEAC、ETC、VAC、TCPI在完成足够多的工作、指数趋于稳定之后
挣得进度定量PV 曲线、EV、实际时间预测工期贯穿始终，包括项目后期
关键路径更新定量更新后的进度网络预测的完成日期和里程碑日期按进度计划推进的项目每次更新时
三点估算（PERT）定量乐观、最可能、悲观的持续时间期望值和分布重新估算剩余任务
蒙特卡洛模拟定量持续时间、成本和风险的区间实现日期和预算的概率大型或高风险项目
速度或吞吐量定量近期迭代数据、剩余待办列表日期或范围区间敏捷和基于流动的工作

定性方法

专家判断 是所有方法中使用最多的，因为总得有人判断公式结果是否合理。最有价值的形式是一次结构化的 对剩余工作的重新估算 ，由执行工作的人员完成。 德尔菲技术 通过多轮从专家小组收集匿名估算，并在各轮之间分享结果，直到范围收窄。

参考类别预测 从一组类似的过往项目的实际结果出发，而不是从本项目的细节出发。这一理念源于 Daniel Kahneman 和 Amos Tversky 关于规划谬误的研究，并由 Bent Flyvbjerg 等人应用于项目。它是对乐观偏差的有力校验，尤其适用于商业论证。

定量方法

定量方法使用项目自身的数据：挣值和挣得进度将指数向前推算，进度更新重新计算关键路径，而蒙特卡洛模拟和速度区间则增加了对不确定性的衡量。以下各节将用数字逐一说明。

使用挣值预测成本

挣值管理 （EVM）是成本预测中使用最广泛的定量方法。它在每个状态日期比较三个数字：计划价值（PV）、挣值（EV）和实际成本（AC），并据此得出 成本绩效指数 （CPI = EV / AC）和进度绩效指数（SPI = EV / PV）。

公式假设条件适用情况
EAC = BAC / CPI当前成本效率保持不变超支的原因会影响剩余工作
EAC = AC + (BAC - EV)剩余工作按原始预算进行偏差是一次性的，原因已经消除
EAC = AC + (BAC - EV) / (CPI x SPI)成本绩效和进度绩效都会影响剩余工作进度已经落后，但仍必须满足固定的结束日期
EAC = AC + 自下而上的 ETC原有估算已不再适用范围、费率或方法已发生变化
ETC = EAC - AC剩余工作的成本
VAC = BAC - EAC预计超支（负值）或结余
TCPI = (BAC - EV) / (BAC - AC)剩余工作要在预算内完成所需的效率

示例详解：预测最终成本

一个软件实施项目的预算（BAC）为 $200,000，计划工期为八个月。第四个月末的数据如下： PV = $80,000，EV = $70,000，AC = $85,000。因此 CPI = 70,000 / 85,000 = 0.824 ，SPI = 70,000 / 80,000 = 0.875。项目超出预算且进度落后。

预测计算EACVAC
EAC（CPI 保持不变）200,000 / 0.824$242,857-$42,857
EAC（一次性偏差）85,000 + (200,000 - 70,000)$215,000-$15,000
EAC（CPI x SPI）85,000 + 130,000 / (0.824 x 0.875)$265,408-$65,408
EAC（自下而上）85,000 + 团队的 ETC $150,000$235,000-$35,000

公式给出的范围大约在 $215,000 到 $265,000 之间。为了选定一个数字，项目经理询问超支的原因。在本例中，团队发现集成工作比估算的更难，而且这会影响其余接口，因此一次性偏差公式过于乐观。团队自下而上的重新估算（$235,000）与基于 CPI 的数字（$242,857）接近，这增强了信心。向发起人报告的预测是 $235,000 至 $245,000，最可能约为 $240,000，ETC 约为 $155,000。

完工尚需绩效指数提供了一个现实检验：TCPI = (200,000 - 70,000) / (200,000 - 85,000) = 1.13。要在预算内完成，团队从现在起每花一美元就必须交付 $1.13 的价值，而到目前为止它只做到了 $0.82。这个差距太大，无法靠更加努力来弥补，因此发起人必须在追加资金和缩减范围之间做出选择。有关每个公式的更多详情，请参阅我们关于 完工估算.

预测完成日期

成本公式并不能直接说明日期。预测完成时间有三种常用方法；请至少使用两种。

1. 更新进度计划和关键路径

输入每项进行中任务的实际开始和完成日期以及剩余持续时间，然后让进度安排工具重新计算。新的完成日期来自更新后的 关键路径，它显示哪些任务实际在驱动结束日期。这是最直接的方法，也是大多数发起人能理解的方法。其弱点在于它依赖于诚实的剩余工期，最好来自 三点估算.

2. 使用 SPI 调整计划工期

一种快速核对方法是预测工期 = 计划工期 / SPI。在本例中，8 / 0.875 = 9.1 个月。它很简单，但有一个已知的缺陷：SPI 以金额计算，随着项目接近完成，它总会回到 1.0，因为最终所有计划价值都会被挣得，即使项目已经晚了几个月。在项目后期，它就不再有用了。

3. 使用挣得进度

挣得进度 （ES）由 Walt Lipke 于 2003 年提出，并由 Kym Henderson 加以扩展，它通过以时间而不是金额来衡量进度绩效，修正了这一缺陷。ES 是按照基准当前 EV *应当*被挣得的时间点。关键公式如下：

  • ES = C + (EV - C 时的 PV) / (C+1 时的 PV - C 时的 PV)，其中 C 是计划价值小于或等于 EV 的最后一个完整周期。
  • SPI(t) = ES / AT，其中 AT 是实际经过的时间。
  • SV(t) = ES - AT，即以时间单位表示的进度偏差。
  • 预测工期（IEAC(t)） = 计划工期 / SPI(t)。

继续该示例，按月累计的计划价值如下所示。

月份12345678
累计 PV（千美元）10285080112145175200
  1. 第四个月的 EV 为 $70,000。计划价值在第三个月末超过 $50,000，在第四个月末达到 $80,000，因此 C = 3。
  2. ES = 3 + (70,000 - 50,000) / (80,000 - 50,000) = 3 + 0.67 = 3.67 个月.
  3. SPI(t) = 3.67 / 4 = 0.917，SV(t) = 3.67 - 4 = -0.33 个月 （落后约一周半）。
  4. 预测工期 = 8 / 0.917 = 8.7 个月.

因此，日期预测从 8.7 个月（挣得进度）到 9.1 个月（简单 SPI）不等。项目经理随后检查关键路径：如果延迟的集成任务在关键路径上，较晚的数字更切合实际；如果它们有浮动时间，较早的数字可能更准确。报告的预测是一个完成 在第九个月中旬至第十个月初之间，以及成本区间。

使用蒙特卡洛模拟进行概率预测

蒙特卡洛模拟 使不确定性变得可见。您不是为每项剩余任务输入单一的持续时间或成本，而是输入一个区间（乐观、最可能和悲观），以及关键风险的概率和影响。软件会从每个区间中随机取值，将进度和成本重新计算数千次，并绘制出结果的分布。

其产出是一组 置信水平，通常称为 P 值。P50 表示有 50% 的可能性在该日期或成本之内完成；P80 表示有 80% 的可能性。下表展示了示例项目中剩余工作的示意性结果。

置信水平预测完成时间（示意）预测最终成本（示意）
P108.6 个月$226,000
P509.1 个月$239,000
P809.6 个月$251,000
P909.9 个月$258,000

解读：最可能的结果接近确定性预测，但如果发起人希望达到 80% 的置信度，就应按 9.6 个月和约 $251,000 进行规划。P50 和 P80 之间的差值为进度和成本应急储备提供了有依据的基础。它还显示了哪些任务和风险对波动幅度影响最大。

蒙特卡洛模拟的好坏取决于其区间：如果区间太窄（这很常见），结果看起来很精确，实际上却是错的。尽可能使用历史数据，并将模型与以下内容关联： 风险登记册 ，使已知风险得到明确建模。

敏捷项目中的预测

敏捷团队通常固定每次迭代的时间和成本，并预测到某个日期能交付多少范围，或者某个范围何时能完成。输入是剩余的待办列表和团队近期的交付速率： 速度 以故事点计，或 吞吐量 ，以每周条目数计。

示例详解：基于速度的发布预测

一个 Scrum 团队的发布待办列表中还剩 240 个故事点，以两周为一个 Sprint 开展工作。其过去六个 Sprint 的速度分别为 28、32、25、30、35 和 30 点（平均 30）。

情景所用速度所需 Sprint 数（240 / 速度）周
乐观（最好的三个 Sprint 的平均值）32.37.4，即 8 个 Sprint16
平均值308 个冲刺16
悲观（最差的三个 Sprint 的平均值）27.78.7，即 9 个 Sprint18
重复观测到的最差 Sprint259.6，即 10 个 Sprint20

团队报告的预测为 8 到 10 个 Sprint（16 到 20 周），最可能为 8 或 9 个。每个 Sprint 结束后都会更新预测，发布燃起图同时显示已完成的工作和范围的任何增长，因此发起人可以看出日期推迟是由于交付变慢还是由于新增了待办条目。

针对基于流动的团队使用吞吐量和蒙特卡洛模拟

看板团队通常改用吞吐量进行预测。一种简单的蒙特卡洛方法是从团队实际的每周吞吐量历史中抽样，模拟数千种可能的未来，从而得出诸如“有 85% 的可能在 11 周内完成这 60 个条目”的结论。它不需要对条目进行估算，只需要一段合理的已完成工作历史记录。

资源和收益预测

资源预测 预测剩余工作需要哪些人员、技能和设备以及何时需要。从更新后的进度计划和 ETC 出发，将每个角色的剩余工作量按月转换为工时或全职当量，并与可用资源进行比较。缺口显示了您需要在哪些地方招聘、借调或重新排序工作；参见 产能规划.

收益预测 考察项目是否仍能实现其商业论证中的价值：完成时间推迟会延迟收益，超支会降低回报，而缩减范围可能会完全取消某些收益。在每个阶段关口重新审视。

如何逐步做出项目预测

  1. 设定状态日期。 对进展、成本和风险使用相同的截止日期，以确保数据一致。
  2. 检查数据。 确保实际成本包括已完成工作的应计费用和已承诺成本，并采用商定的规则而不是乐观的百分比来衡量进展。
  3. 计算各项指标。 计算 CPI、SPI、SPI(t) 以及基于公式的 EAC 和工期。在电子表格中只需几分钟。
  4. 更新进度计划。 输入实际值和剩余工期，并重新计算关键路径。
  5. 重新估算剩余工作。 请执行工作的人员对已发生变化或绩效与计划不同的工作包做出自下而上的 ETC。
  6. 添加风险和变更。 包括未关闭风险的预期成本、剩余应急储备、已批准的变更以及可能获批的变更请求。
  7. 比较并选择。 将公式结果、进度更新和自下而上的估算并列比较，判断哪一个最可信，并说明原因。
  8. 以区间表示。 给出最可能的数值和一个区间，如果进行过模拟，还要注明置信水平。
  9. 报告并采取行动。 呈现预测、其驱动因素以及改进预测的选项，并记录预测，以便日后与实际结果进行比较。

第 1 至 4 步大部分可以自动化，从而把时间留给第 5 至 9 步中的判断，而正是这些判断让预测变得可信。

完成不到约 15-20%自下而上的重新估算和进度更新；只将挣值指数视为早期指标
项目中期且绩效稳定挣值 EAC 和挣得进度，并用关键路径进行交叉核对
在重大变更或重新规划之后根据新计划进行自下而上的 ETC；根据新基准计算挣值
项目后期日期使用挣得进度和关键路径（而非简单的 SPI）；剩余条目使用自下而上的 ETC
大型、高风险或合同性项目对成本和进度进行蒙特卡洛模拟，并结合挣值
敏捷或基于流动的交付速度或吞吐量区间、燃起图、吞吐量蒙特卡洛模拟

无论何种情况，都至少使用两种独立的方法。当它们出现分歧时，差异本身就说明了重要的问题。

如何呈现预测

只有当发起人理解预测并能据此采取行动时，预测才有帮助。在以下文件中设置清晰的预测部分： 项目状态报告 通常包括：

  • 要点： 最可能的最终成本和完成日期，并与基准进行比较。
  • 区间和置信度： ，例如“$235,000 至 $245,000；在第九个月中旬至第十个月初之间完成”。
  • 自上次报告以来的变化： 什么发生了变化以及原因。
  • 驱动因素： 造成偏差的两三个主要原因。
  • 选项： 能够改善结果的行动及其成本和效果，例如缩减范围、增加人员或动用应急储备。
  • 需要的决策： 您要求发起人决定什么，以及何时之前决定。

提前商定阈值，例如如果 EAC 超出 BAC 5% 以上，或预测的完成时间晚于某个关键里程碑，就进行上报，这样当预测恶化时就会触发决策，而不是讨论。我们的 应急计划 指南解释了当预测显示需要时如何设定和释放储备。

项目预测的准确度如何？

随着项目推进，预测会变得更加准确，因为更多的成本是实际值而不是估算值。关于挣值预测多快趋于稳定，有一些研究证据。在 1993 年对 155 份美国国防部合同的研究中，David Christensen 和 Scott Heise 发现，一旦合同完成超过 50%，累计 CPI 的变化不超过 10%。后来的研究，例如 Henderson 和 Zwikael 关于绩效稳定性的研究，对这一结论在其他类型项目中的适用程度提出了质疑，因此请将其视为有用的参考，而不是规则。

实践中的教训：在中途超出预算的项目，如果不具体改变剩余工作的完成方式，很少能够恢复。

跟踪自己的预测准确度

记录每个周期对最终成本和完成日期的预测，然后在收尾时与实际结果进行比较。一张简单的 EAC 预测随时间变化的图表可以显示预测是否稳定、是否稳步上升（乐观的迹象）或是否在后期突然跳变（问题被隐瞒的迹象）。将这些发现记录在您的 经验教训 ，从而改进下一个项目的估算和预测。

常见的预测错误

  • 只预测发起人想听到的结果。 政治压力是对诚实预测的最大威胁。
  • 以为项目会自行好转 ，而没有具体的理由，例如方法改变或增加了资源。
  • 默认采用最乐观的公式。 AC + (BAC - EV) 在超支时给出的数值最小，但它假设问题已经消失。
  • 预测成本却不预测日期，或预测日期却不预测成本。 延迟的项目几乎总是成本更高。
  • 忽视已承诺成本和应计费用， 这会让项目看起来比实际更便宜。
  • 依赖被夸大的进展。 如果任务连续数周停留在 90% 完成，EV 就会被高估，每一项预测都会过于乐观。
  • 在项目后期使用简单 SPI， ，即无论实际延误如何，它都会趋向 1.0。请使用挣得进度或关键路径。
  • 只报告一个精确数字 ，例如 $242,857，这会给人虚假的确定感。
  • 更新太少， ，因此预测在临近结束时会突然跳变。
  • 遗漏风险和待定变更 团队中的每个人都知道。

常见问题

什么是项目预测？

根据项目迄今为止的绩效和剩余工作，预测其最终成本、完成日期、资源需求和其他结果，并在整个交付过程中更新这一预测。

主要的项目预测方法有哪些？

专家判断和自下而上的重新估算、参考类别预测、挣值公式、挣得进度、关键路径更新、三点估算、蒙特卡洛模拟，以及敏捷团队的速度或吞吐量预测。

如何预测项目的最终成本？

使用 EAC = BAC / CPI 等挣值公式计算完工估算，然后用剩余工作的自下而上估算加上未关闭的风险和待定变更进行交叉核对。

如何预测项目的完成日期？

用实际进展更新进度计划和关键路径，并用挣得进度进行交叉核对：预测工期 = 计划工期 / SPI(t)。

预测和估算有什么区别？

估算是在工作开始之前根据范围和假设做出的。预测则是在交付期间利用实际绩效更新预计。

预测和预算有什么区别？

预算是已批准的金额，只能通过变更控制进行更改。预测是对最终成本的当前最佳预计，每个周期都可能变化。

项目预测中的 ETC 是什么？

完工尚需估算：剩余工作的预期成本。ETC = EAC - AC，或者对剩余工作进行新的自下而上估算。

什么是挣得进度？

由 Walt Lipke 提出的一种方法，以时间而非金额来衡量进度绩效。它给出 SPI(t) = ES / AT，预测工期 = 计划工期 / SPI(t)，并且在项目后期仍然可靠。

什么是蒙特卡洛项目预测？

一种模拟方法，使用每项估算和风险的区间将进度和成本重新计算数千次，显示在某个日期之前或某个成本之内完成的概率，例如 P50 和 P80。

敏捷团队如何进行预测？

用剩余待办列表除以近期速度或吞吐量的区间，得出一个日期区间，并在每次迭代时用燃起图进行更新。

项目预测应多久更新一次？

每个报告期，通常为每月或每个 Sprint，以及每当发生重大变更、问题或风险时。

为什么预测应该是一个区间而不是单一数值？

因为未来是不确定的。带有置信度的区间更加诚实，也有助于发起人设定合理的应急储备。

挣值预测何时可靠？

它们会随着项目推进而变得更加可靠。Christensen 和 Heise 在 1993 年对美国国防合同的研究发现，合同完成超过 50% 后，累计 CPI 的变化不超过 10%，但后来的研究对这一结论的适用范围提出了质疑。
