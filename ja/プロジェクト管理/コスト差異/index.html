コスト差異（CV）：計算式、例、分析

コスト差異（CV）は、プロジェクトで完了した作業に、予算より多くのコストがかかったのか少なかったのかを示します。アーンドバリューマネジメントではCV = EV - ACで計算し、結果がマイナスなら完了した作業に対して予算超過、プラスなら予算内です。このガイドでは、計算式、5つのワークパッケージにわたる計算例、しきい値の設定方法、数値が赤になったときの対処法を解説します。

要点

  • CV = EV - AC。マイナスなら完了した作業に対して予算超過、プラスなら予算内です。
  • CV% ＝ CV / EV x 100を使うと、規模の異なるワークパッケージやプロジェクトを比較できます。
  • 実コストは計画支出ではなくアーンドバリューと比較します。そうしないと、スケジュールの影響とコストの影響が混ざってしまいます。
  • CVをワークパッケージごとに分解して何が差異を生んでいるかを見つけ、累積の傾向を月ごとに追跡します。
  • しきい値は割合と金額の両方で設定し、超えた場合に何をするかを事前に合意しておきます。
  • CVは必ず、スケジュール差異、CPI、完成時総コスト見積り（EAC）と併せて読みましょう。

コスト差異（CV）とは何ですか？

コスト差異（CV） は、ある基準日において、実際に完了した作業の予算コスト（アーンドバリュー、EV）と、その作業の実コスト（AC）の差です。完了した作業に計画より多くのコストがかかったのか少なかったのかを金額で示します。CVがマイナスなら、完了した作業に対してプロジェクトは予算超過です。

コスト差異は、次の中核的な指標の1つです： アーンドバリューマネジメント（EVM）、そして スケジュール差異、 コスト効率指数 および 完成時総コスト見積り（EAC）。プロジェクト全体について計算し、さらに有用なのは次の単位ごとに計算することです： ワークパッケージ またはコントロールアカウント。

古いEVMの資料や一部の政府契約では、同じ入力値に別の名前が使われています：

現在の用語旧称意味
アーンドバリュー（EV）BCWP：実施作業の予算コスト実際に行った作業の予算
実コスト（AC）ACWP：実施作業の実コストその作業に実際にかかったコスト
計画価値（PV）BCWS：計画作業の予算コスト現時点までに行われているべき作業の予算

したがって CV = BCWP - ACWP は、CV = EV - ACとまったく同じ計算式です。

ヒント

一般的な財務では、「コスト差異」や「予算差異」は単に実際の支出と予算の比較を意味することがよくあります。EVMを用いるプロジェクトマネジメントでは、コスト差異は常に実コストを次と比較します： 完了した作業の価値。この区別こそがこの指標の要点であり、以下で詳しく説明します。

コスト差異の計算式

計算式示す内容
CV = EV - ACこれまでに完了した作業に対する金額ベースのコスト差異
CV% = (CV / EV) x 100完了した作業に対するコスト差異の割合
EV ＝ 完了率 x BACワークパッケージまたはプロジェクトのアーンドバリュー
VAC = BAC - EAC完成時差異：完了時に見込まれるコスト差異

ここで BAC は 完成時総予算、承認された予算総額、そして EAC は完成時総コスト見積り（EAC）で、最終コストの現時点での予測です。

結果の読み方

結果意味一般的な対応
CV > 0（プラス）完了した作業のコストが予算を下回った：予算内データが揃っているかを確認し、教訓を探すかコンティンジェンシーを解放する
CV = 0完了した作業のコストがちょうど予算どおり監視を続ける
CV < 0（マイナス）完了した作業のコストが予算を上回った：予算超過原因を見つけ、影響を予測し、対応を合意する

EVMにおける符号のルールは覚えやすいものです： マイナスは悪い を、コスト差異とスケジュール差異の両方に用います。財務チームによっては予算差異に逆の符号（実績－予算）を使うことがあるため、レポートを読む前にどちらの方式かを確認しましょう。

コスト差異の計算方法：ステップごとの手順

  1. 基準日を固定する。 すべての数値は、月の最終営業日など、同じ締め日に関するものでなければなりません。
  2. 各ワークパッケージのBACを確認する。 現在承認されている次を使います： コストベースライン（承認済みの変更を含み、マネジメント予備は除く）。
  3. 進捗を測定する。 合意した完了率のルール（短いタスクには0/100、50/50、長いものには重み付けマイルストーンなど）を各ワークパッケージに適用します。
  4. EVを計算する を各ワークパッケージについて算出します：完了率 x BAC。合計するとプロジェクト全体の値になります。
  5. ACを収集する を同じ作業について集計します。完了したがまだ請求されていない作業の未払計上や、正しい単価でのタイムシート時間も含めます。
  6. CVとCV%を計算する を各ワークパッケージと合計について。
  7. CPIを計算する （EV / AC）を算出し、前の期間と比較して傾向を把握します。
  8. しきい値と比較する を設定し、それを外れるものについては差異の説明を書きます。
  9. 予測を更新する：EACとVACを再計算し、その結果を次で報告します： 状況報告書.

ステップ3と5は、ほとんどの誤りが生じる箇所です。進捗が過大に報告されるとEVが高すぎ、CVが実際より良く見えます。請求書が作業より遅れるためにコストが欠落していると、ACが低すぎて同じ効果が生じます。どちらの問題もプロジェクトを実際より健全に見せるため、悪い知らせが遅れて届きます。

計算例：ワークパッケージ別のCRM導入

ある企業が新しい顧客関係管理（CRM）システムを導入しています。完成時総予算（BAC）は $400,000で、5つのワークパッケージに分かれています。5か月目末時点の状況は次のとおりです。

ワークパッケージBAC完了率EVACCVCV%CPI
1. 要求事項と設計$60,000100%$60,000$58,000+$2,000+3.3%1.03
2. 構成とビルド$140,00060%$84,000$103,000-$19,000-22.6%0.82
3. データ移行$70,00040%$28,000$26,500+$1,500+5.4%1.06
4. テスト$80,00010%$8,000$9,500-$1,500-18.8%0.84
5. トレーニングと稼働開始$50,0000%$0$0$0--
プロジェクト合計$400,00045%$180,000$197,000-$17,000-9.4%0.91

合計の計算

  • EV = 60,000 + 84,000 + 28,000 + 8,000 + 0 = $180,000 （BACの45%）。
  • CV = 180,000 - 197,000 = -$17,000.
  • CV% = -17,000 / 180,000 x 100 = -9.4%.
  • CPI = 180,000 / 197,000 = 0.914：プロジェクトは1ドル使うごとに約91セント分の計画作業しか得ていません。

内訳から分かること

  • 超過額全体は次によって説明されます： 構成とビルド：-$19,000、つまり完了した作業に対して22.6%の超過です。他のパッケージを合計すると+$2,000です。
  • テスト は割合の差異が大きい（-18.8%）ものの、ほとんど始まっていないため金額では-$1,500にすぎません。注視は必要ですが、まだ優先事項ではありません。
  • 要求事項は予算をわずかに下回り、データ移行もこれまでのところ効率的に進んでいます。

内訳がなければ、プロジェクト全体の数値（-9.4%）は全般的な問題を示唆します。内訳があれば、どこを見るべきかが分かります。この例では、構築チームの生産性、サプライヤーの単価、計画外のカスタマイズです。

CVを予測に変える

CVは現在地を示し、予測はどこに向かっているかを示します。

  • 現在の効率が続く場合： EAC = BAC / CPI = 400,000 / 0.914 = 約 $437,800.
  • VAC = BAC - EAC = 400,000 - 437,800 = 約 -$37,800。プロジェクトは9.4%の超過に向かっています。
  • 超過が一度きりで、残りの作業が計画どおりに進む場合：EAC = AC + (BAC - EV) = 197,000 + 220,000 = $417,000、VACは-$17,000です。
  • 当初の予算で終えるには、残りの作業に次が必要です： TCPI （(BAC - EV) / (BAC - AC) = 220,000 / 203,000 = 1.08が必要で、これはこれまでどのワークパッケージも達成していない効率です。

スポンサーへの誠実なメッセージは、構築の問題を解決しない限り、プロジェクトは予算より$17,000～$38,000多く必要になる可能性が高い、というものです。当サイトの 完成時総コスト見積り（EAC）のガイド で、計算式の選び方を説明しています。

月今月のEV今月のAC期間CV累積CV累積CV%累積CPI
1$20,000$19,000+$1,000+$1,000+5.0%1.05
2$25,000$25,000$0+$1,000+2.2%1.02

ヒント

累積のEV、AC、PVを1つのチャートにプロットします。ACとEVの線の間隔がコスト差異、PVとEVの線の間隔がスケジュール差異です。当サイトの次のガイドを参照してください： Sカーブ.

コスト差異が計画支出ではなくEVを使う理由

プロジェクトのコストで最もよくある読み違いは、実コストをその時点までの計画支出（PV）と比較することです。CRMの例の5か月目では：

比較計算結果示しているように見えること
実際の支出と計画支出の比較PV - AC = 205,000 - 197,000+$8,000「予算を$8,000下回っています」
コスト差異（EVM）EV - AC = 180,000 - 197,000-$17,000「完了した作業に予算より$17,000多くかかりました」
スケジュール差異（EVM）EV - PV = 180,000 - 205,000-$25,000「作業が計画より$25,000分遅れています」

プロジェクトの支出が計画より少ないのは、計画より作業が少ないからにすぎません。ACとPVを比較すると、「効率的に支出しているか？」と「予定どおりか？」という2つの異なる問いが混ざり、この例では実際の超過が隠れてしまいます。EVMはこれらを分けます： コストにはCV、スケジュールにはSV。どちらも実際に獲得した作業の価値に対して測定します。

このため、ごく小規模なプロジェクト以外では、単純な予算対実績のスプレッドシートでは不十分です。支出だけでなく、進捗の尺度が必要です。

コスト差異をスケジュール差異と併せて読む

CVだけでは半分しか分かりません。SVと併せて読み、プロジェクトの本当の状況を把握しましょう。

CVSV通常の意味問うべきこと
プラスプラススケジュールより先行し、予算内進捗は正確に報告されているか？コンティンジェンシーを解放できるか？
プラスマイナス予算内だがスケジュール遅延作業が安く済んでいるのではなく、遅れているだけではないか？リソースが不足していないか？
マイナスプラススケジュールより先行しているが予算超過スピードのために費用（残業、追加要員）を払っていないか？それは合意済みか？
マイナスマイナススケジュール遅延かつ予算超過根本原因は何か？再計画や変更要求は必要か？

CRMプロジェクトは最下行にあります：CVもSVもマイナスです（SPI = 180,000 / 205,000 = 0.88）。これは最も深刻な組み合わせです。スケジュールを取り戻すには通常さらにお金がかかり、コスト差異が悪化するからです。

コスト差異とCPI、VAC、予算差異の比較

指標計算式種類最適な用途
コスト差異（CV）EV - AC金額、現時点までこれまでの超過額または節約額の大きさを示す
CV%CV / EV x 100割合、現時点までワークパッケージとプロジェクトの比較、しきい値
コスト効率指数（CPI）EV / AC比率、現時点まで効率の傾向、EACの予測
完成時差異（VAC）BAC - EAC金額、予測完了時に見込まれる超過額を示す
スケジュール差異（SV）EV - PV金額、現時点まで作業が計画よりどれだけ進んでいるか遅れているかを示す
予算差異（財務）予算 - 実績、または実績 - 予算コスト項目別の金額期間とコストコードによる会計上の管理

CVとCPIは同じ入力値を使い、常に同じ方向を示します。CVがマイナスならCPIは1未満です。CVは問題となっている金額を示し、CPIは効率を示し、規模の異なるプロジェクト間でも比較しやすい指標です。両方を報告しましょう。

会計上のコスト差異

次のような表記も見られます： 材料費、労務費、間接費の差異。これらはEVMではなく、管理会計の標準原価計算に由来します。差異を価格と数量（または賃率と能率）の要素に分解します。例えば、労務費差異は、賃率差異（計画より高い時給を払った）と作業時間差異（計画より多くの時間を使った）に分けられます。

プロジェクトのコスト差異を説明するのに役立ちます。構成とビルドが$19,000超過している場合、$4,000は請負業者の単価上昇、$15,000は追加時間によるものだと分かれば、どこに手を打つべきかが分かります。ただし、これは診断ツールであり、アーンドバリューとの比較というEVMの代わりにはなりません。

差異のしきい値と対応のタイミング

すべての差異にミーティングが必要なわけではありません。ほとんどの組織は次を設定しています： 差異のしきい値 は、 コストマネジメント計画：それを超えるとプロジェクトマネージャーが差異を説明し、影響を予測し、対応を提案しなければならない限度です。しきい値は通常CVとSVの両方に設定され、回復のための時間が少なくなるため、プロジェクトが進むにつれて厳しくなることがよくあります。

適切なしきい値に普遍的な基準はありません。業界、契約の種類、見積りの精度、組織のリスク許容度によって異なります。下表は 例 （ルールではなく、調整して使うためのものです）：

ステータスしきい値の例（累積）アクション
緑CV%がプラスマイナス5%以内、かつ$10,000未満通常どおり報告
黄CV%が5～10%、または$10,000～$25,000次回のレポートで差異の説明と回復計画を文書で提出
赤CV%が10%超、または$25,000超スポンサーまたは委員会にエスカレーションする。EACを修正し、変更要求を検討する

割合と金額の両方を使うと、2つの問題を避けられます。割合だけでは、CRMの例のテスト（-18.8%だが-$1,500のみ）のような小さなパッケージにフラグが立ち、ノイズが生じます。金額だけでは、大きなパッケージでの意味のあるずれを見逃します。大きなプラスの差異はデータや見積りの問題を示すことが多いため、有利な方向のしきい値も設定するチームが多くあります。

例のしきい値では、CRMプロジェクト全体（-9.4%、-$17,000）は 黄、そして構成とビルドのパッケージ（-22.6%、-$19,000）は 赤 （パッケージレベルで）。

コスト差異のよくある原因

コスト差異がマイナスになる原因

  • 楽観的または不完全な見積り。 タスクの抜け、低すぎる生産性の想定、リスクに対する余裕の欠如。参照： コスト見積り.
  • 計画を上回る単価や価格。 労務単価、請負業者の日額、材料費、為替変動、インフレ。
  • 手戻り。 欠陥、不明確な要求事項、後からの設計変更により、作業が二度行われること。
  • 承認されていないスコープ変更。 スコープクリープ が変更管理を経ずに吸収されるため、コストは増えるのに予算は増えない。
  • 生産性の低下。 経験の浅いスタッフ、割り込み、コンテキストスイッチ、機能しないツール。
  • スケジュールのプレッシャー。 失われた時間を取り戻すための残業、特急料金、追加リソース。
  • 顕在化したリスク。 地盤条件、サプライヤーの不具合、規制の変更、停止。

コスト差異がプラスでも警告となるとき

支出不足が自動的に良い知らせとは限りません。喜ぶ前に次を確認しましょう：

  • 実コストの欠落：未受領の請求書、未提出のタイムシート、未計上の未払費用。
  • 進捗の過大報告：実際より進んでいると申告されたタスクがEVを水増しする。
  • 水増しされた見積り：大きく持続的なプラスのCVは、予算が過大で、ポートフォリオの他の場所で使えた可能性を示唆します。
  • 先送りされた作業：高額でリスクの高い作業がまだ残っている一方で、安い作業が先に完了している状態。
  • 品質の手抜き：今はコストが低いが、後のテストやサポートでコストが高くなる。

大きな差異の本当の原因を見つけるには、次のような体系的な手法： 特性要因図（フィッシュボーン図） やなぜなぜ分析は、作業を行ったチームと一緒に行うとうまく機能します。

コスト差異がマイナスのときの対応方法

  1. データを検証する。 誰かが結論を出す前に、進捗の測定と実コスト（未払計上を含む）を確認します。
  2. 差異の発生箇所を特定する。 プロジェクトからコントロールアカウント、ワークパッケージ、コスト項目へと掘り下げ、何が差異を生んでいるかを突き止めます。
  3. 根本原因を見つける。 価格と数量を分けて考えます：単価が上がっているのか、使用数量が増えているのか。
  4. 典型的か非典型的かを判断する。 原因は続くのか（構造的な生産性の問題）、それとも一度きりか（単発のサプライヤーの不具合）？これによって、どのEACの計算式を使うかが決まります。
  5. 影響を予測する。 EACとVACを再計算し、コンティンジェンシーへの影響を確認します。
  6. 是正処置または予防処置を合意する。 担当者と期日を割り当てる。
  7. ベースラインがもはや現実的でない場合は、変更要求を提出します。 し、次を経由させます： 変更管理.
  8. 判断を記録する し、次の期間のCVを監視して、アクションが効いているかを確認します。

是正処置の選択肢

選択肢役立つ場面注意点
根本原因を解決する（トレーニング、ツール、より明確な要求事項）生産性または手戻りの問題数値に表れるまで時間がかかる
単価を再交渉するか、サプライヤーを変更する価格による差異契約条件と切り替えコスト
残りの作業の順序を変えるか簡素化する設計やアプローチに柔軟性がある場合品質とステークホルダーの期待
スポンサーの承認を得てスコープを縮小する予算が固定されている場合便益が減る可能性がある。ビジネスケースを確認する

差異の背後にある特定済みのリスクについては、 コンティンジェンシー計画 には、どの予備費を使い、誰がそれを解放できるかがすでに書かれているはずです。

差異の説明に書くべきこと

  • 差異：CV、CV%、CPI（累積と期間）。
  • 原因を、根拠とともに1～2文で。
  • 原因が続くと見込まれるかどうか。
  • EAC、VAC、コンティンジェンシー、マイルストーンへの影響。
  • アクション、担当者、期日。
  • スポンサーまたは委員会に求める決定。

例：「構成とビルドは、完了した作業に対して$19,000の超過です（CV% -22.6%、CPI 0.82）。原因は、ユーザーが変更要求なしに依頼した営業パイプライン向けの210時間の追加カスタム開発です。スコープを管理しない限り、この傾向は続くと見込まれます。予測EACは$437,800（VAC -$37,800）です。アクション：11月1日から変更管理を通じてカスタマイズ依頼を凍結する（PM）、残りの構築作業を再見積りする（リード開発者、11月8日まで）。必要な決定：未処理のパイプライン変更を承認するか却下するか。」

アジャイルプロジェクトにおけるコスト差異

EVMは詳細なベースラインを持つ計画駆動型のプロジェクト向けに設計されましたが、コスト差異の考え方は、それに合った方法で進捗を測定すれば、アジャイルのデリバリーでも機能します。

  • リリースレベルでEVを測定する。 リリース予算をBACとし、計画したストーリーポイントのうち完了した割合を完了率として扱います。$300,000のリリースで300ポイント中120ポイントが完了していれば、EVは$120,000です。
  • ACにはスプリントあたりのチームコストを使う。 アジャイルチームのコストはかなり安定しているため、ACは多くの場合、スプリント数にスプリントあたりのチームコストを掛け、その他の支出を加えたものになります。
  • バックログが変わったらベースラインを再設定する。 プロダクトオーナーがスコープを追加または削除した場合は、CVがスコープの変化ではなく効率を反映するよう、計画ポイントを調整します。
  • ベロシティと併せて読む。 低下する ベロシティ は、同じコストで買えるポイントが減るため、CVの悪化として表れます。

この種のアプローチはAgileEVMと呼ばれることがよくあります。正確な管理ツールとしてよりも、スポンサーとの対話のきっかけとして使うのが最適です。当サイトの次のガイド： アジャイルのメトリクスとKPI で、ほとんどのアジャイルチームが日々頼りにしている指標を解説しています。

コスト差異でよくある間違い

  • 実コストを計画価値と比較する をアーンドバリューの代わりに使います。
  • プロジェクト全体の数値だけを報告する（どのワークパッケージが問題を引き起こしているかが隠れる）。
  • 主観的な完了率。例えば何週間も90%のまま止まっているタスクがあると、EVが水増しされます。
  • 未払計上や契約済みコストを無視するため、ACが低くなりすぎる。
  • マネジメント予備をBACに含めるため、パフォーマンスのベースラインがあいまいになる。
  • あらゆる差異を問題として扱うを、しきい値なしで行うため、本当の問題がノイズに埋もれてしまう。
  • 差異を説明するだけで予測しない：必ずEACとVACを更新します。
  • CVがプラスなら良い知らせだと思い込む （データを確認せずに）。
  • 変更管理なしにスコープ変更を受け入れるため、ベースラインが作業と合わなくなります。

ツールとテンプレート

小規模なプロジェクトなら、各ワークパッケージのBAC、完了率、EV、AC、CV、CV%、CPIを並べたスプレッドシートで十分です。次をもとに作成しましょう： WBS（ワーク・ブレークダウン・ストラクチャー） を整え、すべてのコストに行き先があるようにします。出発点は当サイトの WBSテンプレート、そして支出を次で追跡します： 予算テンプレート。当サイトの プロジェクトトラッカーテンプレート は進捗の把握に役立ち、 変更要求テンプレート は、差異のためにベースラインの変更が必要な場合に役立ちます。

より大規模なポートフォリオでは、作業の進行に合わせてEVとACが記録されるよう、予算、タイムシート、カスタムフィールドを備えたプロジェクト管理ソフトウェアを探しましょう。

よくある質問

プロジェクトマネジメントにおけるコスト差異とは何ですか？

コスト差異は、完了した作業のアーンドバリューとその実コストの差で、CV = EV - ACです。完了した作業に予算より多くのコストがかかったのか少なかったのかを示します。

コスト差異の計算式は何ですか？

CV = EV - AC。EVはアーンドバリュー（完了した作業の予算）、ACはその作業の実コストです。割合で表すと、CV% = CV / EV x 100です。

コスト差異がマイナスとはどういう意味ですか？

これまでに完了した作業のコストが予算を上回っているため、完了した作業に対してプロジェクトは予算超過です。CRMの例では、EVが$180,000、ACが$197,000で、CVは-$17,000になります。

コスト差異がプラスとはどういう意味ですか？

完了した作業のコストが予算を下回っているため、完了した作業に対してプロジェクトは予算内です。良い知らせとして扱う前に、データを確認しましょう。

プラスのコスト差異が悪いことはありますか？

はい。請求書や未払計上の欠落、進捗の過大報告、水増しされた見積り、今後控えている高額な作業などが原因になり得ます。大きく持続的なプラスの差異は、他で使えた予算があることも示唆します。

コスト差異の割合はどのように計算しますか？

コスト差異をアーンドバリューで割り、100を掛けます。EVが$180,000でCVが-$17,000なら-9.4%です。

許容できるコスト差異はどのくらいですか？

普遍的な数値はありません。許容限度はプロジェクトのコストマネジメント計画書で設定され、業界、契約、見積りの精度によって異なります。多くのチームは割合の幅と金額を組み合わせて使い、プロジェクトの進行に応じて厳しくしていきます。

コスト差異はどのくらいの頻度で計算すべきですか？

報告期間ごとに行います。ほとんどのプロジェクトでは通常毎月、短く動きの速いプロジェクトでは毎週または隔週です。進捗とコストには同じ基準日を使います。

コスト差異とスケジュール差異の違いは何ですか？

コスト差異（EV - AC）はコストパフォーマンスを測ります：効率的に支出しているか？スケジュール差異（EV - PV）はスケジュールパフォーマンスを金額で測ります：計画どおりの量の作業をこなしたか？どちらもアーンドバリューを使います。

コスト差異とCPIの違いは何ですか？

どちらもEVとACを使います。CVは金額での差（EV - AC）、CPIは比率（EV / AC）です。CVがマイナスなら、CPIは必ず1未満です。

完成時差異（VAC）とは何ですか？

完成時差異（VAC）は、プロジェクト完了時に見込まれるコスト差異で、VAC = BAC - EACです。VACがマイナスなら超過が予測されています。

コスト差異は予算差異と同じですか？

厳密には違います。予算差異は通常、ある期間の実際の支出を予算と比較します。EVMのコスト差異は、実コストを完了した作業のアーンドバリューと比較するため、コスト効率とスケジュールの進捗を切り分けられます。

BCWPとACWPとは何ですか？

アーンドバリュー（実施作業の予算コスト）と実コスト（実施作業の実コスト）の旧称です。コスト差異はBCWP - ACWPです。

コスト差異はアジャイルプロジェクトでも使えますか？

はい、リリースレベルで使えます。リリース予算をBAC、計画したストーリーポイントのうち完了した割合を完了率、スプリントあたりのチームコストを実コストとして使います。バックログが変わったらベースラインを調整します。
