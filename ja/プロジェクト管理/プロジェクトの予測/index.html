プロジェクトの予測：手法、具体例、手順

プロジェクトの予測とは、これまでのパフォーマンスと残りの作業から、プロジェクトがどこで終わるか、主に最終コストと完了日を予測することです。良い予測は、まだ行動する時間があるうちに、スポンサーに正直で早期の警告を与えます。通常は単一の数値ではなく、確信度を伴う幅で示すのが最善です。

要点

  • 最終コスト（EAC）と完了日の両方を予測します。一方だけでは誤解を招く全体像になります。
  • EAC = BAC / CPIのようなアーンドバリューの計算式は、素早く客観的な出発点であって、最終的な答えではありません。
  • アーンドスケジュール（予測期間 ＝ 計画期間 ÷ SPI(t)）を使えば、プロジェクトの終盤でも信頼性の保たれる時間の予測が得られます。
  • モンテカルロ・シミュレーションやアジャイルのベロシティの幅は、予測を確率や日付の幅に変えます。
  • 計算式の結果を、チームによる残作業の再見積り、未解決のリスク、保留中の変更と照らし合わせて検証します。
  • 報告期間ごとに予測を更新し、その精度を追跡し、正直に報告しましょう。

プロジェクトの予測とは何ですか？

プロジェクトの予測 とは、これまでの実際のパフォーマンス、残作業、既知のリスクを使って、プロジェクトの将来の結果、主に最終コスト、完了日、資源の必要量を予測するプロセスです。当初の見積りとは異なり、予測は提供期間を通じて更新されるため、意思決定者は常に、承認されたベースラインと比較した最も可能性の高い着地点を見ることができます。

予測は監視・コントロールの一部です。PMIのPMBOKガイド第8版（2025年11月）では、財務とスケジュールの監視・コントロールなどのプロセスの中に位置付けられています。

注目の大半はコストと日付に集まりますが、完全な予測には、スポンサーが意思決定に必要とするすべてが含まれます。

プロジェクトの予測手法

予測の手法は大きく2つの系統に分かれます。 定性的な手法 は判断に頼り、プロジェクトの初期や新規性の高い作業など、データが少ない場合に使われます。 定量的な手法 は、パフォーマンスデータとモデルを使い、プロジェクトが進むにつれて信頼性が高まります。

定性的な手法

専門家の判断 は、誰かが計算式の結果に意味があるかを判断しなければならないため、あらゆる手法の中で最もよく使われます。最も価値のある形は、体系的な 残作業の再見積り （作業を行う人々による）。 デルファイ法 は、パネルから匿名の見積りを数回にわたって集め、回ごとに結果を共有して、幅が狭まるまで繰り返します。

参照クラス予測法 は、このプロジェクトの詳細からではなく、類似した過去のプロジェクト群の実際の結果から出発します。この考え方はDaniel KahnemanとAmos Tverskyによる計画錯誤の研究に由来し、Bent Flyvbjergらによってプロジェクトに応用されてきました。特にビジネスケースにおいて、楽観バイアスに対する強力なチェックになります。

定量的な手法

定量的な手法はプロジェクト自身のデータを使います。アーンドバリューとアーンドスケジュールは指数を将来に投影し、スケジュールの更新はクリティカルパスを再計算し、モンテカルロ・シミュレーションとベロシティの幅は不確実性の尺度を加えます。以下のセクションでは、それぞれを数値で説明します。

アーンドバリューによるコストの予測

アーンドバリューマネジメント （EVM）は、コスト予測に最も広く使われている定量的な手法です。各ステータス日に、計画価値（PV）、アーンドバリュー（EV）、実コスト（AC）の3つの数値を比較し、次を導き出します： コスト効率指数 （CPI = EV / AC）と、スケジュール効率指数（SPI = EV / PV）。

計算式前提条件使う場面
EAC = BAC / CPI現在のコスト効率が続く超過の原因が残作業に影響する
EAC = AC + (BAC - EV)残作業は当初の予算どおりに進む差異は一時的なもので、原因は解消されている
EAC = AC + (BAC - EV) / (CPI x SPI)コストとスケジュールの両方のパフォーマンスが残作業に影響する遅れているが、固定された終了日を守らなければならない
EAC = AC + ボトムアップのETC当初の見積りがもはや当てはまらないスコープ、単価、アプローチが変わった
ETC = EAC - AC残作業のコスト
VAC = BAC - EAC予想される超過（マイナス）または未消化
TCPI = (BAC - EV) / (BAC - AC)予算内で完了するために残りの作業で必要な効率

実例：最終コストの予測

あるソフトウェア導入の予算（BAC）は$200,000、計画期間は8か月です。4か月目末の数値は次のとおりです： PV = $80,000、EV = $70,000、AC = $85,000。したがってCPI = 70,000 / 85,000 = 0.824 、SPI = 70,000 / 80,000 = 0.875。プロジェクトは予算を超過し、スケジュールも遅れています。

予測計算EACVAC
EAC（CPIが続く場合）200,000 / 0.824$242,857-$42,857
EAC（一時的な差異）85,000 + (200,000 - 70,000)$215,000-$15,000
EAC（CPI x SPI）85,000 + 130,000 / (0.824 x 0.875)$265,408-$65,408
EAC（ボトムアップ）85,000 + チームのETC $150,000$235,000-$35,000

計算式から得られる幅は約$215,000～$265,000です。数値を選ぶために、プロジェクトマネージャーは超過がなぜ起きたかを問います。この例では、チームは統合作業が見積りより難しく、それが残りのインターフェースにも影響すると判断したため、一時的な差異の計算式は楽観的すぎます。チームのボトムアップの再見積り（$235,000）はCPIに基づく数値（$242,857）に近く、確信を与えます。スポンサーに報告する予測は $235,000～$245,000、最も可能性が高いのは約$240,000、ETCは約$155,000です。

完了時必要効率指数は現実性のチェックになります：TCPI = (200,000 - 70,000) / (200,000 - 85,000) = 1.13。予算内で完了するには、チームは今後、1ドルの支出ごとに$1.13の価値を提供しなければなりませんが、これまでの実績は$0.82です。この差は頑張って働くことで埋められるものではないため、スポンサーは追加資金とスコープの縮小のどちらかを選ばなければなりません。各計算式について詳しくは、当サイトの次のガイドをご覧ください： 完成時総コスト見積り（EAC）.

完了日の予測

コストの計算式は日付について直接何も教えてくれません。完了を予測する一般的な方法は3つあり、少なくとも2つを使いましょう。

1. スケジュールとクリティカルパスを更新する

進行中の各タスクの実際の開始日・終了日と残りの所要期間を入力し、スケジューリングツールに再計算させます。新しい完了日は、更新された次から導かれます： クリティカルパス（どのタスクが実際に終了日を左右しているかを示す）。最も直接的な手法で、ほとんどのスポンサーが理解できるものです。弱点は、正直な残り所要期間に依存することで、理想的には次から得たものです： 三点見積り.

2. SPIを使って計画期間を補正する

簡易チェックは、予測期間 ＝ 計画期間 ÷ SPIです。例では、8 / 0.875 = 9.1か月。シンプルですが、既知の欠点があります。SPIは金額で計算されるため、プロジェクトが完了に近づくにつれて常に1.0に戻っていきます。プロジェクトが何か月遅れていても、最終的にはすべての計画価値が獲得されるからです。プロジェクトの終盤には役に立たなくなります。

3. アーンドスケジュールを使う

アーンドスケジュール （ES）は、2003年にWalt Lipkeが開発しKym Hendersonが拡張したもので、スケジュールのパフォーマンスを金額ではなく時間で測定することでその欠点を補います。ESは、ベースラインによれば現在のEVを獲得している*はずだった*時点です。主な計算式は次のとおりです：

  • ES = C + (EV - Cの時点のPV) / (C+1の時点のPV - Cの時点のPV)。CはPVがEV以下である最後の完全な期間です。
  • SPI(t) = ES / AT（ATは実際の経過時間）。
  • SV(t) = ES - AT（時間単位でのスケジュール差異）。
  • 予測期間（IEAC(t)） = 計画期間 / SPI(t)。

例の続きとして、月ごとの累積計画価値を以下に示します。

月12345678
累積PV（千ドル）10285080112145175200
  1. 4か月目のEVは$70,000です。計画価値は3か月目末に$50,000を超え、4か月目末に$80,000に達したので、C = 3です。
  2. ES = 3 + (70,000 - 50,000) / (80,000 - 50,000) = 3 + 0.67 = 3.67か月.
  3. SPI(t) = 3.67 / 4 = 0.917、SV(t) = 3.67 - 4 = -0.33か月 （約1週間半の遅れ）。
  4. 予測期間 = 8 / 0.917 = 8.7か月.

つまり、日付の予測は8.7か月（アーンドスケジュール）から9.1か月（単純なSPI）の幅になります。プロジェクトマネージャーはその後クリティカルパスを確認します。遅れている統合のタスクがクリティカルパス上にあれば遅いほうの数値がより現実的で、フロートがあれば早いほうの数値の可能性もあります。報告する予測は、次の完了日です： （9か月目の半ばから10か月目の初めの間）を、コストの幅と併せて示します。

ヒント

アーンドスケジュールは、まだすべてのスケジューリングツールに標準搭載されているわけではありませんが、時間軸に沿ったベースラインからスプレッドシートで簡単に計算できます。これは次を描くのに使うのと同じデータです： Sカーブ.

モンテカルロ・シミュレーションによる確率的な予測

モンテカルロ・シミュレーション は不確実性を見えるようにします。残りの各タスクに1つの期間やコストを入れる代わりに、幅（楽観値、最可能値、悲観値）と、主要なリスクの発生確率と影響度を入力します。ソフトウェアは各幅からランダムな値を選んでスケジュールとコストを何千回も再計算し、結果の分布をグラフにします。

アウトプットは次の一式です： 確信度（P値とも呼ばれる）。P50は、その日付またはコスト以内に完了する確率が50%であることを、P80は80%であることを意味します。次の表は、例のプロジェクトの残作業についての例示的な結果を示しています。

信頼水準予測される完了（例示）予測される最終コスト（例示）
P108.6か月$226,000
P509.1か月$239,000
P809.6か月$251,000
P909.9か月$258,000

読み方：最も可能性の高い結果は決定論的な予測に近いものの、スポンサーが80%の確実性を求めるなら、9.6か月と約$251,000で計画すべきです。P50とP80の差は、スケジュールとコストのコンティンジェンシーの根拠ある基準になります。また、どのタスクとリスクがばらつきに最も影響しているかもわかります。

モンテカルロの精度は入力する幅次第です。幅が狭すぎると（よくあることです）、結果は精密に見えても間違っています。可能な限り過去のデータを使い、モデルを次に結び付けます： リスク登録簿 。既知のリスクを明示的にモデル化するためです。

アジャイルプロジェクトにおける予測

アジャイルチームは通常、イテレーションごとに時間とコストを固定し、ある日付までにどれだけのスコープを提供できるか、または特定のスコープがいつ完了するかを予測します。インプットは残りのバックログとチームの直近の提供ペースです： ベロシティ （ストーリーポイントまたは スループット （週あたりのアイテム数）。

あるスクラムチームのリリースバックログには240ストーリーポイントが残っており、2週間のスプリントで作業しています。直近6スプリントのベロシティは28、32、25、30、35、30ポイント（平均30）でした。

フローベースのチームにはスループットとモンテカルロ

かんばんチームは、代わりにスループットから予測することがよくあります。シンプルなモンテカルロのアプローチでは、チームの実際の週ごとのスループット履歴からサンプリングして何千もの将来をシミュレーションし、「これら60アイテムを11週間以内に完了できる確率は85%」のような記述を導き出します。アイテムの見積りは不要で、完了した作業のある程度の履歴があれば十分です。

資源とベネフィットの予測

資源の予測 は、残りの作業にどのような人、スキル、設備がいつ必要になるかを予測します。更新されたスケジュールとETCから始め、残りの工数を役割ごとに月別の時間またはFTEに変換し、利用可能な量と比較します。差を見れば、どこで採用、借用、作業順序の変更が必要かがわかります。参考： キャパシティプランニング.

ベネフィットの予測 は、プロジェクトがビジネスケースの価値をまだ提供できるかを問います。完了が遅れればベネフィットも遅れ、超過すればリターンが減り、スコープを削ればベネフィットが完全に失われることもあります。各フェーズゲートで見直しましょう。

プロジェクトの予測を作成する手順

  1. ステータス日を設定する。 進捗、コスト、リスクに同じ締め日を使い、数値の整合性を保ちます。
  2. データを確認する。 実コストに、完了した作業の未払計上額と契約済みコストが含まれていること、そして進捗が楽観的な割合ではなく合意したルールで測定されていることを確認します。
  3. 指標を計算します。 CPI、SPI、SPI(t)と、計算式に基づくEACと期間を算出します。スプレッドシートなら数分で済みます。
  4. スケジュールを更新する。 実績と残りの所要期間を入力し、クリティカルパスを再計算します。
  5. 残作業を再見積りする。 変更されたワークパッケージや計画と異なるパフォーマンスを示しているワークパッケージについて、作業を行う人々にボトムアップのETCを依頼します。
  6. リスクと変更を追加する。 未解決のリスクの期待コスト、残りのコンティンジェンシー、承認済みの変更、承認される可能性の高い変更要求を含めます。
  7. 比較して選ぶ。 計算式の結果、スケジュールの更新、ボトムアップ見積りを並べ、どれが最も信頼できるかを判断し、その理由を説明します。
  8. 幅で表す。 最も可能性の高い値と幅を示し、シミュレーションを実施した場合は確信度も添えます。
  9. 報告し、行動する。 予測、その要因、それを改善するための選択肢を提示し、後で実際の結果と比較できるよう予測を記録しておきます。

ステップ1～4は大部分を自動化でき、その分ステップ5～9の判断に時間を使えます。そこで予測が信頼できるものになります。

予測の提示方法

予測は、スポンサーがそれを理解し行動できる場合にのみ役立ちます。次の中の明確な予測のセクション： プロジェクト状況報告書 には通常次が含まれます：

  • 要点： ベースラインと比較した、最も可能性の高い最終コストと完了日。
  • 幅と確信度： 。たとえば「$235,000～$245,000。完了は9か月目の半ばから10か月目の初め」。
  • 前回報告からの変化： 何が動き、なぜ動いたか。
  • 要因： 差異の主な原因2～3点。
  • 選択肢： 結果を改善するアクションと、そのコストと効果（スコープの縮小、人員の追加、コンティンジェンシーの使用など）。
  • 必要な意思決定： スポンサーに何をいつまでに決めてほしいか。

閾値を事前に合意します。たとえば、EACがBACを5%超えた場合や、予測完了日が主要なマイルストーンを過ぎる場合にエスカレーションする、といったものです。そうすれば、予測の悪化が議論ではなく意思決定の引き金になります。当サイトの コンティンジェンシー計画 ガイドでは、予測で必要性が示されたときに予備を設定し使用する方法を説明しています。

プロジェクトの予測はどのくらい正確ですか？

コストのより多くの部分が見積りではなく実績になるため、予測はプロジェクトが進むにつれて正確になります。アーンドバリューによる予測がどれくらい早く安定するかについては、いくつかの研究の裏付けがあります。米国国防総省の155件の契約を対象とした1993年の研究で、David ChristensenとScott Heiseは、契約の進捗が50%を超えると累積CPIの変動は10%以内にとどまることを発見しました。その後、HendersonとZwikaelによるパフォーマンスの安定性に関する研究などで、これが他の種類のプロジェクトにどこまで当てはまるかが疑問視されているため、ルールではなく有用な目安として扱ってください。

実務上の教訓：中間時点で予算を超過しているプロジェクトは、残作業の進め方を具体的に変えない限り、回復することはめったにありません。

自分の予測の精度を追跡する

各期間の最終コストと完了日の予測を記録し、終結時に実際の結果と比較します。予測EACの推移を示すシンプルなグラフを見れば、予測が安定していたか、着実に上昇していたか（楽観の兆候）、終盤に急変したか（問題が隠されていた兆候）がわかります。その発見を次にまとめます： 教訓 。次のプロジェクトの見積りと予測が改善されます。

予測でよくある間違い

  • スポンサーが聞きたいことを予測すること。 政治的な圧力は、正直な予測に対する最大の脅威です。
  • プロジェクトが回復すると想定する アプローチの変更や資源の追加といった具体的な理由がないのに。
  • 最も楽観的な計算式を既定で使う。 AC + (BAC - EV)は予算超過時に最も小さい数値になりますが、問題が解消されたことを前提としています。
  • 日付抜きでコストを、またはコスト抜きで日付を予測する。 遅れたプロジェクトは、ほぼ必ずより多くのコストがかかります。
  • 契約済みコストと未払計上額を無視する、 その結果、プロジェクトが実際より安く見えてしまいます。
  • 水増しされた進捗に頼る。 タスクが何週間も90%完了のままだと、EVは過大に表示され、すべての予測が楽観的になりすぎます。
  • プロジェクトの終盤に単純なSPIを使う、 （実際の遅れにかかわらず1.0に近づいていく場合）。アーンドスケジュールかクリティカルパスを使います。
  • 単一の精密な数値を報告する （$242,857など）。誤った確実性を暗示してしまいます。
  • 更新の頻度が低すぎる、 その結果、終盤に予測が急変します。
  • リスクと保留中の変更を除外する （チームの全員が知っているもの）。

予測のためのツールとテンプレート

ほとんどのプロジェクトでは、アーンドバリューとアーンドスケジュールによる予測にはスプレッドシートで十分です。必要なのは、時間軸に沿ったベースライン、実コスト、ワークパッケージごとの進捗、そしていくつかの数式です。当サイトの無料の 予算テンプレート は予算を実績と予測に対して追跡し、 リリース計画テンプレート は、アジャイルチームのベロシティに基づくリリース予測に対応しています。ETCの基になる見積りには、次を使います： プロジェクトコスト見積りテンプレート.

スケジューリングツールは予測完了日を自動的に更新し、モンテカルロ分析はリスク分析のアドインやスプレッドシートのシミュレーションで実行できます。当サイトの次の比較： プロジェクト管理ツール では、どのプラットフォームがガントチャート、ワークロード、レポート機能を備えているかを示しています。

よくある質問

プロジェクトの予測とは何ですか？

これまでのパフォーマンスと残りの作業から、プロジェクトの最終コスト、完了日、資源の必要量などの結果を予測し、提供期間を通じてその見通しを更新すること。

プロジェクトの予測の主な手法は何ですか？

専門家の判断とボトムアップでの再見積り、参照クラス予測法、アーンドバリューの計算式、アーンドスケジュール、クリティカルパスの更新、三点見積り、モンテカルロ・シミュレーション、そしてアジャイルチームではベロシティやスループットによる予測。

プロジェクトの最終コストはどのように予測しますか？

EAC = BAC / CPIなどのアーンドバリューの計算式で完成時総コスト見積りを算出し、残作業のボトムアップ見積りに未解決のリスクと保留中の変更を加えたものとクロスチェックします。

プロジェクトの完了日はどのように予測しますか？

実際の進捗でスケジュールとクリティカルパスを更新し、アーンドスケジュールでクロスチェックします：予測期間 ＝ 計画期間 ÷ SPI(t)。

予測と見積りの違いは何ですか？

見積りは作業開始前に、スコープと前提条件から作成されます。予測は提供中に、実際のパフォーマンスを使って見通しを更新します。

予測と予算の違いは何ですか？

予算は承認された金額で、変更管理を通じてのみ変わります。予測は最終コストについての現時点で最善の見通しで、期間ごとに変わりえます。

プロジェクトの予測におけるETCとは何ですか？

残作業見積り：残りの作業の予想コスト。ETC = EAC - AC、または残作業の新たなボトムアップ見積り。

アーンドスケジュールとは何ですか？

Walt Lipkeが開発した、スケジュールのパフォーマンスを金額ではなく時間で測定する手法。SPI(t) = ES / ATと、計画期間 ÷ SPI(t)による予測期間が得られ、プロジェクトの終盤でも信頼性が保たれます。

モンテカルロ法によるプロジェクトの予測とは何ですか？

各見積りとリスクの幅を使ってスケジュールとコストを何千回も再計算し、ある日付までに、あるいはあるコスト以内に完了する確率（P50やP80など）を示すシミュレーション。

アジャイルチームはどのように予測しますか？

残りのバックログを直近のベロシティやスループットの幅で割って日付の幅を出し、イテレーションごとにバーンアップチャートで更新します。

プロジェクトの予測はどのくらいの頻度で更新すべきですか？

各報告期間（多くの場合毎月またはスプリントごと）、そして重大な変更、課題、リスクが生じたときです。

なぜ予測は単一の数値ではなく幅で示すべきなのですか？

将来は不確実だからです。確信度を伴う幅のほうが正直であり、スポンサーが妥当なコンティンジェンシーを設定するのにも役立ちます。

アーンドバリューによる予測はいつ信頼できますか？

プロジェクトが進むにつれて信頼性が高まります。ChristensenとHeiseによる1993年の米国防衛契約の研究では、契約の進捗が50%を超えると累積CPIの変動は10%以内にとどまることがわかりましたが、その後の研究では、それがどこまで一般に当てはまるかが疑問視されています。
