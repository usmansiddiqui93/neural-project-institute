プロジェクトのタスクとアクティビティ：定義、例、コツ

プロジェクトマネジメントにおけるアクティビティとは、所要期間、資源、明確なアウトプットを持つ、スケジュールに組み込まれた個別の作業です。タスクも同じ意味で使われることが多いですが、区別する場合は、タスクはアクティビティを構成するより小さなステップを指します。

執筆Neural Project Instituteプロジェクトマネジメント編集チーム
  • 公開日 2026年9月23日
  • 3分で読めます

要点

  • アクティビティは、ワークパッケージから導き出される、スケジュールに組み込まれた作業の単位です。
  • 「動詞＋名詞」で名前を付け、明確な完了基準を設けましょう。
  • 先行アクティビティ、所要期間、資源、担当者などの属性を記録しましょう。
  • 見積もりと追跡ができる程度に小さく保ちましょう。

記録すべきアクティビティの属性

  • 一意のIDと、「決済ページをテストする」のように動詞で始まる名前。
  • 説明と完了基準。
  • 先行アクティビティと後続アクティビティ。参考： 先行アクティビティと後続アクティビティ.
  • 所要期間の見積りとその根拠。
  • 資源と担当者。
  • サプライヤーからの固定の納期などの制約条件。
  • コストと進捗が正しく集計されるよう、関連するWBSコード。

アクティビティの定義方法

  1. WBSの各ワークパッケージから始める。
  2. 作業を行う人たちに、それを生み出すためにどのようなステップが必要かを尋ねる。
  3. 各アクティビティは、明確な終了点を持つ「動詞＋名詞」の形で記述しましょう。
  4. 8/80ルール（工数8〜80時間）の目安を当てはめるなどして、それぞれ見積もりと追跡ができる大きさにする。
  5. 重要な出来事にはマイルストーンを追加する。参考： マイルストーン.
  6. アクティビティリストと属性を記録し、順序付けに進む。参考： タスクの依存関係.

アクティビティリストの例

ワークパッケージ「研修資料」の場合：

IDアクティビティ所要期間先行担当者
T1研修の目的に合意する2日-研修リーダー
T2コース概要の草案を作成する3日T1インストラクショナルデザイナー
T3スライドと配布資料を作成する8日T2インストラクショナルデザイナー
T4資料をレビューする3日T3テーマの専門家
T5最終化して印刷する2日T4研修リーダー

T1からT5までのチェーンは、2 + 3 + 8 + 3 + 2 = 18稼働日かかります。

よくある間違い

  • 「継続的なサポート」のように、明確な終わりのないアクティビティ。
  • 工数と所要期間を混同すること。担当者がパートタイムで取り組む場合、40時間の工数に10日かかることもあります。参考： 工数見積り.
  • 大きすぎて、終わるまで進捗を判断できないアクティビティ。
  • レビュー、承認、調達のリードタイムなど、構築以外の作業を忘れること。
ヒント

アクティビティが完了したかどうか判断できない場合は、より良い完了基準が必要か、より小さく分割する必要があります。

よくある質問

プロジェクトのタスクとアクティビティの違いは何ですか？

多くの人は区別せずに使っています。区別する場合、アクティビティはスケジュールに組み込まれた作業の単位で、タスクはその中のより小さなステップです。

プロジェクトのアクティビティリストとは何ですか？

スケジュールに組み込むすべてのアクティビティを、ID、名前、スコープの説明とともに一覧にしたもので、スケジュールの作成に使います。

プロジェクトのアクティビティはどのくらいの大きさにすべきですか？

確実に見積もり、追跡できる程度の小ささです。一般的な目安は工数8〜80時間、または1報告期間以内です。

プロジェクトのアクティビティとワークパッケージの違いは何ですか？

ワークパッケージはWBSの最下位レベルでアウトプットを表し、アクティビティはそれを生み出すために必要な作業です。参考： ワークパッケージ.

プロジェクトのアクティビティの属性とは何ですか？

ID、説明、先行アクティビティ、所要期間、資源、制約条件、担当者など、各アクティビティについて記録する詳細情報です。

プロジェクトのタスクにはどのように名前を付けますか？

「予算を承認する」「サーバーを設置する」のように、動詞で始めて結果を示しましょう。

プロジェクトのタスク一覧におけるサマリータスクとは何ですか？

サブタスクをまとめる親タスクで、日付はサブタスクから集計されます。 ハンモック活動 も関連する考え方です。

プロジェクトの繰り返しタスクとは何ですか？

週次のステータス会議など、スケジュールに沿って繰り返されるタスクです。

会議はプロジェクトのタスクに含めるべきですか？

他の作業が依存する主要なレビューや意思決定の会議は含めましょう。定例の会議は通常、間接作業として扱います。

アジャイルでもプロジェクトのタスクは同じですか？

アジャイルチームは通常、スプリントプランニングの際に ユーザーストーリー をタスクに分解します。参考： エピック、ストーリー、タスクの違い.
