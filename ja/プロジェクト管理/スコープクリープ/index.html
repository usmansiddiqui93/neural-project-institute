スコープクリープ：原因、例、防止策

スコープクリープとは、時間、コスト、資源を相応に調整しないまま、プロジェクトのスコープが無秩序に拡大することです。プロジェクトが遅延や予算超過に陥る最も一般的な原因の1つです。

執筆Neural Project Instituteプロジェクトマネジメント編集チーム
  • 公開日 2026年9月16日
  • 3分で読めます

要点

  • スコープクリープとは、スコープの無秩序な拡大です。
  • 明確な対象外事項と変更管理によって防止できます。
  • 新しい依頼については、必ず時間とコストへの影響を示しましょう。

よくある原因

  • 曖昧または不完全な要求事項。
  • 正式な変更管理プロセスがない。
  • ステークホルダーがチームに直接依頼を追加する。
  • チームによるゴールドプレーティング。
  • 対象外事項が十分に伝わっていない。
  • トレードオフの判断に関与しないスポンサー。

例

  • あるウェブサイトのプロジェクトで、期限を延ばさないまま、ブログ、チャットボット、多言語対応が少しずつ追加されていく。
  • オフィス移転のプロジェクトが、追加予算なしで新しい家具やIT機器の刷新まで含むように拡大する。
  • 会議のたびに「あと1つだけ」と追加され、レポートのグラフが5つから20に増える。

警告サイン

  • 次に含まれていないタスクが現れる： WBS.
  • 依頼がメールやチャットで届き、プロジェクトマネージャーを経由しない。
  • スケジュールを変更しないまま、チームが残業している。
  • 成果物がいつまでも「ほぼ完了」のままである。

防止策

  1. 明確な スコープ記述書 を、対象外事項も含めて作成します。
  2. 正式な承認を得ます。
  3. 次を整備します： 変更管理：記録、評価、決定、更新。
  4. すべての変更について、時間とコストへの影響を示します。
  5. ステークホルダーとチームにプロセスを周知します。
  6. アジャイルプロジェクトでは、新しい依頼をバックログに回し、プロダクトオーナーが優先順位を付けられるようにしましょう。

よくある質問

スコープクリープとは何ですか？

時間、コスト、資源を相応に変更しないまま、プロジェクトのスコープが無秩序に拡大すること。

スコープの変更はすべてスコープクリープですか？

いいえ。価値をもたらす承認済みの変更は普通のことです。問題なのはコントロールされていない変更です。

ゴールドプレーティングはスコープクリープの一種ですか？

はい。ゴールドプレーティングとは、主にチームが求められていない機能を追加することで、スコープクリープの一種です。

スコープクリープの防止には誰が責任を負いますか？

プロジェクトマネージャーです。スポンサーと明確な変更プロセスがそれを支えます。

スコープクリープを防ぐために、ステークホルダーにどのように断ればよいですか？

時間とコストへの影響を説明し、選択肢を提示します：後回しにする、別の項目と入れ替える、または資源を追加して承認する。

アジャイルはスコープクリープを防げますか？

アジャイルはスコープが変化することを前提としていますが、固定期間のイテレーションの中でバックログの優先順位付けによってスコープをコントロールします。

変更要求はスコープクリープの防止にどう役立ちますか？

変更要求とは、スコープ、スケジュール、コスト、その他のベースラインを変更するための正式な提案です。これにより、変更がなし崩しに入り込むのではなく、評価と承認を経るようになります。

スコープクリープはどのように測定しますか？

現在のスコープをベースラインと比較し、未承認の変更の件数と影響を追跡します。

スコープクリープが良い結果をもたらすことはありますか？

計画外の改善が価値をもたらすこともありますが、その場合も変更管理を通すべきです。

スコープクリープのコントロールに役立つツールは何ですか？

スコープ記述書、WBS、変更ログ、そして承認ワークフローを備えたプロジェクト管理ソフトウェアです。
