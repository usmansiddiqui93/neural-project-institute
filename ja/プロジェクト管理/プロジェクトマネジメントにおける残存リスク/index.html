プロジェクトマネジメントにおける残存リスク：意味と例

プロジェクトマネジメントにおける残存リスクとは、リスク対応策を計画・実行した後に残るリスクです。リスクを完全に取り除ける対応策はほとんどないため、多くのプロジェクトは残存リスクを抱えており、それを測定し、適切な人が受容し、予備でカバーし、監視しなければなりません。本ガイドでは、計算例を交えて残存リスクの算出方法と、受容できるかどうかの判断方法を解説します。

要点

  • 残存リスクは対応策の後に残るもの、固有リスクは対応策を講じる前の水準です。
  • 二次リスクは対応策によって生じる新たなリスクであり、残存リスクとは異なります。
  • 残存リスクは、対応策の後に発生確率と影響度、または期待金額価値を再評価して算出します。
  • 残存リスクを合意した許容度と比較し、高すぎる場合は対応策を追加するかエスカレーションしましょう。
  • 重大な残存リスクは、スポンサーまたは役員会が明示的に受容し、リスク登録簿に記録すべきです。

残存リスクとは何ですか？

残存リスク とは、リスク対応策を実施した後に残るリスクの水準です。PMIのPMBOKガイドでは、残存リスクを、計画した対応策を講じた後も残ると予想されるリスクと説明しており、意図的に受容したリスクも含まれます。ISOのリスクマネジメント用語集（ISO Guide 73）では、より簡潔に、リスク対応後に残るリスクと定義しています。

平たく言えば、まず プロジェクトリスクから出発し、それに対して何をするかを決め、実行し、そして「今どの程度起こりやすく、起きたらどの程度深刻か？」と問います。その答えが残存リスクです。

  • 特定済みのリスクである。 存在がわかっているため、未知のリスクと違って計画を立てられます。
  • ゼロになることはまれである。 軽減は発生確率や影響度を下げ、転嫁は財務上の影響を移しますが、通常はどちらも事象そのものを完全には取り除きません。
  • 判断のポイントである。 残存リスクの水準がわかったら、それを受容できるかどうかを誰かが判断しなければなりません。
  • プロジェクト以外でも使われる。 情報セキュリティ、労働安全衛生、内部監査、全社的リスクマネジメントでも同じ考え方が使われています。

固有リスク、残存リスク、二次リスク

リスクマネジメントやPMP・CAPMの試験問題には、関連する4つの用語が登場します。下表では、1つのデータ移行リスクを例に、それぞれの違いを示します。

用語意味例
固有リスク対応策や管理策を講じる前のリスク移行中のデータ消失：発生確率3 x 影響度5 = 15
残存リスク対応策の後に残るリスクフルバックアップとリハーサルの後：発生確率1 x 影響度4 = 4
二次リスク対応策を実行したことで直接生じる新たなリスクリハーサルでテスト環境が占有され、他のテストが遅れる
創発的リスクプロジェクトが進むにつれて初めて見えてくるリスク実行中に新しいデータ規制が発表される

残存リスクと二次リスクの違い

どちらも対応策の後に現れるため、混同しやすい用語です。違いは発生源にあります：

  • 残存リスク は 同じリスクが、取り除かれずに低減されたものです。事象はまだ起こりえます。
  • 二次リスク は、対応策によって持ち込まれた 別のリスク です。次の中に独自の項目が必要です： リスク登録簿。スコアと責任者も独自に設定します。

例：スキル不足のリスクを減らすため、テストを専門会社に外部委託するとします。それでもテストが遅れる可能性はいくらか残ります（残存リスク）。また、外部委託によって、その会社が要求事項を誤解するという新たな可能性も生じます（二次リスク）。

ヒント

試験での近道：問題文が「残る」ものを問うていれば答えは残存リスク、「対応策から生じる」ものを問うていれば答えは二次リスクです。

残存リスクが重要な理由

対応策を計画すると、誤った安心感が生まれることがあります。残存リスクを測定すれば、リスクの全体像を正直に保てます。

  • 正直な報告。 スポンサーは、当初特定されたリスクだけでなく、チームが対策を講じた後にどれだけのリスクが残っているかを知る必要があります。
  • 適正規模の予備。 コンティンジェンシー予備は通常、残存リスクと受容したリスクの期待コストから規模を決めます。
  • 費用対効果。 固有リスクと残存リスクを比較すれば、対応策がそのコストに見合うかどうかがわかります。
  • 明確な説明責任。 残存リスクが記録され正式に受容されていれば、誰がそれを受け入れると決めたのかを全員が把握できます。
  • より良い集中。 残存スコアの高いリスクは議題に残り、低い水準まで下がったリスクは通常の監視に移せます。

各対応戦略が残存リスクに与える影響

選んだ対応策によって、何が残るかが決まります。以下はPMIが示す脅威への戦略と、残存リスクへの一般的な影響です。

戦略役割一般的な残存リスク
回避脅威が発生しえないように計画を変更する（例：リスクの高い機能を取りやめる）そのリスクについてはほぼゼロ。ただし変更から生じる新たなリスクを確認する
軽減発生確率、影響度、またはその両方を下げる固有リスクより低い。残存リスクの最も一般的な発生源
転嫁財務上の影響を第三者に移す（例：保険、固定価格契約）財務上の影響は下がるが、スケジュールや評判への影響は残る可能性があり、第三者が履行できないこともある
受容今は何もしない。場合によっては予備やコンティンジェンシー計画を用意する固有リスクと同じ
エスカレーションプロジェクトの権限外であるため、より上位のレベルに責任を移すプロジェクトの登録簿からは外れるが、組織は引き続きそのリスクを抱える

好機の場合は論理が逆になります。活用、強化、共有を行った後、便益がどの程度起こりやすくなり、どの程度大きくなるかを再評価します。

残存リスクの計算方法

公式の計算式は1つではありません。多くのプロジェクトは以下の3つの方法のいずれかを使っています。1つを選んで一貫して使い、尺度はリスクマネジメント計画書で定義しましょう。

方法1：発生確率と影響度を再評価する

最も簡単で一般的な方法であり、多くの登録簿で使われている発生確率 x 影響度のマトリックスと整合します。

  1. 固有リスクを評価する：発生確率（1～5）x 影響度（1～5）。
  2. 対応策を列挙し、現実的で、資金が確保され、責任者がいることを確認する。
  3. 対応策が計画どおりに機能すると仮定して、発生確率と影響度を再評価する。
  4. 掛け合わせて残存スコアを求める。

たとえば、固有の発生確率が4、影響度が4なら16です。軽減策で発生確率が2に下がり、影響度が4のままなら、残存スコアは8です。

方法2：期待金額価値

コストを見積れる場合は、残存リスクを金額で表します。 残存期待金額価値 = 残存発生確率 x 残存コスト影響。 £20,000の超過が10%の確率で起こるなら、残存エクスポージャーは£2,000です。これはコンティンジェンシー予備の規模の決定や、対応策とそのコストの比較に役立ちます。プロジェクト全体については、 モンテカルロ・シミュレーション によって多数の残存リスクを組み合わせ、結果の幅として示すことができます。

方法3：管理策の有効性

特にセキュリティや監査の分野では、管理策の有効性を見積り、それに応じて固有スコアを減らす組織もあります： 残存リスク = 固有リスク x (1 - 管理策の有効性)。固有スコアが15で、管理策の有効性が60%と判断されれば6になります。これはおおまかな目安として扱いましょう。有効性の割合は判断によるものであり、発生確率を下げる対応策が必ずしも影響度を下げるとは限りません。

ヒント

「残存リスク = 固有リスク - 管理策の効果」という略式の表現をよく目にします。考え方は表していますが、数値にするには上記のいずれかの方法が必要です。

計算例：建設プロジェクトの残存リスク

ある建設プロジェクトでは、鉄骨を組み立てるためにレンタルのタワークレーンに依存しています。故障すると、代替機が見つかるまで最大6週間作業が止まる可能性があります。

ステップ詳細度スコアまたは金額
固有リスク発生確率3（起こりうる）x 影響度5（非常に高い）15（高）
固有エクスポージャー30%の確率 x 6週間の遅れのコスト£120,000£36,000
対応策1レンタル会社による毎週の点検で発生確率を下げる発生確率2
対応策22社目のレンタル会社との待機契約で、遅れを3日以内に抑える影響度2
残存リスク発生確率2 x 影響度24（低）
残存エクスポージャー10%の確率 x 3日間の遅れのコスト£15,000£1,500
対応策のコスト点検費用と待機手数料£5,000
二次リスク待機契約先の会社に、急な依頼で空いているクレーンがない可能性がある別途記録、スコア3

対応策のコストは£5,000で、期待エクスポージャーを£34,500減らすため、明らかに実施する価値があります。残存スコア4はプロジェクトの許容度6の範囲内なので、プロジェクトマネージャーはこのリスクを残存水準で受容したものとして記録し、コンティンジェンシー予備として£1,500を確保し、点検報告の監視を続けます。

ここでの数値は説明用です。ご自身のプロジェクトでは、組織の尺度とコスト見積りを使ってください。

残存リスクのその他の例

プロジェクト固有リスク対応残るもの（残存リスク）
ITシステムの移行切り替え時にデータが破損するかもしれない（3 x 5 = 15）本番と同量のデータでのリハーサルと検証済みのバックアップロールバックで1日以内に復旧できる程度の破損がわずかな確率で起こる（1 x 3 = 3）
屋外イベント悪天候で来場者が減るかもしれない（3 x 4 = 12）大型テントのレンタルと中止保険来場者はやはり減るかもしれず、評判への影響は保険の対象外（3 x 2 = 6）
ソフトウェアリリースセキュリティ上の欠陥がリリースされるかもしれない（2 x 5 = 10）コードレビュー、自動スキャン、ペネトレーションテスト未知の欠陥が残る可能性がある（1 x 5 = 5）ため、監視とインシデント対応計画は維持する
サプライヤー契約サプライヤーの納品が遅れるかもしれない（4 x 3 = 12）違約金条項と毎週の進捗確認納品の遅れは起こりにくくなるが、違約金では失った時間は取り戻せない（2 x 3 = 6）
マーケティングのローンチ競合他社が先に発売するかもしれない（2 x 4 = 8）受容し、差別化したメッセージを用意するリスクを受容したため変化なし（2 x 4 = 8）

転嫁や違約金条項は、財務上の影響を減らしても、スケジュールや評判への影響は減らさないことが多い点に注意しましょう。残るものを正直に記録してください。

残存リスクを評価する手順

  1. 固有リスクを評価する （合意した発生確率と影響度の尺度を使用）。
  2. 対応策に合意する（各アクションに責任者、コスト、日付を設定）。
  3. 計画上の残存リスクを見積る：対応策が機能すると仮定して再評価します。これが目標です。
  4. 二次リスクを確認する （対応策によって生じたもの）。別途記録します。
  5. 許容度と比較する 。基準は次で設定したものです： プロジェクトマネジメント計画書.
  6. 判断する：受容する、対応策を追加する、またはエスカレーションする。
  7. 判断を記録する（誰がいつ残存リスクを受容したかを含む）。
  8. 対応策が完了したら再評価する ことで実際の残存リスクを求め、トリガーの監視を続けます。
ヒント

計画上の残存スコアと実際の残存スコアは分けて管理しましょう。計画しただけの対応策は、まだ何も減らしていません。

残存リスクは受容できるか？

残存リスクを受容できるかどうかの判断は判断の問題ですが、直感ではなく合意したルールに従うべきです。

  • 許容度と比較する。 リスクマネジメント計画書には、組織のリスク選好に基づき、プロジェクトで受容できるスコアとエスカレーションが必要なスコアを明記しておきます。
  • さらに低減するためのコストを比較検討する。 追加の対応策のコストが、それによって減るエクスポージャーより大きいなら、残存リスクを受容するのが賢明な場合が多いでしょう。 費用便益分析 がここで役立ちます。
  • 財務以外の影響を考慮する。 安全、法務、評判に関わるリスクは、金銭的な根拠が弱くても、さらに低減する必要がある場合があります。
  • 判断を見える形にする。 重大な残存リスクは、チームがひそかに受け入れるのではなく、プロジェクトの ガバナンス の仕組みを通じて、スポンサーまたはプロジェクト役員会が明示的に受容すべきです。

1～25のスコア尺度を使った、合意済みルールの例：

残存スコア区分一般的な対応
15-25高プロジェクトレベルでは受容不可。対応策を追加するか、スポンサーまたは役員会にエスカレーションする
8-14中スポンサーの同意、コンティンジェンシー計画、綿密な監視がある場合にのみ受容可
1-7低プロジェクトマネージャーが受容可。通常のレビュー頻度で監視する

これらの区分は当サイトの提案であり、標準ではありません。組織のリスク選好とプロジェクトの重要度に合わせて独自に設定しましょう。

残存リスクのマネジメント：コンティンジェンシー予備とフォールバック計画

受容した残存リスクにも計画が必要です。よく使われるツールが2つあります。

ツール内容使う場面
コンティンジェンシー計画リスクが発生した場合に取る行動リスク事象が発生したとき、またはトリガーに達したときに発動する
フォールバック計画コンティンジェンシー計画がうまくいかなかった場合の第二の行動1つの計画では不十分な、影響の大きいリスク向け
コンティンジェンシー予備残存リスクを含む、特定されたリスクのために確保する時間やお金期待値から規模を決め、リスクが発生したら取り崩す
マネジメント予備未知のリスクのための時間やお金で、ベースラインの外に保持する誰も特定していなかったリスクのために、ガバナンスを通じて解放する

コンティンジェンシー予備はコストの ベースライン 内にあり、次の一部です： プロジェクト予算。受容したリスクの残存期待値を合計すれば、その規模について説明可能な出発点が得られます。

残存リスクが実際に発生した場合、それは課題になります。次に移しましょう： 課題ログ。そのうえでコンティンジェンシー計画を実行し、予算やスケジュールが変わる場合は次を経ます： 変更管理.

リスク登録簿への残存リスクの記録

スコアが1つしか表示されない登録簿では、対応策の効果が見えません。列を追加して、対応前と対応後の状況が明確にわかるようにしましょう。

列記録する内容
固有の発生確率、影響度、スコア対応策を講じる前の評価
対応戦略と対応策回避、軽減、転嫁、受容、エスカレーション（日付と責任者付き）
計画上の残存スコア対応策が完了した時点で予想されるスコア

スポンサーへの残存リスクの報告

スポンサーや役員会がすべてのリスクを知る必要はありませんが、プロジェクトがどれだけのリスクを抱えているかは知る必要があります。

  • 上位のリスクについて固有スコアと残存スコアを並べて示し、対応策の効果が見えるようにする。
  • 許容度を超えている残存リスクと、スポンサーに求める判断を強調する。
  • 残りのコンティンジェンシー予備を、それがカバーすべき残存エクスポージャーと対比して報告する。
  • 残存リスクを定期的な プロジェクト状況報告書 やステージゲートのレビューに含める。

小規模なプロジェクトでは、 RAIDログ でリスク、前提条件、課題、依存関係を1か所にまとめて管理できます。詳しくは RAIDログテンプレート.

残存リスクに関するよくある間違い

  • 対応策でリスクがなくなると思い込むこと。 回避した場合を除き、たいていは何かが残ります。
  • 早すぎる再評価。 対応策が実施済みではなく計画段階のときにスコアを下げると、進捗を過大に見せることになります。
  • 二次リスクを無視すること。 どの対応策も新たなリスクを生む可能性があります。毎回確認しましょう。
  • 転嫁を除去とみなすこと。 保険や契約で移せるのはお金であり、時間、評判、安全ではありません。
  • スポンサーに知らせないこと。 チームが黙って受け入れた残存リスクは、正しく受容されたとは言えません。
  • 予備がないこと。 コンティンジェンシーの時間やお金なしに残存リスクを受容すると、発生したときにすべて予算やスケジュールの問題になります。
  • 見直さないこと。 状況は変化します。リスクレビューとステージゲートのたびに残存リスクのスコアを見直しましょう。

残存リスクは、リスクの特定、分析、対応、監視という、より広いプロセスの一部です。

よくある質問

プロジェクトマネジメントにおける残存リスクとは何ですか？

リスク対応策を計画・実行した後に残るリスクです。以前と同じリスクですが、発生確率や影響度が低下した（受容した場合は変わらない）水準にあります。

残存リスクの例を教えてください。

あるチームが、データ移行の前に本番さながらのリハーサルを行い、バックアップを取得します。これでデータ破損の可能性は大幅に下がりますが、わずかな可能性は残ります。その残る可能性とその影響が残存リスクです。

残存リスクはどのように算出しますか？

対応策が実施されていると仮定して発生確率と影響度を再評価して掛け合わせるか、低下した発生確率とコストへの影響を使って期待金額価値を算出します。組織によっては、固有リスクのスコアを推定した管理策の有効性の分だけ下げる方法を使います。

残存リスクの計算式は何ですか？

よく使われる簡略式は、残存リスク = 固有リスク − 対応策または管理策の効果です。実務では、残存発生確率 × 残存影響度、または固有リスク ×（1 − 管理策の有効性）として計算します。

固有リスクと残存リスクの違いは何ですか？

固有リスクは対応策や管理策を講じる前のリスクの水準で、残存リスクは対応策の後に残る水準です。

残存リスクと二次リスクの違いは何ですか？

残存リスクは、対応策の後に元のリスクのうち残るものです。二次リスクは、対応策の実行から直接生じる、新たな別のリスクです。

残存リスクをゼロにすることはできますか？

まれです。リスクを完全に回避する場合（原因となる活動を取りやめるなど）にのみ、そのリスクはゼロに近づきます。それでも、その変更によって新たなリスクが生じることがあります。

プロジェクトで残存リスクを受容するのは誰ですか？

低い残存リスクは通常プロジェクトマネージャーが受容できます。重大なものは、プロジェクトのガバナンスと許容度に従って、スポンサーまたはプロジェクト委員会が受容すべきです。

受容可能な残存リスクの水準とはどの程度ですか？

リスクマネジメント計画で合意した許容度の範囲内に収まり、組織のリスク選好を反映した水準です。何が受容可能かは、組織や影響の種類によって異なり、特に安全や法務に関するリスクでは大きく異なります。

残存リスクはどこに記録しますか？

リスク登録簿に記録します。通常は固有リスクのスコアの隣にある残存スコアの列に、受容した人の名前と日付とともに記載します。

残存リスクが高すぎる場合はどうすればよいですか？

対応策を追加する、リスクを回避するよう計画を変更する、影響をさらに転嫁する、上位レベルにエスカレーションする、あるいは極端な場合はプロジェクトを進めないと判断します。

残存リスクは財務的にどのようにカバーされますか？

通常はコンティンジェンシー予備でカバーします。この予備は、残存リスクや受容したリスクを含む、特定済みリスクの期待コストから算定されます。未知のリスクはマネジメント予備でカバーします。

フォールバック計画とは何ですか？

あるリスクのコンティンジェンシー計画がうまくいかなかった場合に使う、2つ目の行動計画です。フォールバック計画は、影響度の高い残存リスクに対して用意されることがよくあります。

残存リスクはプロジェクトマネジメント以外でも使われますか？

はい。情報セキュリティ、内部監査、安全衛生、全社的リスクマネジメントで標準的な概念であり、多くの場合リスク対応後に残るリスクと定義されています。
