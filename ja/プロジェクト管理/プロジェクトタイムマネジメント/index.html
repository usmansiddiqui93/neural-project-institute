プロジェクトマネジメントガイド · スケジューリングと時間

プロジェクトタイムマネジメント：プロセス、技法、コツ

プロジェクトのタイムマネジメントとは、プロジェクトが期限内に完了するようにするための一連のプロセスです。スケジュールの管理方法を計画し、アクティビティを定義して順序付け、所要期間を見積もり、スケジュールを作成してコントロールします。PMBOKガイドの最近の版では、この領域をスケジュールマネジメントと呼んでいます。

要点

  • プロジェクトのタイム（スケジュール）マネジメントは、スケジュールの計画、作成、コントロールを扱います。
  • 従来の6つのプロセスは、アプローチの計画からスケジュールのコントロールまでを扱います。
  • スケジュールの健全性は、アーンドバリューとクリティカルパスを併せて判断しましょう。
  • 個人の良い時間管理の習慣は、プロジェクトマネージャーがスケジュールを把握し続けるのに役立ちます。

スケジュール・マネジメントのプロセス

PMBOKガイド第6版では、プロジェクト・タイム・マネジメントをプロジェクト・スケジュール・マネジメントに改称し、6つのプロセスとして説明しています：

プロセス行うこと主なアウトプット
スケジュール・マネジメントの計画手法、ツール、単位、ルールを決めるスケジュール・マネジメント計画
アクティビティの定義ワークパッケージをアクティビティに分解するアクティビティリスト と マイルストーン
アクティビティの順序設定特定する 依存関係ネットワーク図
アクティビティ所要期間の見積り各アクティビティの作業時間を見積もる所要期間の見積り
スケジュールの作成日付、クリティカルパス、資源の適合性を算出するスケジュールベースライン
スケジュールのコントロール進捗を追跡し、変更を管理する予測と変更要求

第7版は原則に基づくアプローチをとり、パフォーマンス領域の中でスケジューリングを扱っていますが、これらのステップは今もスケジュールを作成する実践的な方法です。

主要な技法

  • 次からの分解： WBS（ワーク・ブレークダウン・ストラクチャー）.
  • 類推見積り、パラメトリック見積り、 三点見積り.
  • クリティカルパス法 と クリティカルチェーン.
  • 資源平準化 と資源円滑化。
  • スケジュール短縮：クラッシングとファストトラッキング。
  • ローリングウェーブ計画法：近い将来は詳細に、それ以降の作業は概要レベルにとどめます。
  • コントロールには、次のようなアーンドバリューの指標を使う： スケジュール差異 など。

計算例：スケジュールのコントロール

20週間のプロジェクトで、8週目の計画価値は$80,000、アーンドバリューは$68,000です。

  • スケジュール差異（SV）= EV - PV = $68,000 - $80,000 = -$12,000で、計画より完了した作業が少ないことを示します。
  • スケジュール効率指数（SPI）= EV / PV = 68,000 / 80,000 = 0.85。
  • 同じ実績のペースが続くと仮定すると、おおよその期間の予測は20 / 0.85 = 約23.5週です。
  • プロジェクトマネージャーは次を確認します： クリティカルパス：失われた作業がフロートのある非クリティカルなアクティビティ上であれば、完了日はまだ守れるかもしれません。

プロジェクトマネージャーのための個人の時間管理

  • 毎週、スケジュールの更新とリスクの見直しのための時間を確保しましょう。
  • 会議は明確なアジェンダと意思決定を伴う短いものにしましょう。
  • タスクレベルの追跡はチームリーダーに任せ、クリティカルパスに集中しましょう。
  • タスクはばらばらのリストではなく、1つのツールで管理しましょう。参考： プロジェクト管理ソフトウェア.
  • 計画やステークホルダー対応に集中できる時間を確保しましょう。
ヒント

SPIは作業が完了に近づくにつれて1.0に近づくため、プロジェクトの終盤ではSPIだけでは誤解を招くことがあります。クリティカルパスの日付も確認しましょう。

遅延のよくある原因

  • 不明確なスコープと終盤の要求事項の変更。参考： スコープクリープ.
  • コンティンジェンシーのない楽観的な見積り。
  • 共有資源が他の業務に引き抜かれる。
  • サプライヤーや承認の遅れ。
  • スケジュールが更新されず、問題の表面化が遅れる。

よくある質問

プロジェクトのタイムマネジメントとは何ですか？

プロジェクトが期限内に完了するよう、プロジェクトのタイミングを計画、スケジューリング、コントロールするためのプロセスです。

プロジェクトのタイムマネジメントとスケジュールマネジメントの違いは何ですか？

同じ領域を指しています。PMBOKガイド第6版で、プロジェクト・タイム・マネジメントはプロジェクト・スケジュール・マネジメントに名称が変更されました。

プロジェクトのタイムマネジメントのプロセスとは何ですか？

スケジュール・マネジメントの計画、アクティビティの定義、アクティビティの順序設定、所要期間の見積り、スケジュールの作成、スケジュールのコントロールです。

プロジェクトのタイムマネジメントに役立つツールは何ですか？

ガントチャート、ネットワーク図、スケジューリングソフトウェア、そしてアーンドバリューなどの進捗指標です。

プロジェクトのタイムマネジメントにおけるローリングウェーブ計画法とは何ですか？

近い将来の作業は詳細に計画し、それ以降の作業は概要レベルにとどめ、時期が近づくにつれて詳細を加えていく方法です。

プロジェクトのタイムマネジメントでは、スケジュールをどのようにコントロールしますか？

進捗を定期的に更新し、ベースラインと比較し、完了を予測し、差異には変更管理を通じて対処します。

プロジェクトのタイムマネジメントにおけるスケジュール差異とは何ですか？

アーンドバリューから計画価値を引いたものです。マイナスの値はプロジェクトが遅れていることを意味します。参考： スケジュール差異.

プロジェクトのタイムマネジメントを行っていても、プロジェクトが遅れるのはなぜですか？

よくある理由は、楽観的な見積り、スコープの変更、資源の競合、外部要因による遅延、不十分な追跡です。

プロジェクトのタイムマネジメントは、プロジェクトマネージャーの重要なスキルですか？

はい。プロジェクトのスケジューリングも自分自身の時間管理も、次の中核です： プロジェクトマネジメントスキル.

プロジェクトのタイムマネジメントをしっかり学ぶにはどこがよいですか？

スコープ、スケジュール、コストを扱う当サイトのBaselineコースでは、スケジューリングを詳しく学べます。次に必要な知識を身につけるうえでも役立ちます： プロジェクトマネジメント資格.
