What is a project plan?

A project plan is the document that sets out how a project will reach its goal: the deliverables, the tasks needed to produce them, who owns each task, when each task starts and finishes, how tasks depend on each other and the milestones that mark progress. It is the shared reference the team, sponsor and stakeholders use to agree and track the work.

The term is used in two ways. In everyday practice it means the working plan of tasks, owners and dates, which is what this template gives you. The PMBOK Guide uses project management plan for a broader document describing how the project will be executed, monitored and controlled, and closed, bringing together subsidiary plans for scope, schedule, cost, risk, communications and more. For small and medium projects, this template plus a few supporting documents is usually enough; on large projects it becomes the schedule and summary inside the fuller plan.

What should a project plan include?

Most planning guidance agrees on the same core components. The template covers each one:

  • Goal and scope, including what is out of scope (Overview tab). Clear exclusions are your best defence against scope creep.
  • Deliverables and tasks, grouped into phases (Overview and Project plan tabs).
  • One owner per task, so work cannot fall between people.
  • Dates, durations and dependencies, which show when work happens and which delays move the end date.
  • Milestones the sponsor can track.
  • Budget, key risks and success criteria (Overview tab).
  • Status, which turns the plan into a tracking tool.

Keep detailed supporting documents separate and link to them from the plan: the full risk register, a RACI matrix and a communication plan.

How to create a project plan step by step

  1. Agree the goal with the sponsor. Confirm why the project exists, what success looks like, the budget and fixed dates. If there is a signed project charter, start from it: the plan must stay within what it authorised.
  2. Complete the Overview tab. Write a SMART goal, list in-scope and out-of-scope items, name three to seven deliverables, and record budget, top risks and success criteria. Any row you cannot fill is a question for the sponsor.
  3. Break deliverables into tasks. Use a work breakdown structure to split each deliverable into work small enough to estimate. Group rows into phases and number them 1.1, 1.2, 2.1.
  4. Assign one owner per task. If you cannot name one, the task is too vague or nobody has agreed to do it.
  5. Estimate and enter dates. Ask each owner how long the work will take; the duration calculates itself. For uncertain work, see effort estimation techniques such as three-point estimates.
  6. Link the dependencies. Enter predecessor IDs in Depends on, then check every start date falls after the end of the tasks it depends on. The template records dependencies as text and does not move dates for you. See task dependencies.
  7. Mark the milestones. Set Milestone? to Yes for approvals, go-live and handover. Read more on project milestones.
  8. Review and baseline. Walk the team through the plan to test estimates, agree it with the sponsor, then save a copy as your baseline.
  9. Update weekly. Change status, forecast new dates for slipping work and report on milestones.

How detailed should a project plan be?

Plan at the level you can keep current. For a project of a few months, tasks of one to two weeks usually work: small enough that slippage shows quickly, large enough that the plan does not become a to-do list. Detail the next phase fully and keep later phases as summary rows until you approach them (often called rolling wave planning). Split any task longer than a month into deliverables someone can check.

What the example shows

  • The longest chain sets the end date. From 1.1 through 3.1, 3.3, 3.4 and 3.5 to 4.1 there are no gaps, so any delay there moves go-live. That chain is the critical path; the critical path method explains how to calculate it formally.
  • Some work has room to move. Page rewriting (3.2) ends on 26 February, but testing cannot start until the build finishes. The content work has about three weeks of slack to absorb late approvals. See float and slack.
  • Parallel tasks shorten the project. Design and content both start the day after the baseline.
  • Milestones are decisions, not work. Charter, baseline, go-live and handover are what the sponsor tracks.
  • Every row has one owner, including the sponsor, who owns signing the charter.

Calendar days or working days?

The Duration (days) column uses =End − Start + 1, which counts calendar days. "Design templates" runs from Thursday 28 January to Wednesday 17 February: 21 calendar days but only 15 working days.

If your team estimates in working days, replace the formula in the first task row with =NETWORKDAYS(E6,F6) (row 6 is the first task row; E and F hold Start and End) and copy it down. NETWORKDAYS works in Excel and Google Sheets, skips weekends and accepts a range of holiday dates as a third argument. Use one convention for every row and tell the team which.

Tip

A one-day milestone such as go-live shows a duration of 1. That is expected: the Milestone? flag, not the duration, marks it as a checkpoint.

How to keep the project plan up to date

  1. Ask each owner for status and update the Status column.
  2. Re-forecast work in progress. If a task will finish late, record the new date and use Depends on to see what it affects.
  3. Look two to four weeks ahead so upcoming owners know they are starting.
  4. Filter for problems: Blocked, On hold, and past end dates that are not Done. The expert version highlights overdue end dates automatically.
  5. Report it in your project status report. The expert Dashboard tab gives task counts by status and owner.
  6. Re-baseline only through change control. Use a change request when scope, dates or budget change, and log it in the Revision history tab if you use the expert version.

Using the template in Excel and Google Sheets

Excel: download the .xlsx file, overwrite the sample rows and use the formatted blank rows below them. If you add rows beyond those, copy the duration formula down. The header filters let you show one phase, owner or status at a time.

Google Sheets: the Google Sheets button asks you to make a copy in your own Drive. Rename it, replace the samples and share it, with edit access for owners who update their own status. You can also upload the .xlsx to Drive and open it in Sheets.

PDF: a print-ready version for planning workshops or a fixed snapshot. Use a spreadsheet for the live plan.

A spreadsheet suits one project with a small team. If you need dependencies that move dates automatically, interactive Gantt charts or workloads across several projects, software is a better home. Frequently asked questions

What is a project plan template?

A ready-made spreadsheet or document for recording a project's goal, scope, deliverables, tasks, owners, dates, dependencies and milestones. This one has a Project plan tab and an Overview tab.

Is this project plan template free?

Yes. It is free as an Excel file, Google Sheet or PDF, in beginner, advanced and expert versions, with no sign-up.

What should a project plan template include?

A goal, scope and exclusions, deliverables, tasks grouped into phases, an owner per task, start and end dates, dependencies, milestones, budget, key risks, success criteria and task status.

How do I create a project plan in Excel?

Download the .xlsx template, fill in the Overview tab, then list tasks on the Project plan tab with an owner, start and end date each. Duration calculates automatically, and Status and Milestone? have dropdowns.

Can I use the project plan template in Google Sheets?

Yes. Use the Google Sheets button to make a copy in your Drive, or upload the .xlsx file and open it with Google Sheets.

What are the steps to write a project plan?

Agree the goal, define scope and deliverables, break the work into tasks, assign owners, estimate dates, link dependencies, mark milestones, baseline the plan with the sponsor, then update it weekly.

What is the difference between a project plan and a project schedule?

A project plan also covers goal, scope, owners, budget and risks. A project schedule focuses on the timing and sequence of activities in more detail.

What is the difference between a project plan and a project management plan?

A project plan is usually the working plan of tasks, owners and dates. The PMBOK Guide's project management plan is a broader document covering how scope, schedule, cost, risk and communications will be managed.

How detailed should a project plan be?

Detailed enough to show slippage quickly but simple enough to keep current: for a few-month project, tasks of about one to two weeks, with more detail for the next phase.

Who is responsible for the project plan?

The project manager owns and maintains it. Task owners give estimates and status, and the sponsor approves the plan and changes to its baseline.

How often should a project plan be updated?

Update status at least weekly during delivery, and update dates or scope whenever an approved change affects them.

Can I turn the project plan template into a Gantt chart?

Yes. Copy the tasks and dates into our Gantt chart template, or import the task list into project management software such as Wrike.

Can I use this project plan template for Agile projects?

You can use the Overview tab and milestone rows for releases, but Agile teams usually plan in sprints from a backlog. See the role of the project plan in Agile.
