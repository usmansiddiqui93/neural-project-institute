Techniques Scrum : les pratiques qui complètent le cadre

Le Guide Scrum est volontairement minimal. Il laisse aux équipes la liberté de choisir les pratiques qui leur conviennent. Voici les techniques les plus couramment utilisées avec Scrum.

Rédigé parNeural Project InstituteL'équipe éditoriale gestion de projet
  • Publié le 18 septembre 2026
  • 3 min de lecture

À retenir

  • Scrum laisse de la place aux pratiques complémentaires.
  • Les user stories, le story mapping et le planning poker aident à gérer le backlog.
  • Choisissez des techniques qui résolvent de vrais problèmes pour votre équipe.

Techniques de backlog

  • User stories : « En tant que [utilisateur], je veux [objectif], afin de [bénéfice]. »
  • Critères d'acceptation : des conditions claires pour chaque élément, souvent au format Étant donné-Quand-Alors.
  • Story mapping : organiser les stories le long du parcours utilisateur pour planifier les releases.
  • INVEST : Indépendante, Négociable, Valorisable, Estimable, Petite (Small), Testable.
  • Modèles de découpage : découpez par étape du flux de travail, règle métier, type de données ou interface.

Techniques de planification et de suivi

  • Planning poker et autres méthodes d'estimation.
  • Burndown chart du Sprint et burnup chart de release.
  • Planification de capacité ; voir Planification de capacité agile.
  • Definition of Ready, une check-list facultative pour les éléments qui entrent dans un Sprint.

Techniques de livraison

  • Programmation en binôme ou mob programming.
  • Développement piloté par les tests et intégration continue.
  • Swarming sur les éléments hautement prioritaires.
  • Limites de WIP au sein du Sprint.

Techniques d'amélioration

  • Variées formats de rétrospective.
  • Les cinq pourquoi et l'analyse des causes racines.
  • Règles de fonctionnement de l'équipe.

Questions fréquentes

La Definition of Ready est-elle une technique Scrum officielle ?

Non. C'est une pratique facultative utilisée par certaines équipes ; elle ne doit pas devenir un filtre rigide.

Les user stories sont-elles une technique Scrum obligatoire ?

Non. Scrum exige seulement des éléments du Product Backlog ; les user stories sont un format répandu.

Comment fonctionnent les user stories en tant que technique Scrum ?

Une user story est une courte description d'un besoin du point de vue de l'utilisateur, souvent rédigée ainsi : En tant que utilisateur], je veux [objectif], afin de [bénéfice]. Voir [user stories.

Comment le modèle INVEST est-il utilisé en tant que technique Scrum ?

C'est une check-list pour de bons éléments du backlog : Indépendant, Négociable, Valorisable, Estimable, Petit (Small) et Testable. Elle a été proposée par Bill Wake.

Le story mapping est-il une technique Scrum utile ?

Oui. Le story mapping organise les user stories le long du parcours de l'utilisateur, avec une priorité décroissante de haut en bas, pour planifier les releases et trouver la plus petite tranche porteuse de valeur.

Comment fonctionne une Definition of Ready en tant que technique Scrum ?

C'est une check-list facultative qu'un élément du backlog doit satisfaire avant d'entrer dans un Sprint, comme des critères d'acceptation clairs. Elle ne fait pas partie du Guide Scrum.

Pourquoi les critères d'acceptation sont-ils une technique Scrum utile ?

Ils fixent les conditions qu'un élément du backlog doit remplir pour être accepté, souvent rédigées au format Étant donné-Quand-Alors. Ils diffèrent de la Definition of Done, qui s'applique à tous les éléments.

Qu'est-ce que le swarming en tant que technique Scrum ?

Plusieurs Developers travaillent ensemble sur un même élément pour le terminer rapidement, au lieu que chacun commence un élément différent. Voir Swarming agile.

Le mob programming est-il une technique Scrum ?

C'est une pratique complémentaire plutôt qu'une partie de Scrum : toute l'équipe travaille sur la même tâche au même moment sur un seul ordinateur, en se relayant au clavier. Elle diffuse les connaissances et réduit les transferts.

Pourquoi le développement piloté par les tests est-il une technique Scrum utile ?

Le développement piloté par les tests consiste à écrire un test automatisé avant d'écrire le code qui le fait passer, puis à refactorer. Il soutient une Definition of Done exigeante.

Quelles techniques Scrum aident à découper les grandes user stories ?

Découpez par étape du flux de travail, règle métier, type de données, interface ou cas simples versus complexes, en veillant à ce que chaque morceau ait de la valeur à lui seul. Voir epics, stories et tâches.
