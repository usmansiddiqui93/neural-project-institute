Comment utiliser le modèle de plan de projet agile

  1. Remplissez l'onglet Charte avec la vision, les objectifs, les rôles et les accords de fonctionnement.
  2. Décomposez le périmètre en epics et en fonctionnalités dans votre backlog produit.
  3. Planifiez les epics sur les Sprints à partir de votre vélocité attendue.
  4. Repérez les points de release et faites-les valider par les parties prenantes.
  5. Mettez à jour le plan après chaque Sprint Review et révisez les prévisions.

Conseils pour en tirer le meilleur parti

  • Ne planifiez en détail que le prochain Sprint ou les deux prochains.
  • Suivez les résultats, pas seulement la production.
  • Utilisez une approche hybride si la gouvernance exige des jalons.
  • Gardez le plan visible pour toute l'équipe.

Questions fréquentes

Qu'est-ce qu'un modèle de plan de projet agile ?

Un modèle de plan de projet agile est un plan allégé qui présente la vision, les objectifs, l'équipe, les Sprints, les epics et les releases d'un projet agile.

Ce modèle de plan de projet agile est-il gratuit ?

Oui. Le modèle de plan de projet agile est gratuit dans Google Sheets, Excel et PDF.

Les projets agiles ont-ils besoin d'un modèle de plan de projet agile ?

Oui. Les projets agiles sont eux aussi planifiés, mais de façon itérative : un plan de projet agile fixe le cap et est mis à jour à chaque Sprint.

Que doit contenir un modèle de plan de projet agile ?

Vision, objectifs, rôles, durée des Sprints, cérémonies, epics par Sprint, releases, Definition of Done et risques.

Le modèle de plan de projet agile comprend-il une charte de projet agile ?

Oui. L'onglet Charte est une charte de projet agile allégée.

En quoi un modèle de plan de projet agile diffère-t-il d'un modèle de plan de projet traditionnel ?

Un plan de projet traditionnel fige le périmètre dès le départ ; un plan de projet agile fige les délais et adapte le périmètre.

À quelle fréquence mettre à jour le modèle de plan de projet agile ?

Après chaque Sprint Review, en fonction de ce qui a été livré et appris.

Puis-je utiliser le modèle de plan de projet agile avec Kanban ?

Oui. Remplacez les Sprints par des périodes mensuelles ou trimestrielles et suivez le débit plutôt que les points.

Qui est responsable du modèle de plan de projet agile ?

Le Product Owner est responsable des priorités ; un chef de projet ou le Scrum Master peut tenir le plan à jour.

Puis-je partager le modèle de plan de projet agile avec les dirigeants ?

Oui. Les objectifs de Sprint et les releases offrent aux dirigeants une vue claire, centrée sur les résultats.

Quelle est la différence entre les versions débutant, avancé et expert du modèle de plan de projet agile ?

La version débutant du modèle de plan de projet agile ne conserve que les colonnes essentielles sur un seul onglet ; la version avancé est le modèle complet avec tous les onglets, listes déroulantes et formules ; la version expert ajoute des instructions, un tableau de bord qui synthétise automatiquement vos données, des couleurs de statut et un historique des révisions.
